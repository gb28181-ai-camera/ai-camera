# 首页与告警设置模块

> 版本: v0.1.0
> 最后更新: 2026-09-21
> 需求来源: AI摄像头操作手册 第 1 节（首页）、第 8.2 节（告警设置）、第 8.3 节（升级管理）、第 8.5 节（第三方平台管理）

## 1. 模块概述

本模块由四块相对独立、但共同支撑**「平台日常使用」**的能力组成：

| 子模块 | 手册章节 | 定位 |
|:---|:---|:---|
| 首页看板 | 1 | 登录后的**第一屏**：今日/本周/本月的预警与处理、设备统计与多维分析 |
| 告警设置 | 8.2 | **通知策略**：谁能收到、怎么收到、多久收一次 |
| 升级管理 | 8.3 | **版本运维**：固件与 AI 模型的版本库 + 设备远程升级 |
| 第三方平台管理 | 8.5 | **通道配置**：个推（App 推送）、腾讯云短信 |

四者的逻辑关系：

```
   ┌──────────────────────────────────────────────────────────────┐
   │  首页看板                                                     │
   │  今日预警 / 今日处理 / 本周预警 / 本周处理 / 本月预警 /        │
   │  本月处理 / 设备统计 / 风险类型分析 / 风险处理统计 /           │
   │  区域风险统计 / 风险分析 / 告警分析                            │
   └───────────────────────────┬──────────────────────────────────┘
                               │ 数据来自风险/告警/设备/区域聚合
                               │
   ┌───────────────────────────┴──────────────────────────────────┐
   │  告警设置（设备告警设置 / 风险通知设置）                       │
   │  决定「风险/告警产生后，推给谁、用什么通道、多久推一次」        │
   └───────────────────────────┬──────────────────────────────────┘
                               │ 通知通道由第三方平台提供
                               │
   ┌───────────────────────────┴──────────────────────────────────┐
   │  第三方平台管理（个推账号绑定 / 腾讯云短信配置）               │
   └──────────────────────────────────────────────────────────────┘

   ┌──────────────────────────────────────────────────────────────┐
   │  升级管理（独立业务域）                                        │
   │  固件类型管理 → 固件管理 → 模型管理（版本库）                  │
   │                     ↓ 升级下发                                │
   │  设备升级（现在升级 / 定时升级 / 批量升级）                    │
   │        ├── 现在升级 ──▶ 升级记录                              │
   │        └── 定时升级 ──▶ 升级计划 ──（到点执行）──▶ 升级记录    │
   └──────────────────────────────────────────────────────────────┘
```

> **注意**：升级管理在操作手册中位于 8.3 节（属于「系统设置」），但业务上与首页/告警设置
> 无耦合。本文档按任务划分将其归入本模块统一描述。

## 2. 角色与权限

| 角色 | 可执行操作 |
|:---|:---|
| 系统管理员 | 首页看板查看；告警设置配置；升级管理全部增删改查与升级下发；第三方平台配置 |
| 区域管理员 | 首页看板查看；告警设置配置（**仅本人数据**）；查看固件/模型；升级下发 |
| 安全员 | 首页看板查看；告警设置配置（**仅本人数据**） |
| 设备运维员 | 首页看板查看；固件/模型/固件类型维护；设备升级下发与取消 |
| 巡检员 | 移动端首页（`/app/home`）查看个人待办 |

权限码：

| 权限码 | 说明 |
|:---|:---|
| `stats:dashboard` | 首页看板 |
| `alarmSetting:list` / `alarmSetting:create` / `alarmSetting:update` / `alarmSetting:delete` | 设备告警设置 |

| `riskNotify:list` / `riskNotify:create` / `riskNotify:update` / `riskNotify:delete` | 风险通知设置 |
| `riskNotify:disableAll` | 关闭所有通知 |

| `aiModel:list` / `aiModel:create` / `aiModel:update` / `aiModel:delete` / `aiModel:download` | 模型管理 |
| `upgrade:device` / `upgrade:batch` | 设备升级 / 批量升级 |
| `upgrade:plan` / `upgrade:planCancel` | 升级计划 / 取消升级 |

### 3.2 ac_alarm_setting - 设备告警设置

```sql
CREATE TABLE ac_alarm_setting (
    id              BIGSERIAL PRIMARY KEY,
    deleted_at      TIMESTAMPTZ,
    created_by      VARCHAR(50),
    created_dt      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_by      VARCHAR(50),
    updated_dt      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,

    user_id         BIGINT NOT NULL,                       -- 配置所属用户
    alarm_type_id   BIGINT NOT NULL,                       -- 告警类型ID
    active          BOOLEAN DEFAULT TRUE,                  -- 是否启用(关闭所有告警通知)
    notify_type     VARCHAR(20) DEFAULT 'app',             -- 通知类型 app/sms/inner
    notify_freq     INTEGER DEFAULT 0,                     -- 报警频率(分钟)
    notify_user_ids TEXT,                                  -- 通知人员用户ID列表
    threshold       VARCHAR(50),                           -- 阈值
    remark          VARCHAR(500)                           -- 备注
);
CREATE UNIQUE INDEX idx_ac_alarm_setting_user_type
    ON ac_alarm_setting (user_id, alarm_type_id);
CREATE INDEX idx_ac_alarm_setting_deleted_at ON ac_alarm_setting (deleted_at);

COMMENT ON TABLE ac_alarm_setting IS '设备告警设置。约束：只能配置当前登录用户自己的数据（UserID = 当前用户）；一条记录对应「某用户 + 某告警类型」的通知策略；Active=false 即为「关闭该类型的所有告警通知」';
COMMENT ON COLUMN ac_alarm_setting.user_id IS '配置所属用户';
COMMENT ON COLUMN ac_alarm_setting.active IS '是否启用(关闭所有告警通知)';
COMMENT ON COLUMN ac_alarm_setting.notify_type IS '通知类型 app/sms/inner';
COMMENT ON COLUMN ac_alarm_setting.notify_freq IS '报警频率(分钟)';
COMMENT ON COLUMN ac_alarm_setting.notify_user_ids IS '通知人员用户ID列表';
COMMENT ON COLUMN ac_alarm_setting.threshold IS '阈值';
```

> **注意**：本表**无 `dept_id` 列**——它不参与部门级数据权限过滤，而是通过
> **`user_id = 当前登录用户`** 强制隔离。这是全平台唯一一张以用户为隔离维度的表。

## 4. 功能需求

### 4.1 首页看板

**操作说明**（手册第 1 节）：

- 可查看今日预警、今日处理、本周预警、本周处理、本月预警、本月处理、设备统计、风险类型分析、风险处理统计、区域风险统计、风险分析、告警分析等信息。

**业务规则**：

首页包含**全部十二项**内容，分为三类：

**（1）六个时间维度数值卡片**

| 卡片 | 口径 | 数据来源 |
|:---|:---|:---|
| 今日预警 | `COUNT(*) WHERE occurred_dt::date = CURRENT_DATE` | `ac_risk_record` |
| 今日处理 | `COUNT(*) WHERE handled_dt::date = CURRENT_DATE AND status='handled'` | `ac_risk_record` |
| 本周预警 | 本周一至今的 `occurred_dt` 计数 | `ac_risk_record` |
| 本周处理 | 本周一至今的 `handled_dt` 计数 | `ac_risk_record` |
| 本月预警 | 本月 1 日至今的 `occurred_dt` 计数 | `ac_risk_record` |
| 本月处理 | 本月 1 日至今的 `handled_dt` 计数 | `ac_risk_record` |

**（2）一个设备统计**

| 指标 | 说明 | 数据来源 |
|:---|:---|:---|
| 设备统计 | 设备总数、在线数量、离线数量、在线率 | `ac_device`（`status` 分组计数） |

**（3）五个分析图表**

| 图表 | 说明 | 维度 |
|:---|:---|:---|
| 风险类型分析 | 各风险类型的风险数量分布 | `ac_risk_type.name` |
| 风险处理统计 | 已处理 / 未处理 的数量与占比、处理率 | `ac_risk_record.status` |
| 区域风险统计 | 各区域的风险数量排行 | `ac_region.name` |
| 风险分析 | 风险的时间趋势（按日）+ 等级分布 + 检测准确性（误报率） | `occurred_dt` / `risk_level` / `detect_accurate` |
| 告警分析 | 设备告警的类型分布、时间趋势与处理情况 | `ac_alarm_type.name` / `occurred_dt` / `status` |

- 首页数据由单一聚合接口 `GET /web/stats/dashboard` 一次性返回，避免首屏多次请求。
- 所有卡片与图表受**数据权限约束**——不同角色的用户首页数值不同。
- 图表配色建议按风险等级：high=红、medium=橙、low=黄。

**搜索条件**：无（首页为固定时间切片：今日 / 本周 / 本月）。若需自定义区间，
跳转至「统计分析 → 风险统计分析」。

**排序**：排行榜类图表按数量倒序（TOP N）。

### 4.2 设备告警设置

**操作说明**（手册 8.2.1 节）：

- 可配置告警类型（离线告警、电量告警、流量告警）的通知人员、通知类型及报警频率等内容（用户可以自定义风险和告警通知的类型与时间，只能设置当前登录用户的数据）；
- 点击关闭所有告警，可关闭该类型的所有告警通知；
- 选择通知人员、告警类型进行搜索。

**业务规则**：

- **配置维度**：一行记录 = 「某用户 + 某告警类型」的通知策略，唯一索引
  `(user_id, alarm_type_id)` 保证不重复。
- **「只能设置当前登录用户的数据」** —— 这是本页最硬性的约束：
  - 列表查询强制 `WHERE user_id = 当前登录 user_id`；
  - 新增时 `user_id` 由服务端从登录上下文写入，**前端不可传**；
  - 修改 / 删除时服务端校验 `id` 对应的记录 `user_id` 是否为当前用户，**否则拒绝**（403）。
- **可配置项**：

| 配置项 | 字段 | 可选值 |
|:---|:---|:---|
| 通知人员 | `notify_user_ids` | 多选用户（存逗号分隔的用户ID列表） |
| 通知类型 | `notify_type` | `app`（APP推送/个推，默认）/ `sms`（短信/腾讯云）/ `inner`（站内通知） |
| 报警频率 | `notify_freq` | `0` 实时（默认）/ `60` 每小时 / `1440` 每天 |
| 阈值 | `threshold` | 按告警类型取用：电量告警为电量百分比阈值，流量告警为剩余流量 MB 阈值 |
| 备注 | `remark` | 自由文本 |

- **「关闭所有告警」**：点击后把该类型的所有告警通知关闭。
  实现方式为把该用户**全部** `ac_alarm_setting` 记录的 `active` 置为 `false`
  （`Active=false` 即为「关闭该类型的所有告警通知」）。
  接口：`PUT /web/settings/alarm-settings/disable-all`。
- **「用户可以自定义风险和告警通知的类型与时间」**：即通知类型（app/sms/inner）
  与报警频率（0/60/1440）均可由用户自选。

**列表字段**：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 告警类型 | 离线/电量/流量 | `ac_alarm_type.name`（经 `alarm_type_id`） |
| 通知人员 | 用户姓名列表 | `ac_user.name`（经 `notify_user_ids`） |
| 通知类型 | APP推送/短信/站内通知 | `ac_alarm_setting.notify_type` |
| 报警频率 | 实时/每小时/每天 | `ac_alarm_setting.notify_freq` |
| 阈值 | 电量百分比 / 剩余流量 MB | `ac_alarm_setting.threshold` |
| 状态 | 启用/已关闭 | `ac_alarm_setting.active` |
| 备注 | — | `ac_alarm_setting.remark` |
| 操作 | 编辑、删除 | — |

**搜索条件**（手册明确列举）：通知人员（`notify_user_ids` 包含）、告警类型
（`alarm_type_id`）。

**排序**：按告警类型的 `sequence` 升序。

### 4.4 第三方平台管理

#### 4.4.1 个推账号绑定

**操作说明**（手册 8.5.1 节）：

- 可配置个推账号。

**业务规则**：

- 个推（Getui）用于向移动端 App 推送风险与告警通知，对应通知类型 `notify_type=app`。
- 可配置四项：`getui_app_id`、`getui_app_key`、`getui_app_secret`、`getui_master_secret`。
- 以键值形式存入 `ac_thirdparty_config`，`category='getui'`。
- **敏感值脱敏**：`app_secret` 与 `master_secret` 的 `secret` 置为 `true`，
  **查询接口返回时脱敏**（如 `****` 或仅返回前后几位），修改时留空表示不修改。
- 接口：`GET /web/settings/getui`、`PUT /web/settings/getui`。
- 配置不完整时，选择 `app` 通知类型将推送失败，应在页面提示「请先完成个推账号绑定」。

#### 4.4.2 腾讯云短信配置

**操作说明**（手册 8.5.2 节）：

- 可配置腾讯云短信。

**业务规则**：

- 腾讯云短信用于 `notify_type=sms` 的通知通道。
- 可配置四项：`sms_secret_id`、`sms_secret_key`、`sms_sdk_app_id`、`sms_sign_name`。
- 以键值形式存入 `ac_thirdparty_config`，`category='sms'`。
- `sms_secret_key` 为敏感值（`secret=true`），查询时脱敏。
- 接口：`GET /web/settings/sms`、`PUT /web/settings/sms`。
- 配置不完整时，选择 `sms` 通知类型将下发失败，应在页面提示。

#### 4.4.3 消息推送配置

**操作说明**：

- 可维护若干条 WebHook 推送通道，把风险、告警、巡检与设备状态事件实时推送到
  飞书 / 钉钉 / 企业微信 的群机器人，或推送到自建系统。
- 支持新增、编辑、删除、启用/停用、测试推送；列表直接展示每条通道最近一次的发送结果。

**业务规则**：

- **平台差异**（四种平台共用一张表单，差异由后端 `pkg/webhook` 收敛）：

  | 平台 | 适用机器人 | 消息格式 | 加签 |
  |:-----|:-----------|:---------|:-----|
  | `feishu` | 飞书自定义机器人 | 固定 `text` | 不需要 |
  | `dingtalk` | 钉钉自定义机器人 | `text` / `markdown` | `secret` 非空时启用 HMAC-SHA256 加签 |
  | `wecom` | 企业微信群机器人 | `text` / `markdown` | 不需要 |
  | `custom` | 自建 WebHook 服务 | 通用 JSON | 可选（密钥由对接方自行校验） |

- **WebHook 地址**：必填，且必须以 `http://` 或 `https://` 开头。
  钉钉加签会使实际请求地址变长，因此该列长度放宽到 1000 字符。
- **签名密钥**：钉钉为加签密钥；飞书与企业微信留空即可。编辑时提交脱敏串（含 `****`）
  表示不修改原密钥，避免掩码值覆盖真实密钥。
- **事件订阅**：每条通道可订阅一个或多个事件 —— `risk`（AI 风险）、`alarm`（设备告警）、
  `inspect`（巡检通知）、`device`（设备上下线）。**不选任何事件即表示订阅全部事件**。
  事件在风险 / 告警上报落库后由后端分发，推送失败只记录通道状态，**不影响上报结果**。
- **测试推送**：
  - 已保存的通道：调用测试接口实时下发一条测试消息，失败原因直接回显
    （地址错误 / 加签失败 / 平台返回的业务错误码），便于快速定位。
  - 新增弹窗中可先对**未保存**的表单内容做即时连通性测试（不落库），验证通过后再保存。
- **失败状态可见性**：列表展示 `last_send_dt`（最近发送时间）、`last_status`（`success` / `failed`）
  与 `last_error`（失败原因）三个快照字段，无需进入详情即可发现通道异常；
  测试推送同样会刷新这三个字段。
- **平台级配置**：WebHook 通道由系统管理员统一维护，**不按部门 / 用户隔离**，
  因此不做数据权限过滤。
- **权限码**：`webhook:view` / `webhook:create` / `webhook:update` / `webhook:delete` / `webhook:test`。
- 接口：`GET|POST /web/settings/webhooks`、`GET|PUT|DELETE /web/settings/webhooks/:id`、
  `GET /web/settings/webhooks/platforms`、`PUT /web/settings/webhooks/:id/enable|disable`、
  `POST /web/settings/webhooks/:id/test`、`POST /web/settings/webhooks/test`。

### 4.5 升级管理

#### 4.5.1 设备升级管理 —— 设备升级

**操作说明**（手册 8.3.1 节·设备升级）：

- 远程升级可对设备（固件和模型）进行现在升级或定时升级，也可进行批量升级。
- 操作说明：
  - 若选择现在升级，升级成功后，在升级记录中会增加一条升级记录；
  - 若选择定时升级后，在升级计划中会有一条定时升级任务，可点击取消升级取消该任务；
  - 选择所属区域、设备名称、设备编号、固件、模式等条件进行搜索；
  - 勾选一条或多条数据，可进行批量升级操作。

**业务规则**：

- **升级对象**：设备的两类资产 —— **固件（firmware）** 与 **AI 模型（model）**，
  可只升其一，也可同时升级。
- **三条升级路径（必须全部实现）**：

| 路径 | 行为 | 结果落点 |
|:---|:---|:---|
| **现在升级** | 立即向设备下发升级指令 | **升级成功后**，在「**升级记录**」中增加一条记录（`upgrade_type=now`） |
| **定时升级** | 不立即下发，创建一条排期任务 | 在「**升级计划**」中产生一条定时升级任务（`status=pending`）；可点击「取消升级」取消 |
| **批量升级** | **勾选一条或多条数据**后统一升级 | 按所选设备逐台生成升级记录或升级计划（取决于选的是现在还是定时） |

- **搜索条件**（手册明确列举）：所属区域、设备名称、设备编号、固件、模式。
  其中「模式」指**设备工作模式**（`ac_device.device_mode` / `work_mode`），
  用于按模式批量筛选设备（如只对「全开模式」的设备升级）。
- **升级前必须已存在固件与模型版本**（见 4.5.2 / 4.5.3），否则下拉为空。
- 模型必须**与所选固件匹配**（`ac_ai_model.firmware_id`），不匹配时拒绝下发。

#### 4.5.2 设备升级管理 —— 升级计划

**操作说明**（手册 8.3.1 节·升级计划）：

- 对设备进行定时升级时，升级计划中才会产生相应设备的升级任务。列表中包括设备名称、设备编号、所属区域、设备位置、升级固件、升级模型、升级时间等相关内容。
- 操作说明：
  - 点击取消升级，可取消该定时升级任务；
  - 选择一条或多条数据可进行批量取消升级操作；
  - 输入固件名称进行搜索。

**业务规则**：

- **只有定时升级才会产生升级计划记录**。现在升级不会出现在此列表。
- **「取消升级」**：单条取消，`status` 置为 `canceled`
  （`PUT /web/upgrades/plans/:id/cancel`）。
- **批量取消升级**：选择一条或多条数据后统一取消
  （`PUT /web/upgrades/plans/cancel`）。
- **搜索：输入固件名称**（模糊匹配 `firmware_name`）。
- 计划到点后由调度器执行：`status` 流转为 `running → done`（成功）或 `failed`，
  并写回一条升级记录。

**列表字段**：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 设备名称 | 冗余 | `ac_device_upgrade_plan.device_name` |
| 设备编号 | 冗余 | `ac_device_upgrade_plan.device_code` |
| 所属区域 | — | `ac_region.name`（经 `region_id`） |
| 设备位置 | 冗余 | `ac_device_upgrade_plan.location` |
| 升级固件 | 固件名称 | `ac_device_upgrade_plan.firmware_name` |
| 升级模型 | 模型名称 | `ac_device_upgrade_plan.ai_model_name` |
| 升级时间 | 计划执行时间 | `ac_device_upgrade_plan.plan_dt` |
| 状态 | 待升级/升级中/已升级/失败/已取消 | `ac_device_upgrade_plan.status` |
| 备注 | — | `ac_device_upgrade_plan.remark` |
| 操作 | 取消升级 | — |

**搜索条件**（手册明确列举）：固件名称（`firmware_name` 模糊）；
扩展支持设备名称、设备编号、所属区域、升级时间区间、状态。

**排序**：按升级时间（`plan_dt`）升序（最近的排前面）。

#### 4.5.3 设备升级管理 —— 升级记录

**操作说明**（手册 8.3.1 节·升级记录）：

- 对设备进行升级后，升级记录中就会产生相应的设备升级记录。列表中包括设备名称、设备编号、所属区域、设备位置、流量卡、上一固件、上一模型、升级固件、升级模型、升级时间等相关内容。
- 对同一设备升级两次后，在上一固件和上一模型中才会显示上一次升级的固件/模型。
- 选择设备名称、设备编号、操作时间等条件进行搜索。

**业务规则**：

- **产生时机**：只要对设备执行过升级（现在升级成功，或定时升级执行完成），
  就会产生一条升级记录。
- **「上一固件 / 上一模型」的关键语义**：
  - **首次升级**：设备此前无升级历史，`prev_firmware_id/_ver` 与 `prev_ai_model_id/_ver`
    **为空**，列表中不显示上一固件/上一模型。
  - **第二次及以后升级**：`prev_*` 显示**上一次升级后的固件/模型版本**
    （即设备升级前所处的版本），从而形成版本对照。
  - 一句话概括手册原文：**对同一设备升级两次后，在上一固件和上一模型中才会显示
    上一次升级的固件/模型**。
- **「流量卡」列**：取该设备当前绑定的物联网卡号（`iot_card_no` 冗余）。
- 升级失败时记录 `error_msg`（失败原因），供排查。
- 升级方式 `upgrade_type`：`now`（现在升级）/ `plan`（定时升级）。

**列表字段**：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 设备名称 | 冗余 | `ac_device_upgrade_record.device_name` |
| 设备编号 | 冗余 | `ac_device_upgrade_record.device_code` |
| 所属区域 | — | `ac_region.name`（经 `region_id`） |
| 设备位置 | 冗余 | `ac_device_upgrade_record.location` |
| 流量卡 | 流量卡号 | `ac_device_upgrade_record.iot_card_no` |
| 上一固件 | 升级前固件版本（首次为空） | `prev_firmware_ver` |
| 上一模型 | 升级前模型版本（首次为空） | `prev_ai_model_ver` |
| 升级固件 | 升级后固件版本 | `firmware_ver` |
| 升级模型 | 升级后模型版本 | `ai_model_ver` |
| 升级时间 | — | `ac_device_upgrade_record.upgrade_dt` |
| 升级方式 | 现在升级/定时升级 | `ac_device_upgrade_record.upgrade_type` |
| 升级结果 | 成功/失败 | `ac_device_upgrade_record.status` |
| 失败原因 | 失败时展示 | `ac_device_upgrade_record.error_msg` |
| 操作人 | — | `ac_device_upgrade_record.operator` |

**搜索条件**（手册明确列举）：设备名称（模糊）、设备编号（模糊）、操作时间
（`upgrade_dt` 区间）；扩展支持所属区域、升级方式、升级结果。

**排序**：按升级时间（`upgrade_dt`）倒序。

```
   用户选择「定时升级」
          │
          ▼

              ┌───────────────────────────────────┐

                              │ 同时更新设备台账
                              ▼
              ac_device.firmware_id / firmware_ver
              ac_device.model_id    / model_ver
              ac_device.system_ver（若升级系统固件）
```

### 5.4 「上一固件 / 上一模型」的填充语义

```
   设备首次升级
        │
        ├─ prev_firmware_id  = NULL   → 列表「上一固件」为空
        ├─ prev_firmware_ver = ''
        ├─ prev_ai_model_id  = NULL   → 列表「上一模型」为空
        └─ prev_ai_model_ver = ''
        │
        ▼
   设备第二次升级
        │
        ├─ prev_firmware_id  = 第一次升级后的固件ID
        ├─ prev_firmware_ver = 第一次升级后的固件版本
        ├─ prev_ai_model_id  = 第一次升级后的模型ID
        └─ prev_ai_model_ver = 第一次升级后的模型版本
        │
        ▼
   → 手册原文：「对同一设备升级两次后，在上一固件和上一模型中
              才会显示上一次升级的固件/模型」
```
