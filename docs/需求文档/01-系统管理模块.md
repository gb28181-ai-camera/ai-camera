# 系统管理模块

> 版本: v0.1.0
> 最后更新: 2026-09-21
> 需求来源: AI摄像头操作手册 第 8.6 节

## 1. 模块概述

系统管理模块是 AI 摄像头管理平台的**权限与账号底座**。平台的全部业务数据（风险、告警、
设备、巡检、区域）都挂在「用户」与「部门」两个主体上：风险有处理人，告警有处理人，巡检
任务有巡检人，告警设置只能配置当前登录用户自己的数据，数据权限按部门行级过滤。因此本模块
是其它所有模块的前置依赖。

本模块覆盖操作手册 8.6 节的八个页面：个人中心、用户管理、菜单管理、角色管理、部门管理、
岗位管理、操作日志、系统通知，另含系统参数、开放接口密钥、序列号生成器三项支撑能力。

> **注意**：平台采用 **Casbin RBAC** 模型。菜单（含按钮）是权限的最小载体，菜单上绑定的
> API 是 Casbin `p` 策略的唯一来源；角色是 `sub`，部门是 `g2`，岗位是 `g3`。角色授权变更后
> 后端必须重建策略并 `ReloadPolicy()`。

## 2. 角色与权限

| 角色 | 可执行操作 |
|:---|:---|
| 系统管理员 | 用户/角色/菜单/部门/岗位的增删改查、重置密码、启用禁用、角色授权、数据权限设置、菜单 API 绑定；操作日志查看/删除/清空/导出；系统通知查看 |
| 区域管理员 | 只读查看用户/角色/部门/岗位；可查看操作日志；可查看系统通知 |
| 安全员 | 仅个人中心（改本人资料与密码）、系统通知查看 |
| 设备运维员 | 仅个人中心、系统通知查看 |
| 巡检员 | 仅移动端：个人中心、系统通知查看 |

权限码（按钮级）：

| 权限码 | 说明 |
|:---|:---|
| `user:list` / `user:create` / `user:update` / `user:delete` | 用户管理 |
| `user:enable` / `user:disable` / `user:resetPwd` | 用户启用/禁用/重置密码 |
| `role:list` / `role:create` / `role:update` / `role:delete` | 角色管理 |
| `role:assign` / `role:dataScope` | 角色分配权限 / 数据权限 |
| `menu:list` / `menu:create` / `menu:update` / `menu:delete` | 菜单管理 |
| `menu:api` | 菜单 API 绑定 |
| `dept:list` / `dept:create` / `dept:update` / `dept:delete` | 部门管理 |
| `post:list` / `post:create` / `post:update` / `post:delete` | 岗位管理 |
| `log:list` / `log:delete` / `log:clear` / `log:export` | 操作日志 |
| `notice:list` / `notice:read` / `notice:delete` | 系统通知 |
| `config:list` / `config:update` | 系统参数 |
| `apikey:list` / `apikey:create` / `apikey:delete` | 接口密钥 |

### 3.2 ac_user - 用户

```sql
CREATE TABLE ac_user (
    id              BIGSERIAL PRIMARY KEY,
    deleted_at      TIMESTAMPTZ,
    created_by      VARCHAR(50),
    created_dt      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_by      VARCHAR(50),
    updated_dt      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,

    active          BOOLEAN DEFAULT TRUE,                  -- 是否启用
    name            VARCHAR(255) NOT NULL,                 -- 姓名/显示名
    user_name       VARCHAR(100) NOT NULL,                 -- 登录名
    password_hash   VARCHAR(255) NOT NULL,                 -- 密码哈希(bcrypt)
    email           VARCHAR(255),                          -- 邮箱
    phone           VARCHAR(50),                           -- 手机号
    avatar          TEXT,                                  -- 头像
    dept_id         BIGINT,                                -- 部门ID
    post_id         BIGINT,                                -- 岗位ID
    is_admin        BOOLEAN DEFAULT FALSE,                 -- 是否超级管理员
    last_login      TIMESTAMPTZ,                           -- 最后登录时间
    remark          VARCHAR(500)                           -- 备注
);
CREATE UNIQUE INDEX idx_ac_user_username ON ac_user (user_name);
CREATE INDEX idx_ac_user_dept_id ON ac_user (dept_id);
CREATE INDEX idx_ac_user_post_id ON ac_user (post_id);
CREATE INDEX idx_ac_user_deleted_at ON ac_user (deleted_at);

COMMENT ON TABLE ac_user IS '平台登录账号';
COMMENT ON COLUMN ac_user.user_name IS '登录名';
COMMENT ON COLUMN ac_user.password_hash IS '密码哈希(bcrypt)';
COMMENT ON COLUMN ac_user.is_admin IS '是否超级管理员';
```

> **注意**：`password_hash` 在 JSON 序列化时使用 `json:"-"`，任何接口都不得返回该字段。

## 4. 功能需求

### 4.1 个人中心

**操作说明**（手册 8.6.1）：

- 个人中心可修改个人相关信息。

**业务规则**：

- 可修改字段：姓名、邮箱、手机号、头像、备注；登录名（`user_name`）不可自行修改。
- 修改密码需提供原密码 + 新密码，服务端以 bcrypt 重新生成 `password_hash`。
- 个人中心提供「接口密钥」子页：可生成、查看（仅展示前缀）、删除 `ac_api_key`，用于设备上报。
- 登录成功后服务端写入 `last_login`。

**列表字段**（接口密钥）：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 名称 | 密钥用途标注 | `ac_api_key.name` |
| 密钥前缀 | 用于识别密钥 | `ac_api_key.key_prefix` |
| 最后使用时间 | 最近一次调用时间 | `ac_api_key.last_used_dt` |
| 状态 | 是否启用 | `ac_api_key.active` |
| 创建时间 | — | `ac_api_key.created_dt` |

**搜索条件**：无。

### 4.2 用户管理

**操作说明**（手册 8.6.2）：

- 通过输入部门、用户名、状态进行查询操作；
- 点击新增来添加用户账号，其中带红色*均为必填项，部门中数据与部门管理中数据相关联、岗位数据与岗位管理中数据相关联、拥有角色中数据与角色管理中数据相关联；

- 禁用/启用账号：账号默认都为启用状态，若禁用该账号，点击按钮进行禁用后，该账号将无法登录到管理平台中；
- 删除：对列表数据可进行删除操作，选择一条或多条数据进行批量删除操作，点击删除并点击确定即可删除该条数据，若点击取消，则取消删除；
- 重置密码：若用户遗忘密码或其他因素，可对密码进行重置密码操作。点击重置密码，输入新密码后即可完成密码重置，再次使用管理平台时需使用新密码进行登录。

**业务规则**：

- **新增/编辑弹窗**：点击「确定」保存成功并提示；点击「取消」内容不落库。
- **启用/禁用**：账号默认启用（`active=true`）。禁用（`active=false`）后该账号**无法登录**管理平台；已登录会话在下一次鉴权时失效。
- **删除支持批量**：选择一条或多条数据，点击删除并「确定」执行软删除；点「取消」不删除。
- **重置密码**：输入新密码后立即生效，用户再次登录必须使用新密码。
- 必填项校验：姓名、登录名、密码（新增时）、部门。登录名在全局唯一。
- 编辑不修改密码；密码只能通过「重置密码」或用户在个人中心自行修改。
- 用户通过三种来源获得角色：直接分配（`ac_user_role_rel`）、岗位（`ac_post_role_rel`）、部门（`ac_dept_role_rel`）；取所有角色中的**最高数据权限**。

| 部门 | 关联部门名称 | `ac_dept.name` |

### 4.3 菜单管理

**操作说明**（手册 8.6.3）：

### 4.4 角色管理

**操作说明**（手册 8.6.4）：

- 角色管理是管理平台账号中的角色权限，其中数据与用户管理相关联，列表中包括角色编号、角色名称、权限字符、显示顺序、状态、创建时间等相关内容。
- 通过输入角色名称、状态进行查询操作；
- 可添加角色，其中带红色*均为必填项，拥有权限为该角色用户登录平台只能查看已勾选的权限内容；
- 可对角色信息进行修改，点击编辑可修改角色信息，修改后点击确定并提示保存成功即内容已被修改；若在编辑中点击取消，则内容不会被修改；
- 点击数据权限，可设置该角色所能获取的数据权限；
- 对列表数据可进行删除操作，点击删除并点击确定即可删除该条数据，若点击取消，则取消删除。

**业务规则**：

- **拥有权限 = 菜单树勾选集合**。该角色下的用户登录后**只能查看已勾选的权限内容**，未勾选的菜单不返回、未勾选的按钮不显示、未绑定的接口调用返回 403。
- **数据权限**（`data_permission`）四种取值：

| 取值 | 含义 | 行级过滤 |
|:---|:---|:---|
| `all` | 全部数据 | 无过滤 |
| `cross_dept` | 跨部门 | `dept_id IN (本部门 + cross_dept_ids 列表)` |
| `dept` | 仅本部门 | `dept_id = 当前用户部门` |
| `personal` | 仅本人 | `created_by = 当前用户` |

- 角色编号可按住 Ctrl 多选（批量删除）。
- 删除角色时同步删除 `ac_role_menu_rel`、`ac_user_role_rel`、`ac_post_role_rel`、`ac_dept_role_rel` 中的关联，并重建 Casbin 策略。
- 角色授权变更后服务端**必须**调用 `syncCasbinForRole` 重建 `p` / `g` / `g2` / `g3` 策略并 `ReloadPolicy()`。

**列表字段**：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 角色编号 | 主键 | `ac_role.id` |
| 角色名称 | — | `ac_role.name` |
| 权限字符 | Casbin sub | `ac_role.code` |
| 显示顺序 | — | `ac_role.sequence` |
| 数据权限 | all/cross_dept/dept/personal | `ac_role.data_permission` |
| 状态 | 启用/禁用 | `ac_role.active` |
| 创建时间 | — | `ac_role.created_dt` |

**搜索条件**：角色名称（模糊）、状态（`active`）。

**排序**：按 `sequence` 升序，其次创建时间倒序。

### 4.8 系统通知

**操作说明**（手册 8.6.8）：

- 在系统通知中可查看设备告警信息、风险通知信息和巡检通知信息。设备告警、风险通知的通知频率可在设备告警设置、风险通知设置中配置，巡检消息通知会在指派的巡检人员账号中显示。当有未读消息时，图标上会有红点显示，已读后就会隐藏。

**业务规则**：

- 通知分三类（`category`）：`alarm`（设备告警）、`risk`（风险通知）、`inspect`（巡检通知）。
- **未读红点**：存在未读通知时，顶部铃铛图标显示红点；点开查看后红点隐藏。
  红点数量由 `GET /web/system/notifications/unread-count` 提供。
- 设备告警与风险通知的**通知频率**由「设备告警设置」「风险通知设置」决定（实时 / 每小时 / 每天）。
- **巡检消息通知只出现在被指派的巡检人员账号中**。
- 通知通过 `ref_type` + `ref_id` 关联业务对象，点击可跳转至对应的风险/告警/巡检详情。
- 支持单条标记已读、全部标记已读、单条删除。

**列表字段**：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 通知编号 | 主键 | `ac_notification.id` |
| 接收人 | 用户姓名 | `ac_user.name`（经 `user_id`） |
| 通知类型 | 告警/风险/巡检 | `ac_notification.category` |
| 标题 | — | `ac_notification.title` |
| 内容 | — | `ac_notification.content` |
| 关联业务 | 关联对象类型 | `ac_notification.ref_type` |
| 是否已读 | 已读/未读 | `ac_notification.read` |
| 已读时间 | — | `ac_notification.read_dt` |
| 创建时间 | 通知时间 | `ac_notification.created_dt` |

**搜索条件**：通知类型（`category`）、是否已读（`read`）、时间区间（`created_dt`）。

**排序**：按创建时间倒序。

### 4.9 系统参数与接口密钥

**操作说明**：

- 系统参数：维护平台运行参数（键、值、分组、数据类型、说明），支持启用/禁用。
- 接口密钥：为无用户上下文的场景（设备上报风险/告警/心跳）生成密钥。

**业务规则**：

- 接口密钥仅在**生成时**返回一次明文，服务端只保存 SHA256（`key_hash`），列表只展示
  `key_prefix`。生成后写入 `last_used_dt` 记录最后调用时间。
- 密钥用于 `POST /web/risks/report`、`POST /web/alarms/report`、`POST /web/devices/:id/heartbeat`。
- 删除密钥后，使用该密钥的设备上报立即被拒绝。
