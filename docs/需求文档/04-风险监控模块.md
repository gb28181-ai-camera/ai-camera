# 风险监控模块

> 版本: v0.1.0
> 最后更新: 2026-09-21
> 需求来源: AI摄像头操作手册 第 3 节（AI风险）、第 4 节（AI监控）、第 5.1 节（风险监控）

## 1. 模块概述

风险监控模块是平台的**业务核心与闭环终点**。设备端的 AI 模型识别到风险（未戴安全帽、
明火、人员闯入等）后，将风险图片、录像、置信度、发生时间上报至平台，平台落库为一条
风险记录（`ac_risk_record`）。安全员在「风险监控」列表中逐条复核：

1. **复核检测准确性** —— AI 识别得对不对？
   - 点「否」（误报）→ 该条数据**直接转为已处理**，消息通知同时转已读，流程结束；
   - 点「是」（真实风险）→ 消息通知**转为已读**，仍需人工处理。
2. **处理真实风险** —— 点击「处理」按钮，填写**处理结果**与**处理图片**，
   状态由**未处理 → 已处理**。

本模块包含三个页面：

| 页面 | 定位 | 手册章节 |
|:---|:---|:---|
| AI风险 | 全量风险信息的查看与处理入口（无区域/摄像头选择，直接列出全部风险） | 3 |
| AI监控 | 「视频监控 + 该摄像头的风险信息」并列呈现，点击风险可查看详情并**去处理** | 4 |
| 风险监控 | 平台主列表，功能最完整：多维搜索、列内快捷筛选、录像/实时视频/设备监控跳转、刷新频率设置 | 5.1 |

> **注意**：三个页面共用同一张 `ac_risk_record` 表与同一套处理逻辑，区别只在**入口与
> 筛选范围**：AI监控以「区域 + 摄像头」为上下文，风险监控以「列表 + 筛选条件」为上下文，
> AI风险则是无上下文的全局视图（等价于风险监控去掉默认筛选）。

## 2. 角色与权限

| 角色 | 可执行操作 |
|:---|:---|
| 系统管理员 | 查看、复核检测准确性、处理、删除风险；设置刷新频率 |
| 区域管理员 | 同上（受数据权限约束，仅可见授权区域的风险） |
| 安全员 | 查看、复核检测准确性、处理风险（不可删除）；查看录像与实时视频 |
| 设备运维员 | 只读查看风险 |
| 巡检员 | 移动端：查看待处理风险、复核准确性、提交处理结果与处理图片 |

权限码：

| 权限码 | 说明 |
|:---|:---|
| `risk:list` | 查看风险列表与详情 |
| `risk:read` | 标记消息已读 |
| `risk:accurate` | 修改「检测准确」 |
| `risk:handle` | 处理风险（填写处理结果与处理图片） |
| `risk:delete` | 删除风险记录 |
| `risk:video` | 查看视频录像 |
| `risk:live` | 查看实时视频 |
| `risk:refresh` | 设置页面刷新频率 |

### 3.2 ac_risk_record - AI 风险记录

```sql
CREATE TABLE ac_risk_record (
    id              BIGSERIAL PRIMARY KEY,
    deleted_at      TIMESTAMPTZ,
    created_by      VARCHAR(50),
    created_dt      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_by      VARCHAR(50),
    updated_dt      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,

    risk_type_id    BIGINT NOT NULL,                       -- 风险类型ID
    device_id       BIGINT NOT NULL,                       -- 设备ID
    device_code     VARCHAR(100),                          -- 设备编号(冗余)
    region_id       BIGINT,                                -- 所属区域
    location        VARCHAR(255),                          -- 设备位置(冗余)
    image_url       VARCHAR(500),                          -- 风险图片
    video_url       VARCHAR(500),                          -- 风险录像
    risk_level      VARCHAR(20),                           -- 风险等级(冗余)
    detect_score    DOUBLE PRECISION,                      -- AI 置信度
    occurred_dt     TIMESTAMPTZ,                           -- 发生时间

    -- 检测准确（人工确认）
    detect_accurate VARCHAR(10),                           -- 检测准确 yes/no
    accurate_by     VARCHAR(50),                           -- 确认人
    accurate_dt     TIMESTAMPTZ,                           -- 确认时间

    -- 消息通知
    read            BOOLEAN DEFAULT FALSE,                 -- 消息通知是否已读
    read_dt         TIMESTAMPTZ,                           -- 已读时间

    -- 处理
    status          VARCHAR(20) DEFAULT 'pending',         -- 处理状态 pending/handled
    handle_result   TEXT,                                  -- 处理结果
    handle_image    VARCHAR(500),                          -- 处理图片
    handler         VARCHAR(50),                           -- 处理人
    handled_dt      TIMESTAMPTZ,                           -- 处理时间

    -- 语音播报（若该风险类型配置了语音）
    voice_played    BOOLEAN DEFAULT FALSE,                 -- 是否已语音播报

    dept_id         BIGINT                                 -- 所属部门(数据权限)
);
CREATE INDEX idx_ac_risk_record_risk_type_id ON ac_risk_record (risk_type_id);
CREATE INDEX idx_ac_risk_record_device_id ON ac_risk_record (device_id);
CREATE INDEX idx_ac_risk_record_region_id ON ac_risk_record (region_id);
CREATE INDEX idx_ac_risk_record_occurred_dt ON ac_risk_record (occurred_dt);
CREATE INDEX idx_ac_risk_record_status ON ac_risk_record (status);
CREATE INDEX idx_ac_risk_record_dept_id ON ac_risk_record (dept_id);
CREATE INDEX idx_ac_risk_record_deleted_at ON ac_risk_record (deleted_at);

COMMENT ON TABLE ac_risk_record IS 'AI 风险记录';
COMMENT ON COLUMN ac_risk_record.device_code IS '设备编号(冗余)';
COMMENT ON COLUMN ac_risk_record.location IS '设备位置(冗余)';
COMMENT ON COLUMN ac_risk_record.risk_level IS '风险等级(冗余)';
COMMENT ON COLUMN ac_risk_record.detect_score IS 'AI 置信度';
COMMENT ON COLUMN ac_risk_record.detect_accurate IS '检测准确 yes/no';
COMMENT ON COLUMN ac_risk_record.read IS '消息通知是否已读';
COMMENT ON COLUMN ac_risk_record.status IS '处理状态 pending/handled';
COMMENT ON COLUMN ac_risk_record.handler IS '处理人';
COMMENT ON COLUMN ac_risk_record.voice_played IS '是否已语音播报';
```

相关常量：

| 常量 | 值 | 含义 |
|:---|:---|:---|
| `HandleStatusPending` | `pending` | 未处理 |
| `HandleStatusHandled` | `handled` | 已处理 |
| `DetectAccurateYes` | `yes` | 检测准确 |
| `DetectAccurateNo` | `no` | 检测不准确（误报） |

> **注意**：`device_code`、`location`、`risk_level` 是**冗余快照**列。风险发生时刻的设备编号、
> 位置与风险等级写入本表后不再随设备/风险类型的后续修改而变化，保证历史可追溯。

## 4. 功能需求

### 4.1 AI 风险

**操作说明**（手册第 3 节）：

- 可查看AI风险的全部风险信息并进行处理操作。
- 操作说明：
  - 处理风险：对检测准确结果点"是"时，消息通知会转为已读状态，可对该数据进行处理。点击处理按钮，填写处理结果及处理图片，处理后状态由未处理转为已处理。
  - 对检测准确结果点"否"时，该条数据直接转为已处理状态，且消息通知会转为已读状态；
  - 查看录像：点击此按钮，可查看视频录像。
  - 查看实时视频：点击此按钮，可查看实时视频。

**业务规则**：

- 本页展示**全部风险信息**（不预设区域/设备筛选），是风险处理的全局入口。
- 两条处理分支（与风险监控一致，见 4.3），核心是**检测准确 = 是 / 否**决定走向。
- **「查看录像」**：播放 `video_url` 指向的风险发生时段录像。
- **「查看实时视频」**：播放 `ac_device.stream_url` 的实时流；设备离线时按钮不可用并提示。
- 状态机见第 5 节。

**列表字段**：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 风险类型 | 可点击筛选同类数据 | `ac_risk_type.name` |
| 风险图片 | 缩略图，点击放大 | `ac_risk_record.image_url` |
| 设备名称 | 可点击筛选同设备数据 | `ac_device.name` |
| 设备编号 | 可点击筛选同设备数据 | `ac_risk_record.device_code` |
| 所属区域 | — | `ac_region.name` |
| 发生时间 | — | `ac_risk_record.occurred_dt` |
| 检测准确 | 是/否，可修改 | `ac_risk_record.detect_accurate` |
| 消息通知 | 未读/已读 | `ac_risk_record.read` |
| 状态 | 未处理/已处理 | `ac_risk_record.status` |
| 操作 | 查看、处理、查看录像、查看实时视频 | — |

**搜索条件**：风险类型、所属区域、发生时间（区间）、状态、设备名称、设备编号。

**排序**：按发生时间倒序。

### 4.2 AI 监控

**操作说明**（手册第 4 节）：

- 选择区域和摄像头可显示视频监控和风险信息。
- 点击风险信息，可查看该风险的详细信息，点击去处理，可跳转至风险监控界面中并可进行处理。

**业务规则**：

- **必须先选择区域和摄像头**，才会显示该设备的视频监控画面与风险信息列表。
- 页面为左右（或上下）分栏：一侧是**实时视频画面**，一侧是**该摄像头的风险信息流**。
- **点击风险信息** → 弹出该风险的详细信息（图片、类型、置信度、发生时间、设备、区域等）。
- 详情弹窗中的「**去处理**」按钮 → **跳转至风险监控界面**并定位该条风险，可直接处理。
- 该页面只展示**当前选中设备**的风险，不做跨设备聚合。

**列表字段**（风险信息流）：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 风险图片 | 缩略图 | `ac_risk_record.image_url` |
| 风险类型 | — | `ac_risk_type.name` |
| 发生时间 | — | `ac_risk_record.occurred_dt` |
| 状态 | 未处理/已处理 | `ac_risk_record.status` |
| 操作 | 点击查看详情、去处理 | — |

**搜索条件**：所属区域（选择器）、摄像头（设备选择器）。二者为**必选**。

**排序**：按发生时间倒序。

### 4.3 风险监控

**操作说明**（手册 5.1 节）：

- 风险监控数据来源于设备拍摄的风险数据信息，包括风险类型、风险图片、设备名称、设备编号、所属区域、发生时间、检测准确、消息通知、状态等相关内容。
- 操作说明：
  - 点击查看，可查看风险监控的详细信息，且该消息通知由未读转为已读状态，也可修改检测是否准确；
  - 处理风险：对检测准确结果点"否"时，该条数据直接转为已处理状态，且消息通知会转为已读状态；
  - 对检测准确结果点"是"时，消息通知会转为已读状态，可对该数据进行处理。点击处理按钮，填写处理结果及处理图片，处理后状态由未处理转为已处理。
  - 点击删除，并确认删除后，可对该条数据进行删除；
  - 选择风险类型、所属区域、发生时间、状态、设备名称、设备编号等条件进行搜索；
  - 点击列表中风险类型，可直接筛选出该类型的所有数据；设备名称和设备编号筛选方法与前者相同。
  - 点击此按钮，可查看视频录像。
  - 点击此按钮，可跳转至设备监控模块的设备详情中，方便快速查询该设备名称的设备监控数据。
  - 点击此按钮，可查看实时监控画面。
  - 检测准确：对风险图片进行查看，确认检测物体是否准确，可对监控检测准确性进行修改。点击"无"，可修改检测是否准确。
  - 刷新频率：可设置风险监控页面刷新频率，分别可设置为10秒、30秒、60秒。

**业务规则**：

**（1）点击「查看」**

- 打开风险详情，展示风险图片、录像、类型、等级、置信度、设备信息、发生时间等。
- **同时把该条的消息通知由未读转为已读**（`read=true`，写 `read_dt`）。
  接口：`PUT /web/risks/:id/read`。
- 详情中**也可修改检测是否准确**。

**（2）处理风险 —— 两条分支（本模块最关键的业务规则）**

| | 检测准确点「**否**」 | 检测准确点「**是**」 |
|:---|:---|:---|
| 判定 | AI 误报，不存在真实风险 | AI 判定正确，存在真实风险 |
| `detect_accurate` | `no` | `yes` |
| 消息通知 `read` | **转为已读**（`true`） | **转为已读**（`true`） |
| 处理状态 `status` | **直接转为已处理**（`handled`） | 保持**未处理**（`pending`） |
| 是否需要填写处理内容 | **不需要**，流程直接结束 | **需要**，点击「处理」按钮 |
| 处理动作 | 无 | 填写**处理结果**与**处理图片** |
| 处理后 `status` | — | 由**未处理 → 已处理**（`handled`） |
| 落库字段 | `detect_accurate` / `accurate_by` / `accurate_dt` / `read` / `read_dt` / `status` | 上述 + `handle_result` / `handle_image` / `handler` / `handled_dt` |

> **注意**：两条分支**都要求消息通知转为已读**。区别在于点「否」是误报，系统直接归档，
> 无需人工填写处理结果；点「是」是真实风险，必须补充处理结果与处理图片才算闭环。
> 接口：`PUT /web/risks/:id/accurate`（复核准确性）、`PUT /web/risks/:id/handle`（处理）。

**（3）点击「删除」**

- 弹出确认框；**点击「确定」**后删除该条数据，**点击「取消」**则不删除。
  接口：`DELETE /web/risks/:id`。

**（4）搜索**

支持以下条件组合搜索：风险类型、所属区域、发生时间（区间）、状态、设备名称、设备编号。

**（5）列内快捷筛选（点击列表单元格即筛选）**

- **点击「风险类型」列** → 直接筛选出该类型的所有数据；
- **点击「设备名称」列** → 筛选出该设备的所有数据（规则与风险类型相同）；
- **点击「设备编号」列** → 筛选出该编号设备的所有数据（规则与风险类型相同）。

三者的交互一致：点击即把该值填入筛选条件并刷新列表。

**（6）三个跳转 / 播放按钮**

| 按钮 | 行为 | 接口 |
|:---|:---|:---|
| 查看视频录像 | 播放该风险对应的视频录像 | 读取 `video_url` |
| 跳转设备监控详情 | **跳转至「设备监控」模块的设备详情**，方便快速查询该设备的监控数据 | 跳转 `/web/devices/:id` |
| 查看实时监控画面 | 播放该设备的实时监控画面 | 读取 `ac_device.stream_url` |

**（7）检测准确 —— 修改入口**

- 对风险图片进行查看，确认检测物体是否准确，可对监控检测准确性进行修改。
- **点击「无」（否）即可修改检测是否准确**——即点击后把该条置为 `detect_accurate=no`，
  按上表分支一执行（直接转已处理 + 已读）。

**（8）刷新频率**

- 可设置风险监控页面的自动刷新频率，**可选值：10 秒 / 30 秒 / 60 秒**。
- 刷新频率为客户端的轮询周期，用于让新上报的风险及时出现在列表中。

**列表字段**：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 风险类型 | **可点击筛选** | `ac_risk_type.name` |
| 风险图片 | 缩略图，点击查看大图 | `ac_risk_record.image_url` |
| 设备名称 | **可点击筛选** | `ac_device.name` |
| 设备编号 | **可点击筛选** | `ac_risk_record.device_code` |
| 所属区域 | — | `ac_region.name` |
| 设备位置 | — | `ac_risk_record.location` |
| 发生时间 | — | `ac_risk_record.occurred_dt` |
| 检测准确 | 是/否，可修改 | `ac_risk_record.detect_accurate` |
| 消息通知 | 未读/已读 | `ac_risk_record.read` |
| 状态 | 未处理/已处理 | `ac_risk_record.status` |
| 处理结果 | — | `ac_risk_record.handle_result` |
| 处理人 | — | `ac_risk_record.handler` |
| 操作 | 查看、处理、删除、查看录像、设备监控、实时视频 | — |

**搜索条件**（手册明确列举，全部必须实现）：

1. 风险类型（`risk_type_id`）
2. 所属区域（`region_id`）
3. 发生时间（`occurred_dt` 区间）
4. 状态（`status`）
5. 设备名称（关联 `ac_device.name` 模糊）
6. 设备编号（`device_code` 模糊）

**排序**：按**发生时间倒序**（最新风险在最前）；支持风险类型、设备名称、设备编号的列内快捷筛选。

### 4.4 风险上报（设备端）

**业务规则**：

- 设备通过 `POST /web/risks/report`（**ApiKey 鉴权**，无用户上下文）上报风险。
- 平台落库时：
  1. 按上报的 `risk_type` 编码匹配 `ac_risk_type`，取 `id` 写入 `risk_type_id`，
     并把该类型的 `level` **冗余**写入 `risk_level`；
  2. 按设备编号匹配 `ac_device`，取 `id` 写入 `device_id`，并**冗余**写入
     `device_code`、`region_id`、`location`（均为上报时刻的快照）；
  3. `status=pending`，`read=false`，`detect_accurate` 为空（**待人工确认**）；
  4. `voice_played=false`，若匹配到语音配置则触发播报并置 `true`。
- 上报成功后，按「风险通知设置」的通知策略生成 `ac_notification` 并按频率推送
  （个推 / 短信 / 站内），见 `10-首页与告警设置模块.md`。

## 5. 状态机

### 5.1 风险记录状态流转（核心）

```
                       设备上报风险
                            │
                            ▼
              ┌─────────────────────────────┐
              │   status   = pending        │
              │   read     = false          │
              │   detect_accurate = (空)    │
              │   → 列表显示「未处理 + 未读」│
              └──────────────┬──────────────┘
                             │
              ┌──────────────┴───────────────┐
              │                              │
   点击「查看」│                              │ 直接点「检测准确」
   （仅转已读）│                              │
              ▼                              │
   ┌─────────────────────┐                   │
   │ read = true         │                   │
   │ read_dt = now       │                   │
   │ status 仍 pending   │                   │
   └──────────┬──────────┘                   │
              │                              │
              └──────────────┬───────────────┘
                             ▼
                人工判定「检测准确」
                             │
        ┌────────────────────┴────────────────────┐
        │                                         │
   点「否」（AI 误报）                     点「是」（真实风险）
        │                                         │
        ▼                                         ▼
┌───────────────────────┐            ┌──────────────────────────┐
│ detect_accurate = no  │            │ detect_accurate = yes    │
│ read       = true     │            │ read       = true        │
│ status     = handled  │            │ status     = pending     │
│ accurate_by / _dt 记录│            │ accurate_by / _dt 记录   │
│                       │            │                          │
│ ▶ 直接转「已处理」    │            │ ▶ 仍为「未处理」         │
│ ▶ 无需填写处理内容    │            │ ▶ 等待人工处理           │
└───────────┬───────────┘            └────────────┬─────────────┘
            │                                     │
            │                          点击「处理」按钮
            │                                     │
            │                                     ▼
            │                      ┌──────────────────────────┐
            │                      │ 填写「处理结果」          │
            │                      │ 上传「处理图片」          │
            │                      └────────────┬─────────────┘
            │                                   ▼
            │                      ┌──────────────────────────┐
            │                      │ status      = handled    │
            │                      │ handle_result / _image   │
            │                      │ handler / handled_dt     │
            │                      └────────────┬─────────────┘
            │                                   │
            └───────────────┬───────────────────┘
                            ▼
              ┌─────────────────────────────┐
              │   终态：status = handled    │
              │   （可被删除，不可再处理）  │
              └──────────────┬──────────────┘
                             │ 点击「删除」并确定
                             ▼
                    deleted_at 置值（软删除）
```

### 5.2 检测准确性确认状态

```
   ┌──────────────────┐   人工点「是」   ┌──────────────────┐
   │  未确认           │ ───────────────▶ │  yes 检测准确     │
   │ detect_accurate  │                  │ status=pending   │
   │   = (空)         │ ───────────────▶ │                  │
   │ 待人工复核        │   人工点「否」   ├──────────────────┤
   └──────────────────┘                  │  no 检测不准确    │
                                         │ status=handled   │
                                         └──────────────────┘
   已确认后可再次修改（例如误点了「是」，后续确认实为误报）
```

### 5.3 消息通知已读状态

```
   ┌──────────────┐  查看 / 复核准确性 / 处理   ┌──────────────┐
   │   未读        │ ─────────────────────────▶ │   已读        │
   │  read=false   │                            │  read=true    │
   │ 系统通知红点  │                            │ read_dt 记录  │
   └──────────────┘                            └──────────────┘
```
