# 设备接入与国标视频模块

> 版本: v0.2.0
> 最后更新: 2026-10-21
> 需求来源: AI摄像头操作手册 第 11 节（国标视频）
> 实现状态: 已实现（Wave 1–3）。本期边界与已知限制见 §8，**未实现的能力不会在本文中写成「已完成」**。

## 1. 模块概述

本模块把 AI 摄像头之外的 **GB/T 28181 国标设备**接入平台，提供从「设备建档 → SIP 注册 →
目录同步 → 实时播放 / 云台 / 回放 / 语音」的完整链路，并把流媒体收流交给独立的
**ZLMediaKit（ZLM）** 节点，平台只负责信令、鉴权、编排与配置管理。

模块解决四类现场问题：

- **非 AI 相机接入**：现场已有的国标枪机 / 球机 / NVR 通道，无法通过 v0.1.0 的设备心跳协议接入；
- **统一观看入口**：在同一个管理后台里观看国标实时画面、回放设备侧录像、下载录像；
- **设备控制**：云台方向 / 变焦 / 预置位 / 巡航 / 扫描 / 雨刷，以及语音广播与对讲；
- **运维排障**：信令日志、媒体节点状态、拉流代理与推流配置、级联配置。

模块由两个 Go 入口共同承载：

| 入口 | 职责 |
|:---|:---|
| `cmd/server` | `/web/gb/*`、`/app/gb/*`、`/media/hook/*` REST 接口；业务编排；ZLM REST 调用 |
| `cmd/sipsvc` | SIP 监听（5060 udp/tcp）、REGISTER/Digest、Keepalive、Catalog、INVITE、MESSAGE/INFO |

> **架构不变量**：SIP 进程**不碰媒体包**。RTP/PS 由设备直发 ZLM，Go 侧不做
> RTP/PS 解复用（依据：设计文档 §2.1；实现见 `internal/gb28181/sipserver` 包注释）。

## 3. 数据模型

### 3.1 复用 `ac_device`（新增 13 列）

国标设备复用 v0.1.0 的 `ac_device`，**只处理 `gb_device_id` 非空的记录**。
`device_code`（业务编号，如 `CAM_001`）与 `gb_device_id`（20 位国标编码）是**两个命名空间**，
不互相转换、不互相复用。

| 字段 | 说明 |
|:---|:---|
| `gb_device_id` | 20 位国标编码，SIP From 头携带；部分唯一索引（NULL 不参与） |
| `sip_password` | 设备 SIP Digest 密码（敏感，接口返回 `****`） |
| `sip_realm` | SIP 鉴权域，缺省取 `gb28181.sip.domain` |
| `sip_transport` | 信令传输：UDP / TCP |
| `stream_mode` | 媒体传输：UDP / TCP-PASSIVE / TCP-ACTIVE（本期实际使用 UDP） |
| `charset` | XML 报文编码：GB2312 / UTF-8 |
| `register_status` | 注册状态：`pending` / `activated` / `rejected` |
| `register_dt` | 首次注册成功时间（只写一次） |
| `sip_expires` | 注册过期时间；过期后判定离线 |
| `media_server_id` | 绑定媒体节点，`auto` 表示自动选择默认节点 |
| `channel_count` | 通道数（冗余，列表展示用） |
| `local_ip` | 设备级源 IP 覆盖（多网卡场景） |
| `sdp_ip` | 设备级 SDP IP 覆盖（NAT 场景） |

## 4. 功能需求

### 4.1 设备建档与激活

**操作说明**：在「国标设备」页新建 / 选择一条设备，点击「生成激活凭证」。

**业务规则**：

- 设备仍复用「资源管理 → 设备管理」的建档能力；国标接入字段在设备上补齐。
- 「生成激活凭证」是**幂等**的：
  - `gb_device_id` 为空时生成 20 位编码：`<domain 10 位><类型 3 位 132><序号 7 位>`；
    序号优先取 `ac_sequence` 的原子自增，回落为「同前缀最大序号 + 1」，最后做唯一性校验；
  - `sip_password` 为空时生成 16 位随机密码；
  - 已有编码 / 密码时**保持原值**，不会因为重复点击导致设备掉线。
- 返回内容包括：国标编码、SIP 密码、SIP 服务器地址 / 端口、域、传输协议、注册状态，
  以及供前端画二维码的 `qr_content`（一段 JSON 字符串）。
- 首次 REGISTER 鉴权通过后，`register_status` 由 `pending` 变为 `activated`。

### 4.2 SIP 接入、白名单与 Digest

**业务规则**：

- **白名单**：收到任何 SIP 请求，先按 From 头的用户部分查 `ac_device.gb_device_id`；
  查不到（未建档、为空或已软删除）一律 **403 Forbidden**，并写 `ac_gb_sip_log`。
  **绝不退化为用 `device_code` 匹配**。
- **Digest（仅 REGISTER）**：首次请求返回 **401 + WWW-Authenticate**，带凭证后按
  RFC 2617 MD5 校验；`qop=""`（RFC 2069）与 `qop=auth` 都支持，`nc` 按客户端原样传值参与计算。
- **MESSAGE 不强制 Digest**：真机与模拟器的 Keepalive / Catalog 响应 MESSAGE 通常不带
  `Authorization`。对 MESSAGE 只做白名单 + 源地址 + 域前缀校验。
- nonce 无状态：`HMAC-SHA256(secret, deviceID|epoch)`，不入库、不入缓存；
  校验时接受当前与上一个 epoch，给跨窗口的注册往返留余量。
- 密码错误：`register_status` 置 `rejected`，但**不直接改在线状态**（设备可能仍在发心跳）。

### 4.3 通道同步（目录）

**操作说明**：设备列表点击「同步通道」，或对设备「订阅目录」。

**业务规则**：

- 同步 = 向设备发 Catalog 查询（MANSCDP，带外 MESSAGE），设备异步返回。
- 设备会把 `SumNum` 条通道拆成多片，每片复用同一个 SN。平台按 `(deviceID, SN)`
  **重组多片**，收齐后才落库，避免半份目录覆盖出错误的 `channel_count`。
- 目录按字节预算分片；模拟器 `--channels 25` 可稳定触发多片。
- 目录中的中文名称按设备 `charset`（缺省 GB2312）解码；落库为 UTF-8。
- 目录同步**保留用户字段**：`region_id`、`group_id`、`record_plan_id`、`remark`、
  `enable_broadcast` 等不会被设备目录覆盖。
- 超时未收齐的分片会被丢弃，不产生半份通道数据。
- 通道状态 `ON` / `OFF` 来自目录项；播放前只会校验设备是否 **online**，
  `register_status=rejected` 不直接阻止播放（设备可能仍在发心跳）。

### 4.4 实时播放

**操作说明**：「实时播放」页选择设备 / 通道，点击播放。

**业务规则**：

- 播放前校验：通道存在、设备在线（`ac_device.status = online`）、有可用媒体节点。
- 播放接口**返回播放地址集合，不返回媒体本体**：`webrtc`（WHEP）、`flv`（HTTP-FLV）、
  `hls` 三条完整 URL，另附 `http_base` / `app` / `stream` 供前端自行拼接。
- 流名规则：`stream = %08X(ssrc)` **大写 16 进制**（单端口模式同样如此）；
  `app` 恒为 `rtp`。`{deviceId}_{channelId}` 只是鉴权映射键，**不是** ZLM 流名。
- 点播编排等待 ZLM 建流最多 **5 秒**（250ms 轮询）；超时返回「设备未在限定时间内推送媒体流」。
- 停止播放是设备离线后的清理手段，因此**不校验设备在线**；前端回传的 `stream_id`
  必须属于该通道，避免「拿着 A 通道的 stream_id 停掉 B 通道」。
- 抓图：调用 ZLM 抓图接口并落盘到上传目录，返回可访问 URL。
- 前端播放策略：**WebRTC(WHEP) 优先 → HTTP-FLV（`mpegts.js`）兜底 → HLS 保底**；
  WebRTC 失败自动回落 FLV。

### 4.5 云台控制

**操作说明**：实时播放页的云台面板（方向 / 变焦 / 光圈 / 聚焦 / 预置位 / 巡航 / 扫描 / 雨刷）。

**业务规则**：

- 云台走**带外 MESSAGE**（MANSCDP `DeviceControl` / `PTZCmd`），与回放控制的带内 INFO 不同。
- 方向：`up` / `down` / `left` / `right` / `up-left` / `up-right` / `down-left` / `down-right` / `stop`。
- 速度量纲 **1–8**（1 最慢、8 最快，缺省 5），后端映射到 PTZCmd 的 `0x00–0xFF` 字节。
- 变焦 / 光圈 / 聚焦是独立动作，与方向互斥。
- 预置位：查询 / 新增 / 删除 / 调用，编号 1–255。
- 巡航 / 扫描：`start` / `stop`，带巡航组号；雨刷为开关。
- **调用预置位**使用 PTZCmd `0x82`（v0.2.0 补充端点）。

### 4.6 回放与下载

**操作说明**：「录像回放」页选择通道与时间范围检索设备侧录像；「录像下载」页创建下载任务。

**业务规则**：

- 录像检索走**带外 MESSAGE**（`RecordInfo`），按设备响应超时返回已收到的部分；
  `timeout=true` 表示设备未在等待窗口内回齐。
- 回放：INVITE（SDP `s=Playback`）建立会话，返回与实时播放同构的播放地址。
- 回放控制（暂停 / 恢复 / 拖动 / 倍速）走**带内 SIP INFO + MANSRTSP**，
  **不复用**云台的发送函数。
- 下载：INVITE（SDP `s=Download`），任务记录保存在**进程内存**；停止下载即结束会话。
  服务重启后任务列表丢失，这是本期已知限制。
- 录像检索的时间格式为 `2006-01-02T15:04:05`，结束时间必须晚于开始时间。

### 4.7 云端录像

**操作说明**：「云端录像」页按日期与通道筛选、播放、下载、收藏、删除。

**业务规则**：

- `ac_gb_cloud_record` 是 **ZLM 落盘 MP4 的索引**，不是下载任务表。
- 播放 / 下载地址由媒体节点拼接，`download` 只支持**单文件直接下载**：
  响应中 `packaging` 恒为 `false`，**不做合并 / 切片 / 打包**。
- 收藏（`collect`）用于标记需要长期保留的录像；删除是软删除索引。
- **已知限制**：`on_record_mp4` 回调当前只记录日志，尚未写入 `ac_gb_cloud_record` ——
  缺少 `(app, stream) → (device_id, channel_id)` 的 SSRC 注册表，强行写会产生无归属记录。
  因此新录制的 MP4 不会自动出现在云端录像列表，列表功能对已有数据可用。

### 4.8 录像计划

**操作说明**：「录像计划」页维护周计划与时间段，并绑定通道。

**业务规则**：

- 计划与通道的绑定关系存放在 `ac_gb_channel.record_plan_id`，**明细表不含 `channel_id`**。
- 删除仍被通道引用的计划会被拒绝，需先解除绑定。
- **本期只做配置 CRUD，不做定时调度**：到点调用 ZLM `startRecord` / 设备 `RecordCmd`
  的调度器不在本期范围；`active`、`snap` 只是配置值，不会自动驱动录制。

### 4.9 国标报警

**操作说明**：「国标报警」页查看、抓图、处理、清空。

**业务规则**：

- 报警由设备通过 MESSAGE（`CmdType=Alarm`）主动上报，写入 `ac_gb_alarm`；
  与平台侧 AI 告警 `ac_alarm_record` 是两套数据。
- 支持报警级别（1 特急 / 2 紧急 / 3 一般 / 4 其他）、报警方式、报警类型、经纬度、关联抓图 / 录像。
- 处理：写 `handled=true`、处理人与备注；抓图：实时向通道抓图；清空：按 ID 批量软删除。
- 关联设备 / 通道名称由 service 层填充，列表不只显示 ID。

### 4.10 移动位置

**操作说明**：「移动位置」页查看最新位置、实时列表与历史轨迹，并可订阅。

**业务规则**：

- 位置来自设备 MESSAGE（`CmdType=MobilePosition`），写入 `ac_gb_mobile_position`。
- 订阅走 SUBSCRIBE（RFC 3265），订阅类型 `mobile_position`，可设置上报间隔。
- **GIS 展示**：本期仅以表格 / 经纬度数值展示，不引入地图库（与 v0.1.0 的
  「CSS 网格底板 + 归一化坐标」方案一致，页面暂无地图底图）。

### 4.11 拉流代理

**操作说明**：「拉流代理」页新增 / 编辑 / 启动 / 停止 / 删除。

**业务规则**：

- 平台让 ZLM 主动从 `rtsp` / `rtmp` / `http` 源拉流，ZLM 是客户端。
- `Create` / `Update` 只落配置，**不触发重连**；`Start` 才调用 ZLM `addStreamProxy`，
  `Stop` 调用 `delStreamProxy`。
- 同一节点的 `app + stream` 不允许重复。

### 4.12 推流

**操作说明**：「推流」页维护推流配置、复制推流地址、启用 / 停用。

**业务规则**：

- 平台按媒体节点生成推流地址（列表可复制），由**外部编码器**推到该地址。
- **Start / Stop 只维护启用状态**（`status`、`pushing`、`push_time`），
  不会调用 ZLM 或设备发起真实推流。UI 文案必须表达为「启用配置」，不能显示为「推流中」。
- 理由：ZLM 的 `addFFmpegSource` 语义是拉流；本期级联 SIP 交互也不在范围内。

### 4.13 国标级联（配置面）

**操作说明**：「上级平台」页维护上级平台、级联通道、分组 / 区域可见范围。

**业务规则**：

- 本期**只做配置与映射表 CRUD**：
  - 不向上级平台发起 REGISTER / SUBSCRIBE；
  - 不推送 Catalog；
  - 不处理上级的 INVITE。
- 已维护的数据：上级平台编码 / 地址 / 账号密码 / 字符集、推送给上级的通道及定制编码 / 名称、
  按分组 / 按区域推送目录的可见范围。
- 这些 SIP 交互留给后续批次；本模块**不做任何「看起来已级联」的假动作**。

### 4.14 语音广播与对讲

**操作说明**：实时播放页的「语音广播」「语音对讲」按钮。

**业务规则**：

- 平台向通道发 INVITE（SDP `s=Broadcast` / `s=Talk`，`m=audio PCMA/8000`），
  设备 200 OK 的 SDP 给出回推目标；ZLM `startSendRtp` 向设备喇叭回推音频。
- 会话落 `ac_voice_session`（`active` → `ended` / `failed`）。
- **默认半双工**（`mode=half_duplex`）：全双工必然自激，设备喇叭声音会被自身麦克风收回。
- **best-effort**：`startSendRtp` 可能因音频源未就绪失败，此时**保留已建立的语音通道并告警**，
  不把整个会话判失败；停止接口也尽量完成清理，不因单步失败返回 503。
- 同一通道同一时刻只允许一路语音会话（`ErrGbVoiceSessionBusy`）。
- 广播需通道 `enable_broadcast=true`。

### 4.15 语音 Agent 配置

**操作说明**：「语音 Agent」页配置 STT / LLM / TTS / VAD 与 Pipecat 控制面。

**业务规则**：

- 复用 `ac_thirdparty_config`（`Category='voice_agent'`），provider 字典来自 `ac_voice_provider`。
- 敏感键（`*_api_key`、`pipecat_token`）**只写不读**：读接口返回 `****`，
  写接口收到空值或含 `****` 时跳过，不会把展示值覆盖成真密钥。
- 「测试」按类别（stt/llm/tts）验证 provider 连通性，需要 `voice:agent:test` 权限。
- 「下发配置」把配置 POST 到 Pipecat 控制面 `/config`（Bearer token），需要 `voice:agent:apply` 权限。
- 对讲会话启动时会探测 Pipecat 可达性；不可达则**降级为纯对讲**（`agent_enabled=false`）。

### 4.16 信令日志

**操作说明**：「信令日志」页按设备编码 / 方法 / 命令类型 / 结果 / 时间筛选，查看详情与统计。

**业务规则**：

- 追加写入 `ac_gb_sip_log`；队列满时**丢弃并计数，绝不阻塞信令主流程**。
- 记录方向、方法、MANSCDP 命令类型、SIP 状态码、Call-ID、报文内容（截断）、
  处理结果与原因、耗时。
- 无 `dept_id`、不走 DataScope，由 `gb:sip-log:list` 控制。
- 统计接口返回成功 / 拒绝 / 失败数量与总数。

## 5. 状态机

### 5.1 设备注册状态（`ac_device.register_status`）

```
   ┌──────────┐   首次 REGISTER 鉴权通过    ┌────────────┐
   │ pending  │ ─────────────────────────▶ │ activated  │
   │ 已建档   │                            │ 已激活     │
   └────┬─────┘                            └─────┬──────┘
        │                                        │
        │ Digest 校验失败                        │ Digest 校验失败
        ▼                                        ▼
   ┌──────────┐   后续注册成功               ┌────────────┐
   │ rejected │ ─────────────────────────▶ │ activated  │
   └──────────┘                            └────────────┘
```

> `rejected` 只反映「最近一次鉴权失败」，**不直接改在线状态**：
> 设备可能仍在发心跳，直接判离线会与心跳逻辑打架。

### 5.2 设备在线状态（`ac_device.status`）

```
   REGISTER 成功 / Keepalive
   ┌─────────┐ ─────────────────────▶ ┌─────────┐
   │ offline │                        │ online  │
   └─────────┘ ◀───────────────────── └─────────┘
                sip_expires 到期（扫描任务）
```

- 注册有效期只由 REGISTER 决定，**心跳不延长 `sip_expires`**。
- 过期扫描把 `status` 置 `offline`、写 `offline_dt`，**不删除设备，也不删除通道**。
- 进程重启后，设备的下一包 REGISTER / Keepalive 会补齐内存中的源地址。

### 5.3 通道状态

| 值 | 含义 | 来源 |
|:---:|:---|:---|
| `ON` | 通道在线 | 目录 / 设备状态 |
| `OFF` | 通道离线 | 目录 / 设备状态 |

通道 `status` 不单独做定时探测，随目录同步与设备状态更新。

### 5.4 播放 / 语音会话状态

```
   播放： idle ──INVITE + ZLM 建流成功──▶ playing ──停止 / BYE──▶ idle
                └──5s 内未建流──▶ 失败（返回明确错误，不挂死 HTTP）

   语音： active ──Stop / BYE / 错误──▶ ended
                └──无法清理──▶ failed
```

## 6. 非功能需求

### 6.1 容量目标

| 指标 | 目标 | 说明 |
|:---|:---:|:---|
| 接入设备数 | **100 台** | 心跳为 MESSAGE，约 1.7 msg/s，sipsvc 压力可忽略 |
| 并发点播路数 | **20 路** | 决定带宽与 CPU，是最关键容量变量 |
| 出口带宽 | **30 Mbps** | 按 20 × 1.5 Mbps 均摊码率估算 |
| 云端录像存储（可选） | 约 **2.3 TB / 7 天** | 20 路 × 1.5 Mbps × 7 天，`record_day=7` |
| 媒体节点 | **1 个** | 20 路远低于单 ZLM 上限；多节点调度本期不做 |

### 6.2 单端口收流

- ZLM 使用**单端口模式**：只开放 `10000/udp`（TCP-PASSIVE 时同时 `10000/tcp`），
  设备统一向该端口打流，ZLM 按 SSRC 自动建流。
- 平台**不调用** `openRtpServer`；SDP 里直接通告 `rtp_proxy_port`。
- 因此 **TCP-ACTIVE 不可用**（需要 ZLM 主动拨号，单端口模式不创建流级 RTP server）。
- `deploy/zlm/config.ini` 刻意不设 `port_range`：设了会让误用的 `openRtpServer(port=0)`
  从端口段取端口，埋下隐蔽问题（实测存在断言失败风险）。

### 6.3 编码与协议

- XML 缺省 **GB2312**，按设备 `charset` 编解码；目录 / 设备名等中文不能出现乱码。
- SIP 信令走 UDP（模拟器与本期联调均验证 UDP；TCP 信令的模拟器支持不在本期）。
- 回放控制 `MANSRTSP`、云台 `PTZCmd`、目录 `Catalog` 必须使用正确的 `Content-Type`。

### 6.4 安全

- SIP 白名单 + REGISTER Digest + MESSAGE 源地址 / 域名前缀校验。
- 四个敏感字段脱敏返回：`ac_device.sip_password`、`ac_gb_media_server.secret`、
  `ac_gb_platform.password`、`ac_gb_channel.password`。
- ZLM hook 使用 `secret` 查询参数校验；`/media/hook/*` **不挂** JWT / Casbin 中间件。
- 语音 Agent 的 API Key 只写不读；`/test` 需独立权限码。

### 6.5 可用性

- 信令日志异步写入，队列满丢弃，不阻塞信令。
- 点播有 5s 建流超时；录像检索有等待窗口，超时返回部分结果。
- `sipsvc` **副本固定为 1**：SIP 事务、TCP 连接与 INVITE 会话状态都是节点本地的；
  横向扩容需要 Redis 注册表与 RPC，本期不做。

以下能力**明确不在本期范围**，文档与 UI 不得表述为已完成：

| # | 边界 | 具体说明 |
|:--:|:---|:---|
| 1 | **级联只做配置** | 不向上级 REGISTER / SUBSCRIBE、不推送 Catalog、不处理上级 INVITE |
| 2 | **推流只维护状态** | 不调用 ZLM 发起真实推流；由外部编码器使用平台生成的地址推流 |

| 5 | **JT/T 1078 不做** | 车载终端与 `ac_jt_*` 表已整体移出范围 |
| 6 | **云端录像索引不自动产生** | `on_record_mp4` 只记日志，未写 `ac_gb_cloud_record`（缺 SSRC → 设备/通道映射） |
| 7 | **下载任务不持久化** | 任务表在进程内存，重启丢失；不支持合并 / 切片 / 打包 |
| 8 | **ZLM hook 推流/播放鉴权暂时放行** | `on_publish` / `on_play` 当前恒 `allow=true`；未知 SSRC 也能向 10000 端口打流 |
| 9 | **Go 侧不解 RTP/PS** | 媒体完全由 ZLM 处理，平台不解析 PS / 不转封装 |
| 10 | **分进程部署的命令面限制** | `sipsvc` 独立进程时，API 进程的 `control.Default()` 为 nil，播放 / 云台 / 回放等 HTTP 触发的 SIP 命令会返回「信令服务未启动」；需用 `gb28181.embedded=true` 单进程模式，或后续补 RPC |
| 11 | **TCP-ACTIVE 媒体不收流** | 与单端口模式互斥；本期联调只验证 UDP |
| 12 | **GIS 无地图底图** | 移动位置以表格与经纬度展示，未引入地图库 |
