# 设备告警模块

> 版本: v0.1.0
> 最后更新: 2026-09-21
> 需求来源: AI摄像头操作手册 第 5.3 节（设备告警）、第 5.4 节（物联网卡监控）

## 1. 模块概述

设备告警模块关注**设备自身的健康异常**，与风险监控模块形成互补：

| | 风险监控 | 设备告警 |
|:---|:---|:---|
| 数据来源 | AI 模型识别结果（设备「看到了什么」） | 设备状态探测（设备「自己怎么了」） |
| 典型类型 | 未戴安全帽、明火、人员闯入 | **离线告警、电量告警、流量告警** |
| 触发方 | 设备主动上报 `POST /web/risks/report` | 设备上报告警 / 平台探测 `POST /web/alarms/report` |
| 处理方式 | 复核准确性 + 填写处理结果与图片 | 填写处理结果与处理图片 |

本模块包含两个页面：

- **设备告警**：告警记录列表与处理闭环（手册 5.3）。
- **物联网卡监控**：物联网卡流量使用情况（手册 5.4）。流量告警的数据基础即来自此页——
  当剩余流量低于阈值时由平台生成「流量告警」。

> **注意**：平台内置告警类型为**离线告警（`offline`）、电量告警（`battery`）、
> 流量告警（`traffic`）**三种，定义在 `ac_alarm_type`（见 `02-基础信息模块.md`）。
> 每种告警的通知人员、通知类型与报警频率由「设备告警设置」按用户配置
> （见 `10-首页与告警设置模块.md`）。

## 2. 角色与权限

| 角色 | 可执行操作 |
|:---|:---|
| 系统管理员 | 查看、处理、删除告警；查看物联网卡流量；配置告警设置 |
| 区域管理员 | 同上（受数据权限约束） |
| 安全员 | 查看告警、处理告警（填写处理结果与处理图片）；查看物联网卡流量 |
| 设备运维员 | 查看告警并处理（离线/电量/流量多为设备运维范畴）；维护物联网卡 |
| 巡检员 | 移动端：查看待处理告警、提交处理结果与处理图片 |

权限码：

| 权限码 | 说明 |
|:---|:---|
| `alarm:list` | 查看设备告警列表与详情 |
| `alarm:read` | 标记消息已读（点击「查看」时自动触发） |
| `alarm:handle` | 处理告警（填写处理结果与处理图片） |
| `alarm:delete` | 删除告警记录 |
| `card:monitor` | 查看物联网卡监控（流量使用情况） |
| `alarmSetting:list` / `alarmSetting:update` | 设备告警设置（见 10 模块） |

### 3.2 ac_alarm_record - 设备告警记录

```sql
CREATE TABLE ac_alarm_record (
    id              BIGSERIAL PRIMARY KEY,
    deleted_at      TIMESTAMPTZ,
    created_by      VARCHAR(50),
    created_dt      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_by      VARCHAR(50),
    updated_dt      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,

    alarm_type_id   BIGINT NOT NULL,                       -- 告警类型ID
    device_id       BIGINT NOT NULL,                       -- 设备ID
    device_code     VARCHAR(100),                          -- 设备编号(冗余)
    region_id       BIGINT,                                -- 所属区域
    location        VARCHAR(255),                          -- 设备位置(冗余)
    alarm_level     VARCHAR(20),                           -- 告警等级(冗余)
    content         TEXT,                                  -- 告警内容
    occurred_dt     TIMESTAMPTZ,                           -- 告警时间

    read            BOOLEAN DEFAULT FALSE,                 -- 消息通知是否已读
    read_dt         TIMESTAMPTZ,                           -- 已读时间

    status          VARCHAR(20) DEFAULT 'pending',         -- 处理状态 pending/handled
    handle_result   TEXT,                                  -- 处理结果
    handle_image    VARCHAR(500),                          -- 处理图片
    handler         VARCHAR(50),                           -- 处理人
    handled_dt      TIMESTAMPTZ,                           -- 处理时间

    dept_id         BIGINT                                 -- 所属部门(数据权限)
);
CREATE INDEX idx_ac_alarm_record_alarm_type_id ON ac_alarm_record (alarm_type_id);
CREATE INDEX idx_ac_alarm_record_device_id ON ac_alarm_record (device_id);
CREATE INDEX idx_ac_alarm_record_region_id ON ac_alarm_record (region_id);
CREATE INDEX idx_ac_alarm_record_occurred_dt ON ac_alarm_record (occurred_dt);
CREATE INDEX idx_ac_alarm_record_status ON ac_alarm_record (status);
CREATE INDEX idx_ac_alarm_record_dept_id ON ac_alarm_record (dept_id);
CREATE INDEX idx_ac_alarm_record_deleted_at ON ac_alarm_record (deleted_at);

COMMENT ON TABLE ac_alarm_record IS '设备告警记录。结构与 RiskRecord 平行：告警来自设备自身状态（离线/电量/流量），风险来自 AI 识别。两者在「系统通知」中统一汇聚';
COMMENT ON COLUMN ac_alarm_record.device_code IS '设备编号(冗余)';
COMMENT ON COLUMN ac_alarm_record.location IS '设备位置(冗余)';
COMMENT ON COLUMN ac_alarm_record.alarm_level IS '告警等级(冗余)';
COMMENT ON COLUMN ac_alarm_record.content IS '告警内容';
COMMENT ON COLUMN ac_alarm_record.read IS '消息通知是否已读';
COMMENT ON COLUMN ac_alarm_record.status IS '处理状态 pending/handled';
```

相关常量：

| 常量 | 值 | 含义 |
|:---|:---|:---|
| `HandleStatusPending` | `pending` | 未处理 |
| `HandleStatusHandled` | `handled` | 已处理 |
| `AlarmCodeOffline` | `offline` | 离线告警 |
| `AlarmCodeBattery` | `battery` | 电量告警 |
| `AlarmCodeTraffic` | `traffic` | 流量告警 |

> **注意**：`ac_alarm_record` 与 `ac_risk_record` **结构与语义平行**，但**没有**
> `detect_accurate` 系列字段——告警来自设备状态探测，不存在「AI 识别准确性」的复核环节。
> 因此告警**只有一条处理路径**：查看（转已读）→ 处理（填写处理结果与处理图片）→ 已处理。

## 4. 功能需求

### 4.1 设备告警

**操作说明**（手册 5.3 节）：

- 设备告警中可查看设备的告警信息，包括告警类型、所属区域、设备名称、设备位置、状态、消息通知、告警时间等相关内容。
- 操作说明：
  - 点击查看，可查看设备告警的详细信息，且该消息通知由未读转为已读状态，；
  - 点击处理，填写处理结果及处理图片可对其告警信息进行处理，处理后状态由未处理转为已处理；
  - 选择告警类型、所属区域、设备名称、操作时间等条件进行搜索。

**业务规则**：

**（1）点击「查看」**

- 打开告警详情，展示告警类型、告警等级、告警内容、设备信息、所属区域、设备位置、告警时间。
- **同时把该条的消息通知由未读转为已读**（`read=true`，写 `read_dt`）。
  接口：`PUT /web/alarms/:id/read`。

**（2）点击「处理」**

- 弹出处理表单，填写**处理结果**与**处理图片**。
- 提交后**状态由未处理转为已处理**（`status: pending → handled`），
  同时记录 `handler`（当前登录用户）与 `handled_dt`（当前时间）。
- 接口：`PUT /web/alarms/:id/handle`。
- 处理图片通过 `POST /web/upload` 上传后取 URL 写入 `handle_image`。

**（3）搜索**

支持以下条件组合搜索：告警类型、所属区域、设备名称、操作时间（区间）。

**（4）告警产生**

| 告警类型 | 触发条件 | 判定依据 |
|:---|:---|:---|
| 离线告警 `offline` | 设备超过心跳间隔未上报，或主动离线 | `ac_device.status` 翻转为 `offline` |
| 电量告警 `battery` | 设备电量低于「设备告警设置」中配置的阈值 | `ac_device.battery` < 阈值 |
| 流量告警 `traffic` | 物联网卡剩余流量低于「设备告警设置」中配置的阈值 | `ac_iot_card.traffic_left` < 阈值 |

告警产生后：
1. 写入 `ac_alarm_record`（`status=pending`，`read=false`，冗余写入设备编号/区域/位置/等级）；
2. 按该设备所属区域与「设备告警设置」的**通知人员、通知类型、报警频率**生成
   `ac_notification`（`category=alarm`）并推送（个推 / 腾讯云短信 / 站内）；
3. 在「系统通知」中呈现未读红点。

**列表字段**：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 告警类型 | 离线/电量/流量 | `ac_alarm_type.name` |
| 告警等级 | 高/中/低 | `ac_alarm_record.alarm_level` |
| 告警内容 | — | `ac_alarm_record.content` |
| 所属区域 | — | `ac_region.name` |
| 设备名称 | — | `ac_device.name` |
| 设备编号 | — | `ac_alarm_record.device_code` |
| 设备位置 | — | `ac_alarm_record.location` |
| 状态 | 未处理/已处理 | `ac_alarm_record.status` |
| 消息通知 | 未读/已读 | `ac_alarm_record.read` |
| 告警时间 | — | `ac_alarm_record.occurred_dt` |
| 处理结果 | — | `ac_alarm_record.handle_result` |
| 处理人 | — | `ac_alarm_record.handler` |
| 操作 | 查看、处理 | — |

**搜索条件**（手册明确列举，全部必须实现）：

1. 告警类型（`alarm_type_id`）
2. 所属区域（`region_id`）
3. 设备名称（关联 `ac_device.name` 模糊）
4. 操作时间（`occurred_dt` 区间）

**排序**：按**告警时间倒序**（最新告警在最前）。

### 4.2 物联网卡监控

**操作说明**（手册 5.4 节）：

- 物联网卡监控中可查看物联网卡所使用的流量情况，包括物联网卡名称、物联网卡号、设备编号、所属区域、所属设备、流量总额、剩余流量、使用流量、统计时间等相关内容。
- 选择所属区域、物联网卡名称、卡号、所属设备等条件进行搜索。

**业务规则**：

- 本页是**只读的流量看板**，数据全部来自 `ac_iot_card`（在「资源管理 → 物联网卡管理」中维护）。
- 流量单位统一为 **MB**：`traffic_total`（流量总额）、`traffic_used`（使用流量）、
  `traffic_left`（剩余流量）。
- `stat_dt` 为**统计时间**，即本次流量数据的时间点，用于判断数据新鲜度。
- **设备编号**列取自该卡绑定的设备（`ac_device.device_code`），未绑定时为空并在页面标注「未绑定」。
- 剩余流量低于阈值时，平台按「流量告警」生成 `ac_alarm_record` 并按告警设置通知。
- 本页无新增/编辑/删除操作，卡片的增删改统一在「资源管理 → 物联网卡管理」完成。

**列表字段**：

| 字段 | 说明 | 来源表 |
|:---|:---|:---|
| 物联网卡名称 | — | `ac_iot_card.name` |
| 物联网卡号 | 卡号 | `ac_iot_card.card_no` |
| 设备编号 | 绑定设备的编号 | `ac_device.device_code`（经 `ac_iot_card.device_id`） |
| 所属区域 | — | `ac_region.name` |
| 所属设备 | 绑定设备名称 | `ac_device.name` |
| 流量总额 | MB | `ac_iot_card.traffic_total` |
| 剩余流量 | MB | `ac_iot_card.traffic_left` |
| 使用流量 | MB | `ac_iot_card.traffic_used` |
| 统计时间 | 流量数据时间点 | `ac_iot_card.stat_dt` |
| 到期时间 | — | `ac_iot_card.expire_dt` |
| 状态 | 正常/欠费/到期/停用 | `ac_iot_card.status` |

**搜索条件**（手册明确列举，全部必须实现）：

1. 所属区域（`region_id`）
2. 物联网卡名称（模糊）
3. 卡号（模糊）
4. 所属设备（`device_id`）

**排序**：按统计时间（`stat_dt`）倒序；剩余流量升序（便于先看到快耗尽的卡）。

## 5. 状态机

### 5.1 告警处理状态流转

```
   触发条件命中（离线 / 电量低 / 流量不足）
        │
        ▼
   ┌──────────────────────────────┐
   │   status = pending           │
   │   read   = false             │
   │   → 列表显示「未处理 + 未读」│
   │   → 按告警设置推送通知       │
   └──────────────┬───────────────┘
                  │
    ┌─────────────┴──────────────┐
    │                            │
 点击「查看」                直接点击「处理」
    │                            │
    ▼                            │
┌────────────────────┐           │
│ read   = true      │           │
│ read_dt = now      │           │
│ status 仍 pending  │           │
└─────────┬──────────┘           │
          │                      │
          └──────────┬───────────┘
                     ▼
        ┌──────────────────────────────┐
        │ 填写「处理结果」              │
        │ 上传「处理图片」              │
        └──────────────┬───────────────┘
                       ▼
        ┌──────────────────────────────┐
        │   status    = handled        │
        │   handle_result / _image     │
        │   handler   / handled_dt     │
        │   → 列表显示「已处理」        │
        └──────────────┬───────────────┘
                       │ 点击「删除」并确认
                       ▼
              deleted_at 置值（软删除）

   * 与风险不同：告警没有「检测准确」环节，因此没有「点否直接转已处理」的旁路，
     所有告警都必须经过人工处理。
```

### 5.2 物联网卡流量告警阈值

```
   ac_iot_card.traffic_left
            │
            ├── 高于阈值 ──▶ 状态正常，无告警
            │
            └── 低于阈值 ──▶ 生成 ac_alarm_record（alarm_type = traffic）
                              │
                              ├── 冗余写入 device_code / region_id / location / alarm_level
                              ├── read = false，status = pending
                              └── 按「设备告警设置」的通知策略推送
```
