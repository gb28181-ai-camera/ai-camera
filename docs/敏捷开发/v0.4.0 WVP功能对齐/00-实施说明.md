# v0.4.0 WVP-GB28181-Pro 功能对齐实施说明

> 版本：v0.4.0
> 日期：2026-10-25
> 范围：除 JT/T 1078 部标模块外，WVP-GB28181-Pro 的页面与能力在本项目补齐。
> 对照基线：`docs/敏捷开发/v0.2.0 设备接入与国标视频/界面核对清单.md`（2026-10-24）

## 1. 目标与结论

WVP 是成熟的 GB28181 接入平台；本项目是面向 AI 摄像头的监控平台。本期在**不改变
AI 业务定位**的前提下，把 WVP 的国标运维能力补齐，避免「换到本项目后功能倒退」。

结论：

- WVP 的核心国标链路（注册、目录、云台、点播、回放、下载、云端录像、录像计划、
  报警、移动位置、语音、代理/推流、级联、媒体节点、信令日志）本已具备；
- 本期补齐的是**设备配置/控制、运维面板、日志、分享、播放器引擎、时间轴、地图**；
- **JT/T 1078 部标模块明确不在本期范围**，需要独立协议栈与服务端 TCP 1078 接入；
- 电子地图不再坚持「不引入地图库」的旧决策，改为 Leaflet + OSM。

## 2. 播放器：5 引擎

| 引擎 | 实现 | 默认场景 | 许可 |
|:--|:--|:--|:--|
| WebRTC | WHEP（原生 RTCPeerConnection） | 单通道实时/云台 | 浏览器原生 |
| HTTP-FLV | mpegts.js | 视频墙 / 自动兜底 | MIT |
| Jessibuca | 静态资源动态加载 | 手动选择 | GPL-3.0（见 `public/static/js/jessibuca/README-LICENSE.md`） |
| H265web | WASM 软解 | `codec=H265/HEVC` 自动 | CYL_Free-1.0（见 `public/static/js/h265web/README-LICENSE.md`） |
| HLS | hls.js / Safari 原生 | 兜底 | Apache-2.0 |

设计约束：

1. **切换引擎不重新点播**：同一 ZLM 流可同时提供 WebRTC/FLV/HLS；只有切换通道
   或首次点播才调用 `/web/gb/play`。
2. **视频墙固定 FLV**：浏览器 WebRTC 连接数有限，16 宫格必须用 FLV 铺格子。
3. **H.265 自动路由**：后端 `GbPlayResp.codec` 为 H265/HEVC 时默认 h265web；
   H.264 默认 WebRTC。
4. **回放控制不走本地播放器**：暂停/倍速/seek 仍通过 MANSRTSP 下发，避免
   「画面暂停但设备仍在推流」。
5. **动态加载**：h265web/jessibuca 均为按需 script，不进入默认 bundle。

## 3. 新增后端能力

接口清单见 [00-接口契约.md §17](../../开发文档/后端开发/00-接口契约.md)，
页面说明见 [13-国标视频页面与接口.md §9](../../开发文档/页面功能和接口/13-国标视频页面与接口.md)。

### 3.1 设备与通道控制

- `PUT /web/gb/devices/:id`：SIP/媒体/位置编辑；改国标编码时在线设备拒绝。
- 目录同步进度：进程内状态（idle/syncing/success/failed），嵌入式部署可用。
- 设备控制：`TeleBoot`、`SetGuard/ResetGuard`、`ResetAlarm`。
- 时间统计：聚合 `ac_gb_sip_log` 的 REGISTER/Keepalive 相邻间隔，不新增表。
- 通道扩展：经纬度、监视方位、摄像机类型、位置/房间/用途/补光/保密。
- 手动录像：`RecordCmd`；媒体信息：ZLM `getMediaInfo`。

### 3.2 云台

- 预置位名称持久化到 `ac_gb_ptz_preset`；
- 巡航点 0x84/0x85/0x86/0x87，扫描边界 0x89（数据2=1/2）+ 0x8A；
- 修正原 Cruise/Scan 的非标准指令码。

### 3.3 运维与媒体

- 媒体节点指标：gopsutil 采集后端主机 CPU/内存/磁盘/网络；5s 采样、24h ring。
- 流会话：ZLM `getMediaList`。
- 平台信息：版本/构建/运行时长/SIP/默认节点/DB。
- 日志：zap 内存 ring（5000 条），历史检索 + SSE；慢客户端丢弃，不阻塞业务。
- 报警 SSE：按 `ac_gb_alarm.id` 游标轮询，避免改动信令进程状态。
- 代理/推流播放：复用 `BuildPlayURLs`。
- 推流导入：CSV/TSV，逐行校验并返回错误明细。
- 云端录像合并：ffmpeg `concat -c copy`；失败原因落库；镜像已安装 ffmpeg。
- 免登录分享：独立高熵令牌，库中仅存 SHA-256；匿名路由不挂 JWT/Casbin。

## 5. 部署

### 5.1 本地形态

本期本地联调采用「宿主机 Go 后端 + 容器基础设施」：

```bash
docker compose up -d postgres redis
docker compose --profile gb28181 --profile iot --profile turn up -d
# 宿主机后端：export .env 中的 MQTT/TURN 变量后 go run ./cmd/server/main.go
```

详见 [部署文档 §15](../../部署文档/01-部署与运维.md)。

### 5.2 修复项

1. **mochi-mqtt v2.7.9 `Serve()` 不阻塞**：补信号等待，否则容器反复重启。
2. **mqtt 缺 `host.docker.internal`**：Linux 宿主无法回调宿主机后端。
3. **`gb_device_id` 唯一索引包含空串**：多台非国标设备在 `''` 上冲突；
   已改为排除空串，并在 `bootstrap.AutoMigrate` 做幂等索引修正。
4. **App 服务下发 TURN**：仅在产品实际绑定 TURN 服务时下发，避免误导。

## 7. 已知限制

1. JT/T 1078 未实现（范围外）。
2. 推流导入仅 CSV/TSV，xlsx 需新增依赖。
3. 媒体指标/日志 ring 为进程内数据，重启丢失；多副本各看各的。
4. 云端录像合并要求各段编码参数一致；ffmpeg 缺失时任务失败并提示。
5. 分进程部署（server / sipsvc 分离）时目录同步进度读不到信令进程状态，返回 idle。
6. SSE 前端必须用 `fetch + ReadableStream`（`EventSource` 不能带 Authorization）。
