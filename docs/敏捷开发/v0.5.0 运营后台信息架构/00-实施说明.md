# v0.5.0 运营后台信息架构重组

> 日期：2026-10-25
> 目标：按服务组类型重组运营后台一级目录，让「设备运营」与「AI 业务」边界清晰。

## 1. 一级目录

| 顺序 | 一级目录 | 内容 |
|:--:|:--|:--|
| 1 | 首页 | 数据看板 |
| 2 | 系统管理 | 账号与权限、基础信息、告警设置、第三方平台；**不包含设备资源与升级** |
| 3 | 物联网管理 | 产品管理、服务组、设备管理、设备资源、升级管理、设备监控 |
| 4 | 国标视频 | GB28181 设备/通道、播放与录像、报警与位置、流媒体运维、国标级联、组织管理 |
| 5 | 实时音视频 | WebRTC 服务组设备管理、服务设置 |
| 6 | 智能语音聊天 | AIChat 服务组设备管理、服务设置、语音 Agent |
| 7 | AI 智能分析 | 实时监控、AI 风险、AI 监控、风险监控、巡检中心、统计分析 |

> 「风险统计」旧目录已清空并停用；原「系统设置」改名为「系统管理」；
> 原「IOT 管理」改名为「物联网管理」；原「组织与语音」改名为「组织管理」，
> 语音 Agent 移入「智能语音聊天」。

## 2. 新增页面

| 路由 | 页面 | 说明 |
|:--|:--|:--|
| `/av/device` | 实时音视频设备 | 复用 IOT 设备列表，按产品绑定的 `webrtc` 服务组过滤 |
| `/av/service` | 实时音视频服务设置 | 固定展示 WebRTC 服务组，维护组内服务地址/端口 |
| `/voice/device` | 智能语音聊天设备 | 复用 IOT 设备列表，按 `aichat` 服务组过滤 |
| `/voice/service` | 智能语音聊天服务设置 | 固定展示 AIChat 服务组，维护 WebSocket 接入 |
| `/voice/agent` | 语音 Agent | 从国标视频移入；AIChat 走独立 WebSocket，不属于 GB28181 |

## 3. 设备过滤

`GET /web/iot/devices` 新增 `service_group_type` 查询参数（`gb28181` / `webrtc` / `aichat`）：

```
设备 d → 产品 p (d.product_id)
      → 产品-服务组 psg (psg.product_id = p.id)
      → 服务组 sg (sg.id = psg.service_group_id)
过滤条件：sg.type = :service_group_type
```

未绑定产品或未绑定服务组的设备不会出现在 WebRTC / AIChat 专用页。

> **权限粒度说明**：Casbin 控制的是「能否调用 `/web/iot/devices` 等端点」，
> `service_group_type` 是列表筛选条件，不是行级数据权限。若需要「只能管理
> WebRTC 设备、不能查询 AIChat 设备」的强隔离，需要新增按服务组受限的
> 专用端点或在 Service 层做行级校验，属于后续增强项。

## 4. 菜单与权限

- 菜单种子：`docs/开发文档/数据库设计/sql/init/01-初始数据.sql` §14（幂等）。
- 新菜单权限码：`ai:view`、`av:view`、`av:device:list`、`av:service:view`、
  `voice-chat:view`、`voice-chat:device:list`、`voice-chat:service:view`、
  `iot:monitor-dir:view`。
- 新设备/服务设置菜单复用了 IOT 设备/服务组接口，已在 `ac_menu_api` 中
  为 191/192/201/202 复制对应绑定，Casbin p 策略随 `super_admin` 重建。
- 祖先目录自动补齐：把子菜单授权给角色时，递归补齐父目录，避免侧边栏只显示子项。

## 5. 前端菜单权限配置入口

| 入口 | 路由 | 作用 |
|:--|:--|:--|
| 菜单管理 | `/system/menu` | 维护目录/菜单/按钮、`permission_code`、绑定后端接口（Method + Path） |
| 角色管理 | `/system/role` → 行操作「菜单权限」 | 树形勾选角色可见菜单/按钮；保存后重建 Casbin p 策略 |
| 角色管理 → 部门/岗位/用户 | 同页弹窗 | `g2` / `g3` / `g` 继承授权 |
| 数据权限 | 角色行操作「数据权限」 | `all` / `cross_dept` / `dept` / `personal` |

> 新增按钮权限时仍必须同时补 `ac_menu`（type=button）、`ac_menu_api` 和角色授权，
> 否则前端 `permCodes.includes()` 会静默失效。

## 6. Casbin 验证结论

用受限角色实测（仅授权首页与个人中心）：

| 请求 | 结果 |
|:--|:--|
| `GET /web/stats/dashboard` | 200 |
| `GET /web/profile` | 200 |
| `GET /web/gb/devices` | 403 |
| `GET /web/system/users` | 403 |
| `GET /web/iot/products` | 403 |
| `GET /web/gb/platform-info` | 403 |

结论：Auth → Casbin → 路由级权限链路生效；前端按钮显隐由菜单树的
`permission_code` 驱动，未授权按钮不渲染。
