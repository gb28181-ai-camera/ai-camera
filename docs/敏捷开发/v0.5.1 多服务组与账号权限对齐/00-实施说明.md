# v0.5.1 多服务组并存与账号权限对齐

> 日期：2026-10-25
> 范围：设备多服务组展示/国标接入，以及账号与权限模块对照 boticz-mes 的 P0/P1 修复。

## 1. 多服务组并存

数据模型本身已支持「一个产品绑定多个服务组」，因此同一台设备可以同时属于
GB28181、WebRTC、AIChat。本期补齐的是展示与联动：

- `Device` / `IotProduct` / `GbDeviceItem` 增加 `service_groups` 摘要（非持久化，列表批量填充）。
- `GET /web/iot/devices` 与 `GET /web/gb/devices` 支持 `service_group_type`；GB 设备另支持 `product_id`。
- 过滤条件收敛为：产品未删除、关联未删除、服务组启用，与 OTA 下发语义一致。
- 设备列表显示服务组标签；通用 IOT 设备页可按服务组筛选。
- 产品列表显示服务组标签（不再逐行 N+1 查询数量）。
- 国标设备列表/详情显示所属产品与服务组，可按产品/服务组筛选。
- IOT 设备页新增「国标接入」：产品含 GB28181 组且 `gb_device_id` 为空时可直接生成激活凭证；
  已有国标编码时提供跳转国标设备页的入口。
- 同一设备在 `/iot/device`、`/gb/device/list`、`/voice/device` 等页面可同时出现。

## 2. 账号与权限对齐

| 页面 | 修复/增强 |
|:--|:--|
| 菜单管理 | 可加载停用与移动端菜单；状态快捷开关；菜单→角色授权（`GET/PUT /web/system/menus/:id/roles`）；仅 menu 类型可绑定接口；父级类型校验；删除文案修正 |
| 角色管理 | 状态 Switch（`updateRole active`）；新建/编辑可选数据权限，不再硬编码 `all` |
| 岗位管理 | 新增「分配角色」弹窗（复用 `updatePost.role_ids`） |
| 部门管理 | 父级选择排除自身及全部后代；叶子部门不再回退展示顶级部门；树内启停 |
| 参数配置 | `active` 开关真正生效；支持 integer/float/boolean/select/json；新增 `schema` 编辑与 JSON 校验；排序列 |
| 用户管理 | 新增岗位筛选（`page_user post_id`） |

后端新增/变更：

- `GET /web/system/menus` 增加 `platform=pc|mobile|all`、`include_inactive`。
- `GET/PUT /web/system/menus/:id/roles`（权限码 `system:menu:role`）。
- `ac_system_config` 增加 `schema` 列；`Create/UpdateConfigReq` 增加 `active`、`schema`；
  `data_type` 支持别名归一。
- 菜单父级类型校验：目录→目录，菜单→目录，按钮→菜单（根节点保留兼容）。

## 4. 备注

- 服务组过滤是列表筛选条件，不是行级数据权限；若需「只能管理 WebRTC 设备」的强隔离，
  需要新增按服务组受限的专用端点或在 Service 层做行级校验。
- GB28181 组的 `sip` 服务凭据随 OTA 下发，国标信令鉴权仍使用设备级
  `ac_device.sip_password`；两者职责后续需进一步收敛。
