## 一、项目概述

AI Camera 智能监控平台，以 AI 摄像头为采集终端，覆盖实时视频监控、AI 风险识别与处理闭环、
设备告警、巡检中心、统计分析（含可视化大屏）、设备/固件/模型远程升级、物联网卡管理以及
完整的四级权限体系。平台按「手册驱动」方式开发 —— 功能结构以
`docs/需求文档/AI摄像头操作手册 - 43-8101.docx` 为准，逐条落地为需求文档、DDL、接口契约与代码。

| 项目 | 内容 |
|:---|:---|
| 后端语言 | Go 1.26（Gin 1.12 + GORM 1.25 + Casbin 2.135） |
| 后端分层 | Handler → Service → Repository → Model |
| 前端 Web | React 19 + Ant Design 5 + TypeScript 5.6 + Vite 5（管理后台） |
| 前端官网 | 同 `frontend/` 工程第二入口（`website.html`，base `/`） |
| 前端桌面 | Electron 33 + Electron Forge 7（与管理后台同工程） |
| 移动端 APP | Flutter（GoRouter 14 + Dio 5 + flutter_dva） |
| 数据库 | PostgreSQL 16（业务库 `ai_camera_dev` / `ai_camera_test`） |
| 缓存 | Redis（配置预留，v0.1.0 未接入业务） |
| 权限模型 | JWT + Casbin RBAC（g/g2/g3 三链继承）+ 行级数据权限 |
| 总模块数 | 11 个业务模块（00 需求总览为索引） |
| 总表数 | **38 张**（全部 `ac_` 前缀） |
| 总页面数 | **48 个**（Web 39 + 移动端 9） |
| 总 API 端点数 | **200 个**（`/web/*` 178 + `/app/*` 20 + `/health`） |

## 八、接口代码生成规范（重要‼️）

> ⚠️ **严禁手动编写前端API接口代码！**
>
> 所有 API 调用必须通过 `frontend/src/admin/api/generated/` 中的 Controller 静态方法
> （如 `DeviceController.pageDevices()`）。**禁止** `import request from '../../api/request'`
> 后手动拼接 URL 调用 API（如 `request('/web/xxx', { method: 'PUT' })`）。
> 理由：手动拼接的 URL 无法随后端路由变更自动同步，也无法享受响应类型的强约束，
> 是「接口改了前端不报错、上线才发现 404」的根因。

### 8.1 生成工作流

```
后端 Swagger 注释（handler 文件）
        │
        │  bash scripts/gen-swagger.sh
        ▼
docs/web/swagger.json  +  docs/app/swagger.json
        │
        │  （后端需运行在 :8080，供 swagger2-doc-parser 抓取）
        │  cd frontend && bash scripts/api-gen.sh
        ▼
frontend/src/admin/api/generated/
   ├── XxxController.ts        # 20 个控制器（静态方法）
   └── definitions/*.ts        # 205 个类型定义
        │
        ▼
     UI 代码引用（严格使用生成的响应类型）
```

### 8.2 生成物约束

| 约束 | 说明 |
|:---|:---|
| 禁止手动编辑 | `generated/` 下所有文件由脚本覆盖生成，任何手改都会在下次生成时丢失 |
| 禁止绕开类型 | 前端**禁止**使用 `as any`、`data as any`。类型不匹配时应当修正后端 Swagger 注解并重新生成 |
| 新增 API 必回生成 | 后端新增/修改端点后，必须重新执行 `gen-swagger.sh` + `api-gen.sh`，再更新 UI |
| 响应类型严格对齐 | 简单列表读 `res.data ?? []`（`RXxxList`）；分页列表读 `res.data?.items ?? []`（`RPageXxx`） |

### 8.3 后端 Swagger 注释规范

```go
// PageRisks 分页查询风险记录
//
//	@Summary		风险分页列表
//	@Description	按区域、风险类型、处理状态筛选风险记录
//	@Tags			Risk
//	@Accept			json
//	@Produce		json
//	@Param			page		query		int		false	"页码，默认 1"
//	@Param			page_size	query		int		false	"每页条数，默认 20"
//	@Param			region_id	query		int		false	"所属区域"
//	@Param			status		query		string	false	"处理状态 pending/handled"
//	@Success		200			{object}	response.RPageRiskRecord
//	@Failure		400			{object}	response.RBase
//	@Router			/web/risks [get]
//	@ID				pageRisks
func (h *RiskHandler) Page(c *gin.Context) { ... }
```

| 规则 | 说明 |
|:---|:---|
| `@ID` | 方法名首字母小写；分页接口命名为 `pageXxx`（如 `Page` → `pageRisks`、`pageUsers`） |
| `@Success 200` | 必须与实际返回结构一致；分页必须用类型化 `response.RPageXxx`，**禁止** `response.PageResp` |
| `@Tags` | 与 `00-接口契约.md` 第 2.4 节的 Tags 规范一致 |
| 关联名称字段 | 列表涉及多表关联时必须返回关联表的**名称字段**（`risk_type.name`、`device.name`、`region.name`），不能只返回 ID |

### 8.4 响应类型命名规范

| 类型 | 结构 | 用途 | 示例 |
|:---|:---|:---|:---|
| `RXxxList` | `Data []model.Xxx` 或 `[]OptionItem` | 简单列表（无分页） | `RRiskTypeList`、`RRegionList` |
| `RPageXxx` | `Data PageXxxResp{Items, Total, Page, PageSize}` | 分页列表 | `RPageRiskRecord`、`RPageUser` |

> **注意**：一个端点**不得**在不同条件下返回不同格式（如有时分页有时不分页）。简单列表固定用
> `RXxxList`，分页固定用 `RPageXxx`，前端按固定字段读取。

**APP（Dart）**：

```dart
// app/lib/service/api_service.dart（节选）
import 'package:dio/dio.dart';

class ApiService {
  ApiService(this._dio);

  final Dio _dio;

  /// 分页拉取风险列表；端点：GET /app/risks
  /// 响应格式固定为 {code, message, data:{items,total,page,page_size}}
  Future<PageResult<RiskRecord>> pageRisks({
    required int page,
    int pageSize = 20,
    String? status,
  }) async {
    final resp = await _dio.get<Map<String, dynamic>>(
      '/app/risks',
      queryParameters: {
        'page': page,
        'page_size': pageSize,
        if (status != null) 'status': status,
      },
    );

    final body = resp.data;
    if (body == null || body['code'] != 200) {
      throw ApiException(body?['message'] as String? ?? '请求失败');
    }

    final data = body['data'] as Map<String, dynamic>? ?? const {};
    final items = (data['items'] as List<dynamic>? ?? const [])
        .map((e) => RiskRecord.fromJson(e as Map<String, dynamic>))
        .toList();

    return PageResult(
      items: items,
      total: data['total'] as int? ?? 0,
      page: data['page'] as int? ?? page,
      pageSize: data['page_size'] as int? ?? pageSize,
    );
  }
}
```

> **注意**：Dart 侧无 Swagger 代码生成器，因此 `RiskRecord.fromJson` 等模型需与后端
> `internal/dto/response/risk.go` 的 JSON tag **逐字段对齐**；字段名或类型变更时，
> 必须同步更新 Dart 模型，否则会出现运行时解析异常。

## 九、技术要点

| 要点 | 说明 |
|:---|:---|
| **认证** | JWT HS256，claims 携带 `user_id`/`username`/`role_code`/`dept_id`/`data_perm`/`company_id`/`cross_dept_ids` |
| **设备上报鉴权** | `X-Api-Key` 头，SHA256 后匹配 `ac_api_key.key_hash`；该分组**不经过 Casbin** |
| **权限** | Casbin RBAC，`p` 策略由「角色 → 菜单 → 菜单 API」推导；matcher 同时校验路径（`keyMatch2`）与方法（`r.act == p.act`） |
| **角色继承** | `g`（用户→角色）、`g2`（部门→角色）、`g3`（岗位→角色）三链取并集 |
| **数据权限** | `all` / `cross_dept` / `dept` / `personal` 四级，按 `dept_id` + `created_by` 施加行级过滤 |
| **策略一致性** | `casbin.StartAutoReload(5m)` 定时 `LoadPolicy()`，保证多副本部署下策略最终一致 |
| **分页** | 后端统一 `page` / `page_size`（默认 1 / 20），返回类型化 `RPageXxx`；前端读 `res.data.items` |
| **搜索** | 后端统一 `keyword` 模糊搜索，前端 `SearchBar` 组件 |
| **关联名称** | 列表涉及多表关联时通过 GORM `Preload` 带出名称字段，不裸传 ID |
| **树形结构** | 菜单/部门返回嵌套结构（`RMenuList` / `RDeptTree`），前端用 antd `Tree` 渲染 |
| **弹窗** | 新建/编辑用 antd `Modal` 表单，删除用 `Popconfirm` 二次确认 |
| **E2E 定位** | Modal 必须带 `e2e-xxx-modal` className，**禁止**使用通用 `.ant-modal` 选择器 |
| **响应格式** | 统一 `{code, message, data}`；`Success`/`BadRequest`/`Unauthorized`/`Forbidden` 辅助函数 |
| **软删除** | 全部模型嵌入 `BaseModel`，`DeletedAt` 软删除；审计字段由 GORM 钩子从 Context 自动填充 |
| **迁移策略** | 初次建表走 DDL 脚本；增量由 `AutoMigrate` 一次性 fail-fast 执行 |
| **日志** | zap + lumberjack，支持 `json` / `console` 两种格式，生产走 stdout → Loki |
| **API生成** | swagger2-doc-parser 自动生成前端 Controller 与类型，**不得手动编写** |
| **双入口** | 管理后台 base `/admin/`、官网 base `/`，同工程两次构建，**产物不可互换** |

登录接口在两个路由组下各有一个，共用同一套校验逻辑但返回的菜单平台不同：

- `POST /web/auth/login`（Web 管理后台，返回 `menu.platform = 'web'` 的菜单树）
- `POST /app/auth/login`（APP 移动端，返回 `menu.platform = 'mobile'` 的菜单树）

响应载荷 `response.LoginData`：

```go
type LoginData struct {
	Token        string   `json:"token"`
	UserID       int64    `json:"user_id"`
	Name         string   `json:"name"`
	DeptID       *int64   `json:"dept_id"`
	DataPerm     string   `json:"data_perm"`
	CrossDeptIDs string   `json:"cross_dept_ids"`
	Permissions  []string `json:"permissions"`
}
```

### 10.4 认证与权限

```
┌──────────────────────────────────────────────────────────────────────────┐
│  1. JWT 签发   POST /web/auth/login → auth_service.Login()                │
│                pkg/auth/jwt.go 签发 HS256，claims 含 user_id/role_code/    │
│                dept_id/data_perm/company_id/cross_dept_ids                │
└───────────────────────────────┬──────────────────────────────────────────┘
                                ▼
│  2. Auth 中间件  middleware.AuthMiddleware.Handler()                      │
│                校验 Bearer → 写入 gin.Context（handler 可读）              │
│                同时写入 Go Context（GORM 钩子自动填充审计字段 + dept_id）  │
                                ▼
│  3. Casbin 校验  middleware.CasbinMiddleware(enforce)                     │
│                enforce(username, c.Request.URL.Path, c.Request.Method)    │
│                matcher: keyMatch2(r.obj, p.obj) && r.act == p.act         │
│                         && (g || g2 || g3)                                │
                                ▼
│  4. 数据权限     utils.NewDataScope(c).ApplyToQuery(q, "alias.dept_id")   │
│                all / cross_dept / dept / personal 四种模式行级过滤         │
└──────────────────────────────────────────────────────────────────────────┘
```

| 分组 | 中间件 | 端点数 | 适用 |
|:---|:---|:---:|:---|
| 公开 | 无 | 3 | `/web/auth/login`、`/app/auth/login`、`/health` |
| API Key | `ApiKeyAuth()` | 3 | `/web/risks/report`、`/web/alarms/report`、`/web/devices/:id/heartbeat` |
| 认证 | `AuthMiddleware` + `CasbinMiddleware` | 193 | 其余全部业务端点 |

### 10.5 API 调用示例

```bash
# ── 1. 登录获取 token ──
curl -X POST http://localhost:8080/web/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"<口令>"}'
# → {"code":200,"data":{"token":"eyJ...","user_id":1,"data_perm":"all",...}}

# ── 2. 带 token 调用管理端接口 ──
curl -X GET 'http://localhost:8080/web/devices?page=1&page_size=20' \
  -H 'Authorization: Bearer eyJ...'
# → {"code":200,"data":{"items":[...],"total":520,"page":1,"page_size":20}}

# ── 3. 设备上报风险（ApiKey 认证，无用户会话）──
curl -X POST http://localhost:8080/web/risks/report \
  -H 'Content-Type: application/json' \
  -H 'X-Api-Key: <设备 API Key>' \
  -d '{
        "device_code": "AC-0001",
        "risk_type_code": "NO_HELMET",
        "image_url": "https://api.ai-camera.com/uploads/risks/xxx.jpg",
        "detect_score": 0.93,
        "occurred_dt": "2026-09-21T10:30:00+08:00"
      }'

# ── 4. 设备心跳上报（ApiKey 认证）──
curl -X POST http://localhost:8080/web/devices/1/heartbeat \
  -H 'Content-Type: application/json' \
  -H 'X-Api-Key: <设备 API Key>' \
  -d '{"battery":86,"voltage":"12.4V","storage_free":8192}'

# ── 5. APP 移动端登录与取待办 ──
curl -X POST http://localhost:8080/app/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"safety01","password":"<口令>"}'

curl -X GET http://localhost:8080/app/todos \
  -H 'Authorization: Bearer eyJ...'
```
