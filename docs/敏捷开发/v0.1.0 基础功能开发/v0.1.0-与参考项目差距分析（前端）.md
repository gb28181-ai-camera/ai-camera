# v0.1.0 与参考项目（boticz-mes）差距分析 —— 前端

> 审计日期: 2026-09-21
> 审计范围: `ai-camera/frontend`（React 管理后台 + 官网 + Electron）、`ai-camera/app`（Flutter 移动端）
> 参考基线: `boticz-mes/frontend`、`boticz-mes/frontend_app`
>
> **审计期间 `ai-camera/app` 正处于并发修改中**（`lib/constants/Screen.dart`、`lib/layout/Gaps.dart`、`lib/theme/app_spacing.dart`、`lib/theme/app_text.dart` 在审计过程中被改写）。凡涉及这些文件的结论均标注了"测量时刻"，并给出当前状态。

## 1. 结论摘要（Web）

**没有"跑不起来"级别的问题。`npx tsc --noEmit` 退出码 0，构建链路完整、类型安全。** 但存在 1 个"用户无法操作"级别的缺陷：

| 级别 | 问题 | 事实依据 |
|:---|:---|:---|
| **P0 用户无法操作** | Electron 主窗口 `frame: false`，但**全仓库没有任何 `ipcMain` 处理器**，preload 也未暴露 `window.*`，且不存在标题栏组件 → 桌面端**无法拖拽、最小化、最大化、关闭窗口** | `frontend/electron/main.ts:17` `frame: false`；`frontend/electron/preload.ts:7-14` 仅暴露 `platform`/`version`/`isDesktop`；`grep -rn ipcMain electron/ src/` 无匹配（exit 1）；`frontend/src/admin/components/` 与 `layouts/` 下无 TitleBar（boticz 对应 `src/components/TitleBar.tsx`，且 `src/layouts/MainLayout.tsx:312` 有 `{isDesktop && <TitleBar />}`） |

其余为能力缺口（不影响启动）：

- **打印能力为零**：ai-camera 全仓库 `grep -rniE "@media print\|window\.print\|OrderPrinter"` 无匹配；boticz 有 `OrderPrinter.tsx` + **12 个打印 CSS**（采购/销售/质量/生产/工资/设备标签）。
- **桌面端自动更新缺失**：ai-camera 无 `updater.ts`、无 `UpdateModal.tsx`、无 `updateStore.ts`，forge 配置无相关钩子。与 `ai-camera/docs/敏捷开发/v0.1.0 基础功能开发/待完成事项.md` 第 14 项自述一致。
- **对象存储直传缺失**：ai-camera 走服务端 multipart（`ImageUpload.tsx:77` `Common.uploadFile(formData)` → `POST /web/upload`）；boticz 走 COS STS 直传（`src/components/CosUpload.tsx` + `cos-js-sdk-v5`，`package.json:52`）。与待完成事项第 2 项（P0）一致。
- **前端单测差距显著**：**127 用例 vs 9 用例（14 倍）**。

**ai-camera Web 反超项**：双入口构建（admin + website）组织更干净、Docker/nginx 更完善（gzip + 强缓存 + alias）、`authStore` 更健壮（见 §5）。

## 2. 结论摘要（Flutter）

**存在 1 个"跑不起来"级别的问题，且 `app/` 未纳入版本控制：**

| 级别 | 问题 | 事实依据 |
|:---|:---|:---|
| **P0 跑不起来** | **`app/` 下六个平台目录全部缺失**（`android`/`ios`/`web`/`linux`/`macos`/`windows`），仅存 `lib/`、`test/`、`build/`。**无法对任何平台编译或运行**，只有 `flutter test` / `flutter analyze` 可用 | 逐目录判定：六个平台目录均 MISSING；`app/.metadata` 中记录了 `root`/`android`/`ios` 的 `create_revision`，说明 `flutter create` 曾执行、平台目录后被删除；已在临时副本中实测：`flutter build web` → `This project is not configured for the web. To configure this project for the web, run flutter create . --platforms web` |
| **P0 全仓库未纳入版本控制** | **`ai-camera` 仓库没有任何提交**，`master` 分支为空，`backend/`、`frontend/`、`app/`、`docs/` **全部未跟踪**（`app/` 并非特例） | `git log` → `fatal: your current branch 'master' does not have any commits yet`；`git rev-list --count HEAD` → 报错；`git ls-files` → 空；`git status --short` → `?? app/ ?? backend/ ?? docs/ ?? frontend/`（未被 ignore，仅未 add） |

> 对照：boticz `frontend_app/` 六个平台目录 + `test/` + `integration_test/` + `patrol_test/` + `test_driver/` 齐备。

**关于「设计稿缩放体系」的核实结论（本项前提需修正）**：

1. 任务书称"ai-camera 没有 `Screen.dart`"——**不成立**。`ai-camera/app/lib/constants/Screen.dart` 存在（171 行），且 `sizeByDesign` 语义与 boticz 一致（`designWidth=414`、按屏幕短边等比）。
2. 但在**审计开始时**它是**死代码**：`grep -rn "import.*Screen.dart" lib/` **零匹配**，`sizeByDesign` 仅出现在自身定义与文档注释中（4 处全在本文件内）。真实缩放体系确实缺失。
3. 任务书称 ai-camera 用"`AppStore` 门面 + `ChangeNotifier`"、`flutter_dva` 未使用——**不成立**。ai-camera `pubspec.yaml:19` 声明 `flutter_dva: ^1.0.9`，`main.dart:2` 导入，`lib/models/auth_model.dart` 继承 `DvaState`，`lib/models/index.dart:17` 的 `AppStore` 是 flutter_dva `Store` 之上的**安全取值门面**，不是替代品。**此项不构成能力缺口。**
4. **const 上下文冲突是真实存在的，且已实测发生**：迁移期间 `flutter analyze` 报出 **167 个编译错误**（132 `invalid_constant` + 33 `const_with_non_constant_argument` + 2 `non_constant_default_value`）。详见 §4 第 1 项。

**其余差距**：组件库深度（表单/校验体系缺失）、测试（单元 4 文件 vs 19、无 integration_test、无 Patrol E2E）、无打印/导出。

**ai-camera Flutter 反超项**：网络层明显更强（超时三件套 + DioException 中文映射 + 401 去重 + 不抛异常契约），`main.dart` 的 dva 装配更严谨（见 §5）。
