## 一、测试概述

### 1.1 测试目标

保障 AI Camera 智能监控平台 **11 个业务模块、38 张数据库表、209 个 API 端点** 的业务逻辑
正确性与数据一致性，覆盖从单元到端到端的五个测试层次。

本项目的测试有三个区别于普通 Web 系统的关注点，测试设计必须覆盖：

| 关注点 | 说明 | 测试手段 |
|:---|:---|:---|
| **鉴权链路完整性** | 四级权限叠加（JWT → Auth → Casbin → 数据权限）任一层失效都会导致越权 | Casbin matcher 单元测试 + 接口测试的越权用例 |
| **设备上报链路的幂等性与健壮性** | 设备侧网络抖动会重试，ApiKey 可能失效，心跳可能延迟 | 集成测试（重复上报/无效 Key/乱序心跳） |
| **风险处理闭环的状态机** | `pending → handled` 有两条分支（复核「否」直接归档 / 复核「是」再处理），状态与 `read` 字段联动 | 单元测试逐字段断言 + 集成测试全链路 |

### 1.2 测试范围

| 维度 | 范围 |
|:---|:---|
| **模块** | 系统管理 / 基础信息 / 资源管理 / 风险监控 / 设备监控 / 设备告警 / 实时监控 / 巡检中心 / 统计分析 / 首页与告警设置 / 移动端 |
| **后端代码** | 25 个 Service、23 个 Repository、25 个 Handler、209 个 API 端点、3 个中间件、6 个 pkg 工具包 |
| **前端** | 管理后台 39 个页面、官网 9 个组件、移动端 9 个页面 |
| **表** | 38 张 `ac_` 业务表 + `casbin_rule` 策略表 |
| **集成点** | 个推推送、腾讯云短信、对象存储（文件上传） |
| **不测试范围** | 设备固件内部逻辑、AI 推理算法本身、视频流编解码（由设备端承担） |

环境隔离的关键约束：

| 约束 | 说明 |
|:---|:---|
| **禁止跨库操作** | 测试**必须**使用 `ai_camera_test`，**禁止**操作 `ai_camera_dev`（开发库） |
| **端口错开** | 测试服务固定 8081，与开发服务 8080 错开，允许同时运行 |
| **启动前停服** | 启动测试服务前必须停止本地开发服务，避免端口冲突 |
| **测试库先清空** | 跑单测前必须执行 `resetdb`，避免与 seed 数据冲突（事务回滚无法清理序列与唯一索引残留） |
| **MCP 只读 dev** | `postgres_ai_camera_dev` 仅供查阅表结构，不用于测试执行 |

### 3.2 数据库配置

```bash
# ── 后端测试环境变量（所有后端测试命令都需要）──
export TEST_DB_HOST=192.168.1.227
export TEST_DB_PORT=5432
export TEST_DB_USER=boticz
export TEST_DB_PASSWORD='<测试库密码>'
export TEST_DB_NAME=ai_camera_test

# ── 测试服务启动（冒烟测试用，端口 8081）──
export CONFIG_PATH="config/config-test.yaml"
cd backend && go run ./cmd/server/main.go

# ── MCP Server（查询测试库表结构）──
# postgres_ai_camera_test  →  ai_camera_test
```

测试数据隔离方式：**每个测试用例在独立事务中执行，完成后自动回滚**。

```go
testutil.WithTx(t, func(ctx context.Context, db *gorm.DB) {
    // 测试逻辑：直接使用 db（事务作用域）
    //   - 用例内的所有写入都在事务中
    //   - 函数返回后自动 ROLLBACK，不污染数据库
})
```

> **注意**：事务回滚**不能**清理自增序列与唯一索引残留 —— 若某个用例依赖
> `ac_device.device_code` 全局唯一，同一进程内重复执行会出现「已存在」冲突。因此
> **每次完整测试前仍须执行 `resetdb`**，`WithTx` 只保证用例之间的数据隔离。

## 四、测试层次详情

### 4.1 单元测试 (Unit Testing)

> **定位**：代码级测试，聚焦单个 Service 方法的**字段写入**与状态流转验证
> **执行频率**：每次代码提交（CI `backend:unit-test`）
> **运行时间**：毫秒级/用例
> **对标**：Service 方法覆盖率；**字段验证率**（要求验证绝大多数字段的更新）
> **工具**：`backend/tests/<domain>/` + `testutil.WithTx(t, fn)`

#### 测试重点（本项目特有）

| 重点 | 说明 | 断言要点 |
|:---|:---|:---|
| **字段级断言** | 防止「接口返回成功但字段没存进去」 | 创建/更新后重新查询，逐字段比对（含指针字段的 nil / 非 nil） |
| **风险处理状态机** | 两条分支联动 `status` 与 `read` | 复核「否」→ `status=handled` 且 `read=true`；复核「是」→ `read=true` 且 `status` 仍为 `pending` |
| **Casbin matcher 语义** | 接口与方法必须参与判定 | 构造「有角色但未授权该接口」的用户，断言 `Enforce` 返回 `false` |
| **数据权限四模式** | `all`/`cross_dept`/`dept`/`personal` 的过滤结果 | 同一份数据在四种 `data_perm` 下的可见条数 |
| **冗余字段一致性** | 风险/告警/换卡记录都冗余了设备编号、区域、位置 | 写入时冗余字段必须与主表一致 |
| **软删除** | 全部模型 `DeletedAt` 软删除 | 删除后默认查询不可见，`Unscoped` 可查 |

#### 事务隔离约束

```go
// backend/tests/risk/risk_service_test.go（示例结构）
func TestRiskHandle(t *testing.T) {
	testutil.WithTx(t, func(ctx context.Context, db *gorm.DB) {
		// 1. 构造前置数据（设备 + 风险类型 + 风险记录）
		// 2. 调用 RiskService.Handle(ctx, id, req, "safety01")
		// 3. 重新查询 ac_risk_record，逐字段断言
		//    - status == "handled"
		//    - handler == "safety01"
		//    - handled_dt != nil
		//    - handle_result / handle_image 与入参一致
	})
}
```

### 4.2 集成测试 (Integration Testing)

> **定位**：跨模块业务链路验证，Service → Repository → 真实数据库的端到端数据流
> **执行频率**：每次代码提交
> **运行时间**：秒级/链路
> **对标**：核心业务链路覆盖率
> **工具**：`testutil.WithTx` + 多 Service 协同调用

#### 核心链路清单

| 序号 | 链路 | 涉及模块 | 关键断言 |
|:---:|:---|:---|:---|
| 1 | 风险上报 → 复核 → 处理闭环 | 资源管理 → 风险监控 | 状态从 `pending` → `handled`，`handler`/`handled_dt`/`handle_result` 全部落库 |
| 2 | 风险复核「否」直接归档 | 风险监控 | `status=handled` 且 `read=true`，无 `handler` 字段 |
| 3 | 设备心跳 → 在线状态 → 历史采样 | 资源管理 → 设备监控 | `ac_device` 快照更新 + `ac_device_history` 新增一条采样 |
| 4 | 换卡 → 设备更新 → 换卡记录 | 资源管理 | `ac_device.iot_card_id` 更新 + `ac_iot_card_replace_log` 记录新旧卡号 |
| 5 | 升级下发 → 计划 → 记录 → 取消 | 升级管理 | 现在升级直出记录；定时升级出计划；取消后计划状态变更 |
| 6 | 巡检任务 → App 完成 → 巡检记录 | 巡检中心 → 移动端 | 任务 `finished` + `ac_inspect_record` 一条已处理记录 |
| 7 | 角色授权 → Casbin 策略 → 越权校验 | 系统管理 | `AssignMenus` 后 `syncCasbinForRole` 生效，`Enforce` 结果正确 |
| 8 | 角色授权 → 菜单树过滤 | 系统管理 | 用户登录返回的菜单树仅含已授权项（含祖先目录） |
| 9 | 数据权限四模式可见性 | 全平台 | 同一条风险在四种 `data_perm` 下的列表可见性 |
| 10 | 告警上报 → 通知策略 → 站内通知 | 设备告警 → 告警设置 | `ac_alarm_record` + `ac_notification` 同时生成 |
| 11 | 上传文件 → URL 落库 → 风险关联 | 上传 → 风险监控 | `image_url` 为完整可访问 URL |

> **注意**：链路 7/8 是本项目集成测试的**最高优先级** —— Casbin 策略推导（角色 → 菜单 → 菜单 API）
> 与菜单树过滤是一套联动逻辑，任何一侧的改动都可能破坏另一侧，且问题表现是「用户看不到菜单」
> 或「用户能看到不该看的接口」，都属于线上高危问题。

✅ 详细测试用例清单请参考：`docs/测试文档/测试规范/02-集成测试.md`

### 4.3 接口测试 (API Testing)

> **定位**：Handler 层参数校验、中间件链路、响应结构与越权防护
> **执行频率**：每次代码提交 + 发版前全量
> **运行时间**：秒级/端点组
> **对标**：209 个端点的用例覆盖率
> **工具**：`httptest` + Gin Engine（或真实服务 + curl 脚本）

#### 必测项（每个端点）

| 检查项 | 说明 |
|:---|:---|
| **无 token** | 期望 401「未提供认证Token」 |
| **token 格式错误** | 期望 401「认证格式错误」（非 `Bearer xxx` 形式） |
| **token 无效/过期** | 期望 401「无效的Token」 |
| **越权访问** | 有 token 但角色未授权该接口 → 期望 403「权限不足」 |
| **参数缺失/非法** | 期望 400，且 message 明确 |
| **不存在的 ID** | 期望 404 或明确的业务错误 |
| **成功响应结构** | `{code:200, data:...}`；分页端点必须返回 `{items, total, page, page_size}` |
| **响应类型一致性** | 分页端点返回 `RPageXxx`，简单列表返回 `RXxxList`，**不得混用** |
| **关联名称字段** | 列表响应中涉及关联表的字段必须是**名称**（`device.name`、`region.name`、`risk_type.name`），不能只有 ID |
| **软删除不可见** | 删除后再查询列表，被删记录不出现 |

#### 特殊端点组

| 端点组 | 特殊检查 |
|:---|:---|
| `/web/risks/report`、`/web/alarms/report`、`/web/devices/:id/heartbeat` | ① 无 `X-Api-Key` 期望 401「缺少API Key」② 无效 Key 期望 401「无效的API Key」③ 有效 Key 成功且更新 `ac_api_key.last_used_dt` ④ **不经过 Casbin**（即使无用户会话也应放行） |
| `/web/auth/login`、`/app/auth/login` | ① 错误口令 401 ② 停用用户（`active=false`）拒绝 ③ 成功返回 `LoginData` 完整字段 ④ Web 与 App 返回的菜单 platform 不同 |
| `/web/devices/modes` 等静态子路径 | **路由优先级**：`/web/devices/modes` 不能被 `/web/devices/:id` 吞掉 |
| `/web/stats/screen`、`/web/stats/dashboard` | 聚合接口：空库时不得报错，返回零值结构 |
| `/web/upload`、`/web/upload/audio` | ① 文件类型限制 ② 超大文件拒绝 ③ 响应返回可访问 URL |
| `/health` | 无鉴权、返回 200（K8s readiness/liveness 依赖） |

✅ 详细测试用例清单请参考：`docs/测试文档/测试规范/03-接口测试.md`

### 4.4 回归测试 (Regression Testing)

> **定位**：发版前的整体健康检查，确认新版本未破坏既有功能

> **运行时间**：10~20 分钟
> **对标**：核心链路 100% 通过 + 数据完备性检查
> **工具**：SQL 校验脚本 + 接口抽样 + 冒烟测试

#### 回归清单

| 分类 | 检查项 | 判定标准 |
|:---|:---|:---|

### 4.5 端到端测试 (E2E Testing)

> **定位**：真实浏览器 + 真实后端 + 真实数据库的完整用户操作模拟
> **执行频率**：每日构建 + 发版前全量
> **运行时间**：分钟级
> **对标**：核心用户旅程覆盖率
> **工具**：Playwright（Web 管理后台）+ Flutter Test / patrol（移动端）

#### 执行规范

| 规范 | 说明 |
|:---|:---|
| **串行执行** | 冒烟测试固定 `--workers=1`，spec 文件按**文件名字母序**运行 |
| **文件编号** | 功能测试编号 `01a` ~ `10f`；**全页面覆盖类收尾测试固定 `99-` 前缀**，保证排在最后 |
| **Modal 定位** | **禁止**使用通用 `.ant-modal`、`.ant-modal-footer`、`.ant-modal').last()`；必须使用 `e2e-xxx-modal` class |
| **新增 Modal** | 任何新建的 antd `<Modal>` 必须添加 `className="e2e-xxx-modal"` |
| **SelectorModal** | `<SelectorModal className="e2e-xxx">` 会把 class 应用到 Modal（`.e2e-xxx`）与触发按钮（`.e2e-xxx-btn`） |
| **截图留存** | 失败用例截图输出到 `frontend/e2e/screenshots/`（已 gitignore） |

> **注意**：禁止使用通用 `.ant-modal` 的原因 —— 存在嵌套弹窗场景（如处理风险 Modal 内
> 打开图片预览、表单 Modal 内打开设备选择 Modal）时，通用选择器会匹配到**错误的那一层
> 弹窗**，导致测试偶发失败且难以定位。

#### 冒烟测试执行流程

```bash
# 1. 清空测试数据库

# 2. 初始化测试基础数据

# 5. 串行执行冒烟测试

# 6. 关闭前后端服务
```

## 八、后端单元测试命令速查

```bash
# ── 前置：清空测试库（每次完整测试前必做，避免与 seed 数据冲突）──
cd backend && go run ./tests/testutil/resetdb/main.go

# ── 初始化测试基础数据（冒烟测试前必做）──
cd backend && go run ./tests/testutil/initdb/main.go

# ── 全量后端单测（必须设置环境变量指向测试库）──
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/... -count=1 -timeout 180s

# ── 指定模块（-v 输出详细日志）──
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/system/... -v
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/risk/... -v
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/device/... -v

# ── 单个用例（-run 正则匹配）──
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/risk/ -run TestRiskHandle -v

# ── 覆盖率报告（生成 HTML）──
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/... -coverprofile=coverage.out
cd backend && go tool cover -html=coverage.out -o coverage.html

# ── 静态检查（CI 门槛）──
cd backend && go vet ./...
cd backend && gofmt -l .            # 输出非空即失败

# ── 前端单测（MSW mock，无需启动后端）──
cd frontend && npx vitest run
cd frontend && npx vitest           # watch 模式

# ── E2E 测试（需后端运行）──
cd frontend && npx playwright test
cd frontend && npx playwright test --ui                # 交互式调试
cd frontend && npx playwright test e2e/smoke --workers=1   # 冒烟串行
cd frontend && npx playwright show-report              # 查看报告

# ── 移动端测试 ──
cd app && flutter test
cd app && flutter analyze           # 要求 0 error 0 warning
```
