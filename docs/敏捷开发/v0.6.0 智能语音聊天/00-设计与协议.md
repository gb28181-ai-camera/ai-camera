# v0.6.0 智能语音聊天（Pipecat + WebSocket）

> 日期：2026-10-25
> 决策：App/Web + ESP32 双客户端；半双工 + 服务端 VAD；设备端唤醒；服务端+设备端 MCP；短期+长期记忆。

## 1. 架构

```text
ESP32/小智设备 ──wss──┐
Flutter App     ──wss──┼──> Go Backend /web|app|device/voice/ws ──ws──> Pipecat /ws/voice
Web 管理端      ──wss──┘        （ticket/设备凭据、限流、上下文签名）      （VAD/STT/LLM/TTS/MCP/记忆）
GB28181 摄像头 ──RTP──> ZLM ──RTP──> Pipecat RTP 桥 /session/start（保持不变）
```

- Pipecat 仍只在内网 `expose: 8090`，不直接暴露公网。
- Go 网关负责鉴权、把用户/设备上下文签名后注入 Pipecat。
- 同一个 Pipecat 进程同时支持 RTP（GB28181）与 WebSocket（AIChat/App/Web）。

## 2. 鉴权

| 客户端 | 流程 |
|:--|:--|
| Web 管理端 | 登录 JWT → `POST /web/voice/ws-ticket` → `ticket`（60s，一次性）→ `ws://host/web/voice/ws?ticket=...` |
| Flutter App | 登录 JWT → `POST /app/voice/ws-ticket` → `ws://host/app/voice/ws?ticket=...` |
| AIChat 设备 | 设备用 `ac_iot_product_service` 的 username/password 做 HTTP Basic；`ws://host/device/voice/ws`；服务端校验产品绑定 `aichat` 组且服务协议含 WebSocket |
| Go → Pipecat | `Authorization: Bearer <PIPECAT_TOKEN>` + `X-Voice-Context: <base64url JSON>`（session_id/user_id/device_id/dept_id/scopes/exp） |

`X-Voice-Context` 使用 `PIPECAT_CONTEXT_SECRET` HMAC-SHA256 签名；Pipecat 只信任签名上下文。

## 3. WebSocket 协议（小智兼容子集 + 扩展）

### 3.1 消息

客户端首帧：

```json
{"type":"hello","version":1,"transport":"websocket",
 "features":{"mcp":true,"aec":false,"wake_word":"device"},
 "audio_params":{"format":"pcm16","sample_rate":16000,"channels":1,"frame_duration":20},
 "client":{"kind":"app","client_id":"uuid","device_id":"..."}}
```

`format`：`pcm16`（App/Web）或 `opus`（ESP32）；`sample_rate` 上行 16000，下行由服务端 hello 返回 24000。

服务端 hello：

```json
{"type":"hello","session_id":"s1","transport":"websocket",
 "audio_params":{"format":"pcm16","sample_rate":24000,"channels":1,"frame_duration":20},
 "capabilities":{"mcp":true,"memory":true,"barge_in":false}}
```

| 方向 | type | 关键字段 |
|:--|:--|:--|
| C→S | `listen` | `state=detect\|start\|stop`、`mode=auto\|manual`、`text`（唤醒词） |
| C→S | `abort` | `reason` |
| C→S | `mcp` | `payload`（JSON-RPC 2.0） |
| C→S | `ping` | `ts` |
| S→C | `stt` | `text,is_final,confidence,turn_id` |
| S→C | `llm` | `text,emotion` |
| S→C | `tts` | `state=start\|sentence_start\|stop`、`text,turn_id` |
| S→C | `mcp` | `payload`（JSON-RPC 2.0） |
| S→C | `tool` | `state=calling\|result\|error`、`name,display` |
| S→C | `error` | `code,message,retryable` |
| S→C | `wake` | `state=detected`、`text,confidence`（设备端唤醒回执；服务端不跑 KWS） |

二进制音频：PCM16 `s16le` 单声道；Opus 使用小智 v1 裸帧（首期）。App/Web 用 PCM16，避免 Dart/浏览器 Opus 依赖。

### 3.2 交互

- 设备端唤醒命中后发 `listen/detect`；服务端立即下发预合成短句（“我在”）作为快速应答，再启动 STT/LLM。
- 半双工：TTS `start` 到 `stop` 期间服务端丢弃上行，并保留 300ms 尾巴；客户端在 `tts start` 时暂停麦克风。
- `listen/mode=auto`：服务端 Silero VAD 断句；`manual`：客户端 `listen/stop` 结束。
- `abort`：立即停止当前 LLM/TTS，发 `tts stop`，清空输出队列。

## 4. 服务端 MCP（Go）

Pipecat 通过内部 HTTP JSON-RPC 调用 Go：

```text
POST /internal/mcp
Authorization: Bearer <INTERNAL_MCP_TOKEN>
Content-Type: application/json
```

支持方法：

- `initialize` → `{protocolVersion:"2024-11-05", capabilities:{tools:{}}, serverInfo:{name:"ai-camera",version:"v0.6.0"}}`
- `tools/list` → `{tools:[{name,description,inputSchema}]}`
- `tools/call` → `{content:[{type:"text",text:"..."}], isError?:false}`

首期工具：

| name | 说明 | 风险 |
|:--|:--|:--|
| `device.list` | 按关键字/服务组查询设备 | 低 |
| `device.status` | 查询设备在线/电量/最后心跳 | 低 |
| `alarm.query` | 查询近期告警 | 低 |
| `risk.query` | 查询近期风险 | 低 |
| `ptz.control` | 云台方向/预置位（需要设备支持） | 中，需确认 |
| `notify.send` | 发送站内通知 | 中，需确认 |

工具实现必须从签名上下文注入 `user_id/dept_id`，禁止 LLM 传入；写操作按 `risk_level` 要求确认。

## 5. 设备端 MCP

小智设备在 `hello.features.mcp=true` 后，Pipecat 发：

```json
{"type":"mcp","payload":{"jsonrpc":"2.0","id":1,"method":"initialize","params":{...}}}
```

流程：`initialize` → `tools/list`（分页 cursor）→ `tools/call`。Pipecat 把设备工具映射为 LLM FunctionSchema；工具名含 `.` 时转成 `device_<...>`，调用时映射回原始 `wire_name`。设备断线/超时不阻塞音频链路。

## 6. 记忆

### 6.1 短期

- Pipecat `LLMContext` + `LLMContextSummarizer`；会话内保留最近 N 轮 + 摘要。
- 会话结束写 `ac_voice_session_summary`；默认 TTL 30 天。

### 6.2 长期

- 表 `ac_voice_memory`（pgvector，默认 BGE-M3 1024 维）。
- 写入：每轮助手回复后异步抽取 0-3 条事实/偏好；显式“记住…”优先；去重（content_hash + 余弦 >0.90）。
- 读取：会话开始 top-k（5-8）；按 owner（user/device/dept/global）+ 相似度 + 重要度 + 新近度。
- Embedding：`VOICE_EMBEDDING_ENDPOINT`（OpenAI-compatible `/v1/embeddings`）；未配置时只按时间/关键词检索并标记 `embedding_status=failed`。
- 用户可查询/删除/导出记忆；默认保留 180 天；不存原始音频。

## 7. 数据库

新增表（DDL 见后续 `15-语音Agent.sql`）：

- `ac_voice_agent`：Agent 人格/唤醒词/greeting/voice/模型。
- `ac_voice_mcp_server`、`ac_voice_mcp_tool`、`ac_voice_tool_permission`、`ac_voice_mcp_call_log`。
- `ac_voice_memory`、`ac_voice_session_summary`、`ac_voice_turn`（可选逐字稿）。
- `ac_voice_session` 扩展 `transport/client_id/input_format/output_format/last_seen_at/turn_count/close_code`。

## 9. 分期

| 阶段 | 内容 | 验收 |
|:--|:--|:--|
| P1 | Pipecat `/ws/voice` + PCM16 + hello/listen/tts + 半双工 + 短 ack；Go ticket/WS 网关；Flutter App 按住说话 | App 10 轮对话；首音频 p95 <2s；GB RTP 不回归 |
| P2 | Opus + 小智协议兼容；设备端唤醒 detect；abort | 模拟 ESP32 完成 hello→STT→TTS；唤醒 ack <300ms |
| P3 | 服务端 MCP + 设备端 MCP bridge + 权限/审计 | 5 只读 + 2 写工具；跨用户调用被拒；100% 审计 |
| P4 | 短期摘要 + pgvector 长期记忆 + 删除/导出 | 跨会话回忆 3/5；隔离 0 泄漏；删除生效 |
| P5 | Web 配置页/记忆管理、观测、并发与成本限制 | 配置可下发；100 并发；错误率 <1% |

本期代码按 P1–P4 实现；P5 的并发硬化按部署环境验收。
