# v0.6.0 智能语音聊天实现说明

> 日期：2026-10-25
> 协议：[00-设计与协议.md](./00-设计与协议.md)

## 1. 已实现

### Pipecat（deploy/pipecat）

- 新增 `WS /ws/voice`，与现有 GB28181 RTP `/session/start` 并存。
- 小智兼容子集：`hello / listen(detect|start|stop) / abort / stt / llm / tts / mcp / tool / error / wake / ping / pong`。
- PCM16（App/Web）与 Opus（ESP32）协商；上行 16k、下行 24k。
- 半双工 gate：TTS 期间丢弃上行 + 300ms 尾巴；`abort` 打断。
- 快速应答：`fast_ack_text`（默认「我在」）文字立即下发，PCM 缓存后台预热。
- 服务端 MCP：HTTP JSON-RPC → Go `/internal/mcp`，工具映射为 FunctionSchema。
- 设备端 MCP：同一 WS 上 `type=mcp` JSON-RPC bridge，工具名 `device_*` 映射。
- 记忆：短上下文 + 摘要；会话开始注入长期记忆，结束写摘要。
- 鉴权：`PIPECAT_TOKEN` + `X-Voice-Context` HMAC-SHA256。

### Go 后端

- 8 张新表 + `ac_voice_session` 扩展；pgvector 1024 维 + HNSW。
- `POST /web/voice/ws-ticket`、`POST /app/voice/ws-ticket`；60s 一次性 ticket。
- WS 网关：`/web/voice/ws`、`/app/voice/ws`、`/device/voice/ws`，反向代理 Pipecat。
- 内部 MCP：`POST /internal/mcp`（6 个工具、权限、确认、审计）。
- 记忆：`/internal/voice/memory/{retrieve,write}`；Web 列表/删除/导出。
- 管理：`/web/voice/mcp/tools`、`/web/voice/mcp/logs`。
- 配置键：`ws_enabled`、`fast_ack_text`、`mcp_enabled`、`memory_*`、`embedding_*` 等。

### Flutter App

- `VoiceWsClient`：ticket、hello、listen、abort、stt/llm/tts、二进制 PCM16、重连。
- `VoiceAudioSession`：record 采集 16k PCM16、flutter_sound 边收边播 24k。
- `VoiceChatPage`：按住说话、半双工、字幕、MCP 工具提示、错误/重连。
- 入口：首页与国标实时播放页。

### Web 管理端

- `/voice/agent` 新页面：基础 / WebSocket / MCP / 记忆 / 观测。
- 连接测试：获取 ticket → 连 Go 网关 → 展示服务端 hello。
- MCP 工具编辑、调用日志、记忆列表/删除/CSV 导出。

## 3. 已知限制

1. ticket 一次性存储为进程内，多副本需 Redis。
2. WS 网关不解析 `hello`，`ac_voice_session.input_format/output_format/turn_count` 未自动填充。
3. 设备 Basic 是产品级凭据；未传 `device_code` 时上下文 `device_id=0`。
4. `ptz.control` 依赖内嵌 SIP 控制面；分进程部署时不可用。
5. 写工具的人类确认 UI 未做；当前由 LLM 在参数里传 `confirm=true`。
6. 长期记忆的逐轮事实抽取未做，当前只写会话摘要；embedding 未配置时降级为时间/关键词检索。
7. RTP 路径仍存在 Pipecat 1.13 aggregator/VAD 的既有不兼容，本次未改（WS 不受影响）。
8. 真实 ESP32/Opus、真机 AEC、100 并发压力测试未验证。
