## 核心测试要点

> 国标链路与其他模块最大的差异是：**平台只负责信令，媒体由 ZLM 与设备直连**。
> 因此测试必须分成三层：① Go 侧纯逻辑（协议编解码、鉴权、状态机）；
> ② 服务级集成（事务内的 CRUD、脱敏、字段落库）；③ 协议级联调（sipsvc ↔ gbsim ↔ ZLM）。
> 任何一层缺失，都会出现「单测全绿但真机黑屏」的情况。

### 1.3 关键用例明细

#### 1. 白名单 403

- **测试方法**：`TestLookupWhitelist`、`TestVerifyUsernameMismatch`
- **输入**：未建档的 20 位国标编码；已建档但 `gb_device_id` 为空；已软删除设备
- **预期**：`Lookup` 返回 `ErrUnknownDevice`；SIP 层回 **403 Forbidden** 并在 `ac_gb_sip_log`
  写入 `result=failed`、`reason` 含拒绝原因；**绝不能**退化为按 `device_code` 匹配
- **覆盖文件**：`backend/internal/gb28181/auth/authenticator_test.go`

#### 2. Digest 401 → 200

- **测试方法**：`TestDigestResponseRFC2617Vector`、`TestVerifyCorrect`、`TestVerifyWithoutQop`、
  `TestVerifyUppercaseNC`、`TestVerifyExpiredNonce`
- **输入**：RFC 2617 标准向量；`qop=""`；客户端回传大写 `nc`
- **预期**：摘要值与标准向量一致；`qop=auth` 与无 qop 两种算式都通过；
  `nc` 原样参与计算（统一格式化会导致「密码正确却一直 401」）；过期 nonce 被拒绝
- **覆盖文件**：`backend/internal/gb28181/auth/authenticator_test.go`

#### 3. GB2312 目录

- **测试方法**：`TestMarshalDecodeGB2312`、`TestDecodeCharsetMismatch`、
  `TestDecodeNoDeclarationGBBytesMustFail`、`TestCatalogRoundTripGB2312`
- **输入**：中文通道名（如「东门球机通道1」）按 GB2312 编码；声明 `GB2312`；错误声明
- **预期**：解码后中文无损；声明与实际编码不一致时报错而不是静默乱码；
  无 XML 声明且含 GB 字节时**必须失败**（避免把乱码写库）
- **覆盖文件**：`backend/internal/gb28181/protocol/manscdp/codec_test.go`、
  `backend/tools/gbsim/manscdp/codec_test.go`

#### 4. 目录多片重组

- **测试方法**：`TestCatalogFragments`、`TestCatalogReassembly`、
  `TestCatalogPreservesUserFields`、`TestDispatcherCatalogChunking`、`TestEmptyCatalog`
- **输入**：同一 SN 的 2+ 片目录；空目录；已设置 `region_id` / `group_id` 的通道
- **预期**：收齐后才落库；`channel_count` 等于 `SumNum`；空目录回一条 `SumNum=0`；
  用户字段不被覆盖；半份目录超时不落库
- **覆盖文件**：`backend/internal/gb28181/protocol/manscdp/codec_test.go`、
  `backend/internal/gb28181/device/manager_test.go`、`backend/tools/gbsim/main_test.go`

#### 5. 云台 MESSAGE

- **测试方法**：`TestBuildPtzCommand`、`TestBuildPtzCommandChecksum`、
  `TestMarshalPTZControlRawBytes`、`TestGotoPresetIDValidation`
- **输入**：八方向 + stop；速度 1–8；变焦 / 光圈 / 聚焦；预置位 1–255
- **预期**：PTZCmd 字节序、方向位、速度映射与校验和正确；预置位越界被拒绝；
  速度按 1–8 映射，不按 0–255 解释
- **覆盖文件**：`backend/tests/gb28181/play_service_test.go`、

#### 6. 回放 INFO

### 2.5 启动 gbsim

```bash
cd backend
go run ./tools/gbsim \
  --device-id 34020000001320000001 \
  --device-name 东门球机 \
  --sip-server 127.0.0.1:5060 \
  --sip-domain 3402000000 \
  --password 'SimPass1234567890' \
  --channels 25 \
  --mode udp \
  --charset GB2312 \
  --stream-file testdata/sample.h264 \
  --fps 25 --loop --keepalive 30s \
  --verbose
```

参数含义以 `go run ./tools/gbsim --help` 的实际输出为准。关键项：

| 参数 | 作用 |
|:---|:---|
| `--device-id` | 20 位国标编码，必须与 `ac_device.gb_device_id` 一致 |
| `--sip-server` | 平台 SIP 地址；内嵌模式为 `127.0.0.1:5060` |
| `--sip-domain` | SIP 域 / Digest realm，必须与 `gb28181.sip.domain` 一致 |
| `--password` | 与 `ac_device.sip_password` 一致 |
| `--channels N` | 通道数；每条目录项约 460 字节、预算 700 字节，**N≥2 即触发多片** |
| `--charset` | `GB2312` / `UTF-8`，必须与 `ac_device.charset` 一致 |
| `--stream-file` | H.264 Annex-B 样本；不给则 INVITE 回 488 |
| `--ssrc-override` | 设备回一个与平台不同的 `y=`，验证平台 SSRC 校正路径 |
| `--verbose` | 打印 SIP / MANSCDP 报文级日志，排查 401 / 403 必开 |

### 2.7 负向用例

#### A. 白名单 403

```bash
cd backend
go run ./tools/gbsim \
  --device-id 34020000001320009999 \
  --sip-server 127.0.0.1:5060 \
  --sip-domain 3402000000 \
  --password 'whatever' \
  --channels 1 --verbose
```

预期：gbsim 报注册失败；平台侧 `ac_gb_sip_log` 出现该编码的 `result=failed`
（403 Forbidden），`ac_device` 不新增记录。

#### B. 密码错误 → 401 / rejected

把 gbsim 的 `--password` 改成错误值重启。预期：连续 401 后注册失败；
`ac_device.register_status='rejected'`，但 `status` 不会被强行改成 offline。

#### C. 目录发不出（UDP MTU）

现象：设备已注册，但通道一直不出现。排查：

1. gbsim 日志出现 `size of packet larger than MTU` → 说明单条 MESSAGE 超 MTU；
2. 确认 gbsim 的目录分片预算未被改大（`catalogByteBudget=700`）；
3. 或改用 TCP 信令（**模拟器本期只支持 UDP**，需要真机 / 后续批次）。

#### D. 能注册但黑屏

1. `--verbose` 确认 INVITE / 200 OK / ACK 是否完成；
2. 确认设备 200 OK 的 SDP `o=` 用户名是**设备国标编码**（不是通道编码 / 平台编码）——
   平台按 `o=` 取 ACK 目的地址，写错会「INVITE 成功但推流永不开始」；
3. 确认 SDP `c=` 与平台 `gb28181.media.public_ip` 是设备可达地址；
4. 确认 ZLM `10000/udp` 可达、媒体节点记录存在且 secret 一致。

### 2.8 播放 / 云台 / 回放的 HTTP 验证

```bash
# 登录取 token（seed 默认 admin / admin123）
TOKEN=$(curl -s -X POST http://localhost:8080/web/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | jq -r '.data.token')

# 取一个通道的主键（路由参数用数据库主键，不是国标编码）
CH=$(docker compose exec -T postgres psql -U aicamera -d ai_camera_test -Atc \
  "SELECT id FROM ac_gb_channel WHERE name LIKE '%通道1' ORDER BY id LIMIT 1")

# 开始播放（默认 webrtc）
curl -s -X POST "http://localhost:8080/web/gb/play/$CH" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"protocol":"webrtc"}' | jq

# 播放状态
curl -s "http://localhost:8080/web/gb/play/$CH/status" \
  -H "Authorization: Bearer $TOKEN" | jq

# 云台：向右，速度 5
curl -s -X POST "http://localhost:8080/web/gb/ptz/$CH" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"direction":"right","speed":5}' | jq

# 停止播放
curl -s -X POST "http://localhost:8080/web/gb/play/$CH/stop" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"stream_id":"<上一步返回的 stream_id>"}' | jq
```

预期：

- 播放返回 `app=rtp`、`stream` 为 8 位大写十六进制（`%08X(ssrc)`）、三条播放 URL；
- 5 秒内 ZLM 收到流（gbsim 打印发送字节数）；`status.ready=true`；
- 云台请求返回成功；gbsim `--verbose` 日志能看到入向 MESSAGE（模拟器当前只解析
  Catalog / DeviceInfo / DeviceStatus，PTZ 会打印「暂未实现」但**平台侧发送成功**）；
- 停止后 ZLM 侧流被清理。

> **模拟器能力边界**：gbsim 已实现 REGISTER / Keepalive / Catalog / DeviceInfo /
> DeviceStatus / INVITE 应答 / PS + RTP 推流；**未实现** PTZ 应答、RecordInfo 应答、
> TCP 信令、TCP-ACTIVE 媒体、AI 风险上报。回放控制（INFO）与云台应答需真机验证。

## 5. 已知未覆盖项（不得在验收中伪装为通过）
