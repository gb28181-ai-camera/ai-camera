# 认证与权限测试用例

> 版本: v0.1.0
> 最后更新: 2026-09-21

## 核心测试要点

> 认证与权限是本项目的**安全边界**：JWT 决定「你是谁」，Casbin 决定「你能访问哪些接口」，
> 数据权限决定「你能看到哪些行」。三者任一失效都会造成越权，属 🔴 P0 缺陷。

## AuthService

### 1. 登录成功
- **测试方法**: `TestAuthService_Login`
- **输入**: `username="admin"`、`password="123456"`（种子数据）
- **预期结果**: 返回 `*response.LoginData`，**并逐字段核对**：`token`（非空且可被 `ParseToken` 解出）、`user_id`（等于 admin 的 ID）、`name`（等于 `ac_user.name`）、`dept_id`（等于 `ac_user.dept_id`）、`data_perm`（等于该用户角色的 `data_permission`）、`cross_dept_ids`（等于角色 `cross_dept_ids`）、`permissions`（非空切片，含已授权菜单的 `permission_code`）
- **覆盖文件**: `backend/tests/auth/auth_service_test.go`

### 2. 登录失败 — 密码错误
- **测试方法**: `TestAuthService_Login_WrongPassword`
- **输入**: `username="admin"`、`password="wrong-password"`
- **预期结果**: 返回 `err != nil`；`LoginData` 为 `nil`；错误信息不包含「用户不存在」等可用于枚举用户名的字样
- **覆盖文件**: `backend/tests/auth/auth_service_test.go`

### 3. 登录失败 — 用户不存在
- **测试方法**: `TestAuthService_Login_UserNotFound`
- **输入**: `username="ghost_user"`、`password="123456"`
- **预期结果**: 返回 `err != nil`；错误信息与「密码错误」**完全一致**（防用户名枚举）
- **覆盖文件**: `backend/tests/auth/auth_service_test.go`

### 4. 登录失败 — 账号已禁用
- **测试方法**: `TestAuthService_Login_Disabled`
- **输入**: 预置 `active=false` 的用户，凭正确密码登录
- **预期结果**: 返回 `err != nil`；不签发 token
- **覆盖文件**: `backend/tests/auth/auth_service_test.go`

### 5. 登录成功更新最后登录时间
- **测试方法**: `TestAuthService_Login_UpdateLastLogin`
- **输入**: 预置 `last_login = nil` 的用户，执行登录
- **预期结果**: 登录成功后回读 `ac_user.last_login` **非空**且接近当前时间；`updated_by` 被刷新为登录用户名
- **覆盖文件**: `backend/tests/auth/auth_service_test.go`

### 6. 密码哈希存储
- **测试方法**: `TestAuthService_Login_PasswordHashed`
- **输入**: 创建用户时传明文密码
- **预期结果**: `ac_user.password_hash` **不等于**明文密码；以 `bcrypt.CompareHashAndPassword` 校验通过；`password_hash` 字段 JSON tag 为 `-`，不出现在任何响应中
- **覆盖文件**: `backend/tests/auth/auth_service_test.go`

### 7. 数据权限来源正确
- **测试方法**: `TestAuthService_Login_DataPerm`
- **输入**: 分别以 `all` / `cross_dept` / `dept` / `personal` 四种角色的用户登录
- **预期结果**: `LoginData.data_perm` 分别等于该角色 `ac_role.data_permission`；`cross_dept_ids` 与角色字段一致；无角色的用户 `data_perm` 退化为 `personal`
- **覆盖文件**: `backend/tests/auth/auth_service_test.go`

## ProfileService

### 1. 获取个人资料
- **测试方法**: `TestProfileService_Get`
- **输入**: `userID`
- **预期结果**: 返回 `*model.User`，**并逐字段核对**：`id`、`name`、`user_name`、`email`、`phone`、`avatar`、`dept_id`、`post_id`、`active`、`is_admin`、`remark`、`created_dt`；`Preload` 后 `Dept.Name` 与 `Post.Name` 非空
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

### 2. 更新个人资料
- **测试方法**: `TestProfileService_Update`
- **输入**: `UpdateProfileReq{Name:"张三", Email:"zs@x.com", Phone:"13800000001", Avatar:"/upload/a.png"}`
- **预期结果**: 更新成功，**并逐字段核对**：`name`、`email`、`phone`、`avatar` 均已更新为输入值；`updated_by` 等于当前登录名；`updated_dt` 已刷新；`user_name`、`password_hash`、`is_admin`、`active`、`dept_id`、`post_id` **未被改动**
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

### 3. 更新个人资料 — 提权防护
- **测试方法**: `TestProfileService_Update_PrivilegeEscalation`
- **输入**: `UpdateProfileReq` 中夹带 `IsAdmin=true`、`Active=false`、`DeptID=其他部门ID`
- **预期结果**: 回读 `ac_user`，`is_admin`、`active`、`dept_id` **保持原值不变**（DTO 未暴露该字段）
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

### 4. 修改密码
- **测试方法**: `TestProfileService_ChangePassword`
- **输入**: `ChangePasswordReq{OldPassword:"123456", NewPassword:"abc@2026"}`
- **预期结果**: 返回 nil；回读 `password_hash` 与旧值不同且 `bcrypt` 校验新密码通过、旧密码不通过；`updated_by`/`updated_dt` 刷新
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

### 5. 修改密码 — 旧密码错误
- **测试方法**: `TestProfileService_ChangePassword_WrongOld`
- **输入**: `OldPassword="wrong"`
- **预期结果**: 返回 `err != nil`；`password_hash` **未被修改**
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

### 6. 个人中心菜单树
- **测试方法**: `TestProfileService_Menus`
- **输入**: `username`（已授权菜单的用户）
- **预期结果**: 返回 `[]model.Menu`；仅包含该用户角色已授权的菜单；`type=button` 的节点携带非空 `permission_code`；父子关系经 `children` 正确嵌套；`active=false` 的菜单不返回
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

### 7. 列出 API Key
- **测试方法**: `TestProfileService_ListApiKeys`
- **输入**: `userID`
- **预期结果**: 返回该用户的 `[]model.ApiKey`；每条含 `name`、`key_prefix`、`last_used_dt`；响应中**不含** `key_hash`（JSON tag 为 `-`）；他人 Key 不出现
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

### 8. 生成 API Key
- **测试方法**: `TestProfileService_GenerateApiKey`
- **输入**: `userID`、`name="设备网关"`
- **预期结果**: 返回 `GenerateApiKeyResp`；**明文 Key 仅此一次返回**且非空；回读 `ac_api_key`，`user_id` 等于入参、`name` 正确、`key_prefix` 等于明文 Key 的前 8 位、`key_hash` 等于明文 Key 的 SHA256 且**不等于明文**、`active=true`、`last_used_dt` 为 nil
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

### 9. 删除 API Key
- **测试方法**: `TestProfileService_DeleteApiKey`
- **输入**: `userID` + 本人 `keyID`
- **预期结果**: 返回 nil；`ac_api_key.deleted_at` 非空（软删除）；`ListApiKeys` 不再返回该条
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

### 10. 删除他人 API Key — 越权拦截
- **测试方法**: `TestProfileService_DeleteApiKey_OtherUser`
- **输入**: `userID=用户B`、`keyID=用户A的Key`
- **预期结果**: 返回 `err != nil`；`ac_api_key` 中该条 `deleted_at` **仍为空**
- **覆盖文件**: `backend/tests/auth/profile_service_test.go`

## CasbinService

### 1. p 策略由角色→菜单→菜单API 推导
- **测试方法**: `TestRoleService_AssignMenus_SyncCasbin`
- **输入**: 角色 `role_x`、菜单 `menu_x`（绑定 `GET /web/basic/regions`）、`AssignMenus(role_x, [menu_x])`
- **预期结果**: `Enforce("用户登录名", "/web/basic/regions", "GET") == true`；`casbin_rule` 中新增 `p_type='p'`、`v0=role_x`、`v1='/web/basic/regions'`、`v2='GET'` 的行
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

### 2. 未授权接口拒绝
- **测试方法**: `TestCasbinService_Enforce_Denied`
- **输入**: 同上用户，请求 `GET /web/system/users`
- **预期结果**: `Enforce(...) == false`；经中间件返回 403，message="权限不足"
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

### 3. g 链继承（用户 → 角色）
- **测试方法**: `TestIT_CasbinThreeChainInherit_G`
- **输入**: `AddGroupingPolicy(user.user_name, role.code)`
- **预期结果**: 用户经 g 继承获得该角色全部 p 策略，`Enforce` 对已授权接口返回 true
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

### 4. g2 链继承（部门 → 角色）
- **测试方法**: `TestIT_CasbinThreeChainInherit_G2`
- **输入**: `AddDeptGroupingPolicy(dept.code, role.code)`，用户属该部门但**未直接分配角色**
- **预期结果**: `Enforce(user.user_name, 已授权路径, 方法) == true`；`casbin_rule` 中 `p_type='g2'`、`v0=dept.code`、`v1=role.code`
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

### 5. g3 链继承（岗位 → 角色）
- **测试方法**: `TestIT_CasbinThreeChainInherit_G3`
- **输入**: `AddPostGroupingPolicy(post.code, role.code)`，用户属该岗位
- **预期结果**: `Enforce(...) == true`；`casbin_rule` 中 `p_type='g3'`、`v0=post.code`、`v1=role.code`
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

### 6. 解除继承链立即失效
- **测试方法**: `TestIT_CasbinThreeChainInherit_Revoke`
- **输入**: 先建立 g2 继承并确认 true，再 `RemoveDeptGroupingPolicy(dept.code, role.code)`
- **预期结果**: 再次 `Enforce(...) == false`（需 `ReloadPolicy()` 生效）
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

### 7. 删除菜单 API 后策略同步移除
- **测试方法**: `TestMenuService_DeleteAPI_SyncCasbin`
- **输入**: `DeleteAPI(menuID, apiID)`
- **预期结果**: 对应 p 策略被移除；`Enforce` 由 true 变为 false
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

### 8. 清空角色授权后策略全清
- **测试方法**: `TestRoleService_AssignMenus_Empty`
- **输入**: `AssignMenus(roleID, [])`
- **预期结果**: 该角色全部 p 策略被移除；`ac_role_menu_rel` 中该角色的关联为 0 条
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

### 9. 删除角色清理全部策略
- **测试方法**: `TestRoleService_Delete_CleanCasbin`
- **输入**: `Delete(roleID)`
- **预期结果**: p、g、g2、g3 中该角色的策略全部清除；`ac_role_menu_rel` 关联清除
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

### 10. 部门 code 为空时不生成 g2
- **测试方法**: `TestRoleService_AssignDepts_EmptyCode`
- **输入**: 部门 `code=""`，执行 `AssignDepts`
- **预期结果**: `casbin_rule` 中**不产生** `g2` 策略（`code` 是 g2 主体，空值会使继承失效），或返回明确校验错误
- **覆盖文件**: `backend/tests/auth/casbin_test.go`

## DataScope

### 1. 四级可见行数差异
- **测试方法**: `TestIT_DataScopeFourLevels`
- **输入**: 3 个部门各 2 条 `ac_region`（共 6 条），分别以四种 `DataScope` 调用 `RegionService.Page`
- **预期结果**: `all` → `total=6`；`cross_dept`（含本部门 + 1 个跨部门）→ `total=4`；`dept` → `total=2`；`personal`（该部门内仅 1 条由本用户创建）→ `total=1`
- **覆盖文件**: `backend/tests/auth/data_scope_test.go`

### 2. 结果集包含关系
- **测试方法**: `TestIT_DataScopeFourLevels_Subset`
- **输入**: 同上
- **预期结果**: `personal` 返回的 ID 集合 ⊆ `dept` 集合 ⊆ `cross_dept` 集合 ⊆ `all` 集合
- **覆盖文件**: `backend/tests/auth/data_scope_test.go`

### 3. `dept_id` 为空时的退化逻辑
- **测试方法**: `TestDataScope_ApplyToQuery_NoDept`
- **输入**: `DataScope{DataPerm:"dept", DeptID:nil}` 与 `DataScope{DataPerm:"personal", DeptID:nil}`
- **预期结果**: 两者均退化为 `created_by = 当前用户名` 的过滤（SQL 中含 `created_by`，**不含** `dept_id`）；返回行数等于该用户创建的行数，**不等于全表**
- **覆盖文件**: `backend/tests/auth/data_scope_test.go`

### 4. `cross_dept_ids` 为空时的退化逻辑
- **测试方法**: `TestDataScope_ApplyToQuery_EmptyCrossDept`
- **输入**: `DataScope{DataPerm:"cross_dept", CrossDeptIDs:"", DeptID:nil}`
- **预期结果**: 退化为 `created_by` 过滤，**不返回全表**（这是最危险的越权路径，必须显式覆盖）
- **覆盖文件**: `backend/tests/auth/data_scope_test.go`

### 5. `cross_dept_ids` 解析
- **测试方法**: `TestDataScope_ApplyToQuery_ParseIDs`
- **输入**: `CrossDeptIDs="2, 3,,abc,5"`
- **预期结果**: 解析为 `[2,3,5]`，忽略空项与非法项；生成的 SQL 为 `dept_id IN (2,3,5)`
- **覆盖文件**: `backend/tests/auth/data_scope_test.go`

### 6. `all` 权限不加过滤
- **测试方法**: `TestDataScope_ApplyToQuery_All`
- **输入**: `DataScope{DataPerm:"all"}`
- **预期结果**: 返回的查询**不含**任何 `dept_id` / `created_by` 附加条件；行数等于全表
- **覆盖文件**: `backend/tests/auth/data_scope_test.go`

### 7. 空 `data_perm` 的默认值
- **测试方法**: `TestDataScope_NewDataScope_Default`
- **输入**: gin.Context 中未设置 `data_perm`
- **预期结果**: `ds.DataPerm == "personal"`（默认最严格，防止缺省放行）
- **覆盖文件**: `backend/tests/auth/data_scope_test.go`

### 8. 别名推导 created_by 列名
- **测试方法**: `TestDataScope_ApplyToQuery_Alias`
- **输入**: `ApplyToQuery(q, "d.dept_id")`
- **预期结果**: 生成的 SQL 使用 `d.dept_id` 与 `d.created_by`（前缀正确推导），不出现无限定列名导致的歧义错误
- **覆盖文件**: `backend/tests/auth/data_scope_test.go`

## AuthMiddleware / CasbinMiddleware

### 1. 无 Authorization 头
- **测试方法**: `TestAPI_AuthMiddleware_NoToken`
- **输入**: `GET /web/basic/regions`（无头）
- **预期结果**: HTTP 401；message="未提供认证Token"
- **覆盖文件**: `backend/tests/auth/middleware_test.go`

### 2. 认证格式错误
- **测试方法**: `TestAPI_AuthMiddleware_BadFormat`
- **输入**: `Authorization: Token abc`
- **预期结果**: HTTP 401；message="认证格式错误"
- **覆盖文件**: `backend/tests/auth/middleware_test.go`

### 3. 伪造签名
- **测试方法**: `TestAPI_AuthMiddleware_Forged`
- **输入**: 篡改 JWT 第三段签名
- **预期结果**: HTTP 401；message="无效的Token"
- **覆盖文件**: `backend/tests/auth/middleware_test.go`

### 4. 合法 token 写上下文
- **测试方法**: `TestAPI_AuthMiddleware_Context`
- **输入**: 合法 token
- **预期结果**: `c.GetInt64("user_id")`、`c.GetString("user_name")`、`c.GetString("data_perm")`、`c.GetInt64("dept_id")` 均有值；Go Context 中 `model.UsernameFromCtx` / `model.DeptIDFromCtx` / `model.UserIDFromCtx` 均正确（驱动审计字段回填）
- **覆盖文件**: `backend/tests/auth/middleware_test.go`

### 5. 未授权返回 403 而非 401
- **测试方法**: `TestAPI_CasbinMiddleware_Forbidden`
- **输入**: 合法 token + 未授权接口
- **预期结果**: HTTP **403**（非 401、非 500）；message="权限不足"
- **覆盖文件**: `backend/tests/auth/middleware_test.go`

### 6. 静态路由优先于 `:id`
- **测试方法**: `TestAPI_StaticRoutePriority`
- **输入**: 依次请求 `GET /web/devices/modes`、`/web/devices/iot-cards`、`/web/devices/voice-configs`、`/web/devices/options`、`/web/devices/history`、`GET /web/risks/pending-count`、`PUT /web/upgrades/plans/cancel`
- **预期结果**: 全部命中对应的静态 handler，**不返回** 400「非法 ID」、**不返回** 404、**不报** 参数绑定错误
- **覆盖文件**: `backend/tests/auth/router_test.go`

### 7. API Key 认证
- **测试方法**: `TestAPI_ApiKeyAuth`
- **输入**: `POST /web/risks/report` 分别以「无 Key」「错误 Key」「已删除 Key」「合法 Key」请求
- **预期结果**: 前三者 401；合法 Key 返回 200 且回读 `ac_api_key.last_used_dt` **非空**
- **覆盖文件**: `backend/tests/auth/middleware_test.go`
