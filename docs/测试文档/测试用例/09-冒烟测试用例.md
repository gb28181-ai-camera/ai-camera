# 冒烟测试用例

> 版本: v0.1.0
> 最后更新: 2026-09-21

## 核心测试要点

> 冒烟测试是**全流程串联验证**，在版本发布前执行，目的是确认核心业务闭环无阻断性缺陷。
> 与单元测试（单点）和集成测试（2~5 个模块）不同，冒烟覆盖**完整业务闭环**，
> 按真实用户的操作顺序串联基础信息、资源、风险、告警、巡检、升级、权限、统计八大模块。
> 分 8 个 Round 串行执行，前置 Round 的数据供后续 Round 复用。

| # | 测试要点 | 测试方法 | 状态 |
|---|---------|---------|:----:|
| 1 | 基础数据搭建（区域/风险类型/告警类型/设备模式/固件/模型） | Round 1（12 步） | 🟡 |
| 2 | 设备接入与物联网卡绑定 | Round 1（含） | 🟡 |
| 3 | 风险上报 → 确认 → 处理 → 统计 | Round 2（14 步） | 🟡 |
| 4 | 设备心跳 + 告警上报 → 处理 → 历史记录 | Round 3（13 步） | 🟡 |
| 5 | 巡检任务闭环（Web 建 → App 完成 → 记录） | Round 4（9 步） | 🟡 |
| 6 | 现在升级 / 定时升级 / 取消 | Round 5（12 步） | 🟡 |
| 7 | 权限体系（Casbin 三链 + 数据权限四级） | Round 6（11 步） | 🟡 |
| 8 | 统计与大屏 | Round 7（8 步） | 🟡 |
| 9 | 异常与边界分支 | Round 8（9 步） | 🟡 |
| 10 | 前端 E2E 全页面覆盖 | `99-all-list-page.spec.ts` | 🟡 |

## 执行顺序规范

> **必须严格遵守**，否则用例间数据依赖断裂导致大面积失败。

1. 冒烟测试（`frontend/e2e/smoke/`）**串行执行**（`--workers=1`），spec 文件按文件名字母序运行
2. **必须先执行所有功能测试（`01a` ~ `10f`），最后执行 `99-all-list-page.spec.ts`**（全页面覆盖验证）
   —— `99-` 前缀保证其排在最后
3. 新增冒烟测试文件编号**必须小于 `99`**；全页面覆盖类收尾测试保留 `99-` 前缀
4. 执行完成后**关闭前后端服务**，避免端口冲突影响下次执行

```bash
# 串行执行全部冒烟
cd frontend && npx playwright test e2e/smoke --workers=1

# 单独执行全页面覆盖（必须最后）
cd frontend && npx playwright test e2e/smoke/99-all-list-page.spec.ts
```
