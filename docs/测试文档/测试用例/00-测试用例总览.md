## 核心测试要点

> AI Camera 的测试重心有三处：**权限体系**（Casbin 三链继承 + 数据权限四级，出错即越权）、
> **状态机**（风险 pending→handled、巡检 published→finished、升级计划 pending→canceled，出错即数据不一致）、
> **字段回填**（`created_by`/`dept_id`/冗余名称字段，出错即「保存了但没生效」，是最高频的隐性缺陷）。

## 执行命令速查

### 环境准备

```bash
# 1. 清空测试数据库（必须，避免与 seed 数据冲突）
cd backend && go run ./tests/testutil/resetdb/main.go

# 2. 初始化种子数据（冒烟/接口测试需要）
cd backend && go run ./tests/testutil/initdb/main.go
```

### 后端测试

```bash
# 全量
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/... -count=1 -timeout 180s

# 单模块（带详细输出）
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/basic/... -v

# 单个用例
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/basic/ -run TestRegionService_Create -v

# 按前缀批量（集成链路）
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/... -run 'TestIT_' -count=1 -v

# 覆盖率
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/... -coverprofile=coverage.out -count=1 && go tool cover -func=coverage.out
```

### 前端测试

```bash
# 单元测试（MSW mock，无需后端）
cd frontend && npx vitest run

# 端到端测试（需后端在 :8080 + Vite dev server）
cd frontend && npm run dev
cd frontend && npx playwright test

# 冒烟子集（串行，spec 按字母序）
cd frontend && npx playwright test e2e/smoke --workers=1
```

### 移动端测试

```bash
cd app && flutter test
cd app && flutter analyze
```

### 冒烟完整流程

```bash
# 1. 清库
cd backend && go run ./tests/testutil/resetdb/main.go
# 2. 初始化种子数据
cd backend && go run ./tests/testutil/initdb/main.go
# 3. 启动测试服务
export CONFIG_PATH="config/config-test.yaml" && cd backend && go run ./cmd/server/main.go
# 4. 执行前端冒烟（串行）
cd frontend && npx playwright test e2e/smoke --workers=1
# 5. 关闭前后端服务
```

## 编写约定

1. **方法名与契约一一对应**：`RegionService.Create` → `TestRegionService_Create`；
   升级模块因方法名较长，采用 `TestUpgradeService_CreateFirmware` 形式保留语义。
2. **预期结果必须具体**：显式列出要核对的**字段名与期望值**，禁止写「测试通过」「功能正常」。
3. **必须验证绝大多数字段的更新**：每个 `Create`/`Update` 用例至少核对 6 个字段，
   含业务字段 + 审计字段（`created_by`/`updated_by`）。
4. **每模块用例数不少于 15 条**（本套文档最少为巡检模块的 20 条）。
5. **覆盖文件路径必须真实存在**：`backend/tests/<domain>/<domain>_service_test.go`。
