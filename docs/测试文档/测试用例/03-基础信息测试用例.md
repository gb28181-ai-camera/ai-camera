# 基础信息测试用例

> 版本: v0.1.0
> 最后更新: 2026-09-21

## 核心测试要点

> 区域是**几乎所有业务列表的归属维度**（设备、风险、告警、巡检、物联网卡、语音配置都带 `region_id`），
> 风险类型的 `level` 驱动首页与大屏的分级统计，告警类型的三个内置编码（`offline`/`battery`/`traffic`）
> 是设备心跳与告警上报的约定值。三者均为**低频改动但被高频引用**的基础数据，
> 测试重点是**全字段落库**与**删除后被引用方的降级行为**。

## RegionService

### 1. 创建区域
- **测试方法**: `TestRegionService_Create`
- **输入**: `CreateRegionReq`
- **预期结果**: 创建成功，**并逐字段核对**：`name`、`code`、`sequence`、`active`（默认 true）、`remark`、`dept_id`、`created_by`（等于当前登录名）、`created_dt`（非零）
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 2. 获取区域详情
- **测试方法**: `TestRegionService_Get`
- **输入**: 区域 ID
- **预期结果**: 返回 `*model.Region`，**并逐字段核对**：`id`、`name`、`code`、`sequence`、`active`、`remark`、`dept_id`、`created_dt`、`updated_dt`
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 3. 更新区域
- **测试方法**: `TestRegionService_Update`
- **输入**: `UpdateRegionReq{Name:"厂区B", Code:"R-B", Sequence:20, Remark:"已调整"}`
- **预期结果**: 更新成功，**并逐字段核对**：`name`="厂区B"、`code`="R-B"、`sequence`=20、`remark`="已调整"；`updated_by` 等于当前登录名；`updated_dt` 已刷新；`created_by`/`created_dt` 保持原值
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 4. 删除区域 — 软删除
- **测试方法**: `TestRegionService_Delete`
- **输入**: 区域 ID
- **预期结果**: `ac_region.deleted_at` **非空**（非物理删除）；`Page` 不再返回该区域、`total` 减 1；`Get` 返回错误或 nil；再次 `Delete` 幂等
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 5. 删除被引用的区域 — 引用保护
- **测试方法**: `TestRegionService_Delete_Referenced`
- **输入**: 先建设备 `region_id` 指向该区域，再删除区域
- **预期结果**: 删除**被拒绝**，返回业务错误「该区域下存在 N <单位>，无法删除」；区域记录**仍存在**（`deleted_at` 为空）；引用方记录与其 `region_id` 均不变
- **引用清单（9 张表，与需求文档 §5.2 逐条对应）**: `ac_device` / `ac_risk_record` / `ac_alarm_record` / `ac_inspect_task` / `ac_inspect_record` / `ac_iot_card` / `ac_voice_config` / `ac_device_upgrade_plan` / `ac_device_upgrade_record`——**任一表有引用即拒绝删除**
- **设计意图**: 区域是设备、风险、告警、巡检的公共归属维度，允许删除会导致大量记录悬挂在失效区域上、按区域筛选失效。因此对**被引用的基础数据**采取「拒绝删除 + 明确提示引用数量」而非静默软删除。若确需清理，应先转移引用方或先停用（`active=false`）而非删除。
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 6. 分页查询
- **测试方法**: `TestRegionService_Page`
- **输入**: `PageRegionReq{Page:1, PageSize:20}`
- **预期结果**: 返回 `PageRegionResp`；`items` 长度 = `min(page_size, total)`；`total`/`page`/`page_size` 回显正确；仅返回 `deleted_at` 为空的记录
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 7. 分页过滤条件
- **测试方法**: `TestRegionService_Page_Filters`
- **输入**: 分别按 `name`（模糊）、`code`（模糊）、`active` 过滤
- **预期结果**: 每种条件命中数正确；`name`/`code` 为模糊匹配；多条件组合为 AND；无匹配时 `items=[]` 且 `total=0`
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 8. 分页默认与边界
- **测试方法**: `TestRegionService_Page_Default`
- **输入**: 不传 `page`/`page_size`；再传 `page=0`、`page=-1`、`page_size=0`、`page_size=1000`
- **预期结果**: 不传时 `page=1`、`page_size=20`；`page≤0` 归一为 1；`page_size≤0` 归一为默认值（**不得返回全表**）；`page_size` 超上限被截断或被拒绝；`page` 超总页数时 `items=[]` 且 `total` 不变
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 9. 排序稳定性
- **测试方法**: `TestRegionService_Page_Order`
- **输入**: 预置 3 条 `sequence` 相同、1 条 `sequence` 更小的区域
- **预期结果**: `sequence` 小的排在前；`sequence` 相同的按 `id` 升序稳定排列（**重复执行顺序一致**）
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 10. 区域下拉选项
- **测试方法**: `TestRegionService_Options`
- **输入**: `ds`（数据权限）
- **预期结果**: 返回 `[]response.OptionItem`（简单列表 `ROptionList`，**不是分页结构**）；每项 `ID`/`Name` 非空、`Code` 等于区域编码；`active=false` 的区域**不返回**；受数据权限过滤
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 11. 数据权限四级
- **测试方法**: `TestRegionService_Page_DataScope`
- **输入**: 3 个部门各 2 条区域，分别以 `all`/`cross_dept`/`dept`/`personal` 调用 `Page`
- **预期结果**: `total` 分别为 6 / 4 / 2 / 1；结果集满足 `personal ⊆ dept ⊆ cross_dept ⊆ all`
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 12. 字段长度边界
- **测试方法**: `TestRegionService_Create_CodeTooLong`
- **输入**: `code` 为 51 个字符（列宽 50）、`name` 为 256 个字符（列宽 255）
- **预期结果**: 均返回 error，或在落库前被截断（行为必须一致且明确）；不产生 500 错误
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

## RiskTypeService

- **测试方法**: `TestRiskTypeService_Create`

- **预期结果**: 创建成功，**并逐字段核对**：`name`、`code`、`sequence`、`level`、`description`、`active`、`dept_id`、`created_by`、`created_dt`

### 2. 风险等级枚举
- **测试方法**: `TestRiskTypeService_Create_Level`
- **输入**: `level` 分别传 `high`/`medium`/`low`；再传 `"unknown"`
- **预期结果**: 前三者落库成功且 `level` 值与输入一致；非法值返回校验错误；不传时默认 `medium`
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 3. 获取风险类型详情
- **测试方法**: `TestRiskTypeService_Get`
- **输入**: 风险类型 ID
- **预期结果**: 返回 `*model.RiskType`，**并逐字段核对**：`id`、`name`、`code`、`sequence`、`level`、`description`、`active`、`dept_id`
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 4. 更新风险类型
- **测试方法**: `TestRiskTypeService_Update`
- **输入**: 改 `name`/`code`/`sequence`/`level`/`description`/`active`
- **预期结果**: 上述 6 字段全部更新为输入值；`updated_by`/`updated_dt` 刷新；`created_by`/`created_dt` 不变
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 5. 删除风险类型 — 引用保护 + 软删除
- **测试方法**: `TestRiskTypeService_Delete`
- **输入**: 无引用时传风险类型 ID；有引用时先建风险记录再删
- **预期结果**:
  - **无引用**：软删除成功，`deleted_at` 非空；`Page`/`Options` 均不再返回
  - **有引用**（已有风险记录或语音配置引用该类型）：删除被拒绝并返回引用条数，记录保留
- **设计意图**: 与区域一致，风险类型被风险记录/语音配置引用时拒绝删除，避免历史风险的 `risk_type_id` 悬挂导致列表无法展示类型名称
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 6. 分页查询
- **测试方法**: `TestRiskTypeService_Page`
- **输入**: `PageRiskTypeReq{Page:1, PageSize:20}` + `name`/`code`/`level`/`active` 过滤
- **预期结果**: 返回 `PageRiskTypeResp`；各过滤条件命中数正确；`items` 中 `level` 与 `description` 完整
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 7. 下拉选项
- **测试方法**: `TestRiskTypeService_Options`
- **输入**: `ds`
- **预期结果**: 返回 `[]OptionItem` 数组；`active=false` 不返回；受数据权限过滤；用于风险上报时的 `risk_type_id` 选择
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 8. 风险等级用于冗余回填
- **测试方法**: `TestIT_RiskFullLifecycle_LevelRedundancy`
- **输入**: 建 `level=high` 的风险类型 → 上报一条该类型风险
- **预期结果**: `ac_risk_record.risk_level` == `"high"`（**冗余自风险类型**，用于列表与统计免关联查询）
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 9. 数据权限四级
- **测试方法**: `TestRiskTypeService_Page_DataScope`
- **输入**: 四种 `DataScope`
- **预期结果**: 可见行数满足 `personal ≤ dept ≤ cross_dept ≤ all`
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

- **预期结果**: 按设计拒绝或因软删除而不影响已有告警记录；删除后 `AlarmService.Report` 使用该类型仍不报错（或返回明确错误而非 500）
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`

### 5. 获取告警类型详情
- **测试方法**: `TestAlarmTypeService_Get`

### 6. 更新告警类型

### 8. 删除告警类型 — 平台内置类型受保护
- **测试方法**: `TestAlarmTypeService_Delete`、`TestAlarmTypeService_Delete_Builtin`
- **输入**: 自定义告警类型 ID / 平台内置类型（`code` 为 `offline`、`battery`、`traffic`）
- **预期结果**:
  - **自定义类型且无引用**：软删除成功，`deleted_at` 非空；`Page`/`Options` 不再返回
  - **内置类型且无引用**：删除成功（内置编码本身不构成拒绝理由）
  - **存在告警记录引用**：删除被拒绝并返回引用条数，记录保留；已有告警记录的 `alarm_type_id` 不变
- **设计意图**: 内置类型是设备上报协议的一部分（设备按 `offline`/`battery`/`traffic` 上报），但只要没有实际引用仍允许清理；有引用时一律拒绝
- **覆盖文件**: `backend/tests/basic/basic_service_test.go`
