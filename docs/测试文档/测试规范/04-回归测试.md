# 回归测试规范

> 版本: v0.1.0
> 最后更新: 2026-09-21

---

> **定位**：在版本发布前，对**全部已有用例**重跑一遍，确认新改动未破坏既有功能。
> 回归测试不产生新用例，它是对既有用例的**编排与分级**。
>
> **执行频率**：每次版本发布前 + 每次数据模型/中间件/路由/权限变更后。
>
> **运行时间**：全量 < 180s。
>
> **对标**：回归清单覆盖率 100%，无 P0/P1 遗留缺陷。

---

## 一、回归分级

```
┌────────────────────────────────────────────────────────────────┐
│  🔴 P0 阻断级   核心链路不可用 / 数据丢失 / 越权 / 无法登录      │
│     └─ 必须立即修复，阻塞发布，修复后全量回归                    │
├────────────────────────────────────────────────────────────────┤
│  🟠 P1 严重级   主流程可用但结果错误 / 权限误判 / 状态机失效     │
│     └─ 本版本必须修复，修复后执行定向回归 + 相关链路回归         │
├────────────────────────────────────────────────────────────────┤
│  🟡 P2 一般级   次要功能异常 / 展示错误 / 边界未处理             │
│     └─ 评估后修复，修复后执行定向回归                           │
├────────────────────────────────────────────────────────────────┤
│  🔵 P3 轻微级   文案 / 样式 / 交互细节 / 日志冗余                │
│     └─ 可延后，记录至下版本                                     │
└────────────────────────────────────────────────────────────────┘
```

### 1.1 缺陷等级判定表

| 维度 | 🔴 P0 | 🟠 P1 | 🟡 P2 | 🔵 P3 |
|:---|:---|:---|:---|:---|
| **影响范围** | 全部用户 | 多数用户 | 部分场景 | 极少场景 |
| **业务影响** | 无法登录 / 无法建单 / 数据丢失 | 结果错误 / 越权可见 | 展示错误 / 筛选失效 | 样式 / 文案 |
| **典型场景** | 登录 500；风险上报丢失；`personal` 用户看到全部数据 | 状态流转错误；`pending-count` 与实际不符 | 分页 `total` 偏差；排序不稳定 | 提示语错别字 |
| **修复时限** | 立即 | 本版本 | 下个迭代前 | 排期 |
| **回归范围** | 全量 | 定向 + 关联链路 | 定向 | 定向 |

## 三、执行顺序

```
resetdb ──► initdb ──► 启动 config-test.yaml ──┬──► S3 单元测试
                                              ├──► S4 集成测试
                                              ├──► S5 接口测试
                                              ├──► S6 权限回归
                                              ├──► S7 端到端测试
                                              └──► S8 历史缺陷复验
                                                        │
                                                        ▼
                                              99-all-list-page.spec.ts
                                              （全页面覆盖，必须最后执行）
```

```bash
# S1 环境准备
cd backend && go run ./tests/testutil/resetdb/main.go
cd backend && go run ./tests/testutil/initdb/main.go
export CONFIG_PATH="config/config-test.yaml" && cd backend && go run ./cmd/server/main.go

# S3~S6 后端全量
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/... -count=1 -timeout 180s

# S7 前端端到端（冒烟串行）
cd frontend && npx playwright test e2e/smoke --workers=1
```

> **注意**：S7 的冒烟 spec 按文件名字母序串行执行，`01a` ~ `10f` 为功能测试，
> `99-all-list-page.spec.ts` 为全页面覆盖验证，**必须最后执行**。
> 新增冒烟文件编号必须小于 `99`。
