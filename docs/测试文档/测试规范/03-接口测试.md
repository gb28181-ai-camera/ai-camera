# 接口测试规范

> 版本: v0.1.0
> 最后更新: 2026-09-21

---

> **定位**：在 HTTP 层验证 200 个端点的**契约一致性**——认证、参数绑定与校验、权限拦截、
> 数据权限过滤、响应类型、分页边界、软删除语义。
>
> **执行频率**：每日构建 + 每次路由/中间件变更后。
>
> **运行时间**：全量 < 90s。
>
> **对标**：`docs/开发文档/后端开发/00-接口契约.md` 中的路由总表逐条覆盖，
> 每个端点的响应类型与 Swagger 注解一致。

---

## 一、测试关注维度

| 维度 | 校验内容 | 失败典型症状 |
|:---|:---|:---|
| **认证** | 无 token / 格式错误 / 过期 token / 伪造签名 | 401 未返回或误放行 |
| **授权（Casbin）** | 已授权接口放行、未授权接口 403 | 越权访问、权限漏配 |
| **参数绑定** | 必填缺失、类型错误、枚举越界、分页边界 | 500 而非 400 |
| **业务逻辑** | 状态流转、唯一约束、关联存在性 | 非法状态被接受 |
| **数据权限** | 四级（all/cross_dept/dept/personal）行数差异 | 越权看到他人数据 |
| **响应类型** | 简单列表 `RXxxList` vs 分页 `RPageXxx` | 前端取 `res.data.items` 为 undefined |
| **软删除** | `DELETE` 后列表不含、`GET :id` 返回 404 | 删除后仍可查 |
| **关联名称** | 列表返回 `region.name`、`device.name` 等名称字段 | 前端只拿到 ID |

## 三、通用测试要点

### 3.1 认证（所有 `/web/*` 与 `/app/*` 非公开端点）

| # | 用例 | 请求 | 期望 |
|:---:|:---|:---|:---|
| 1 | 无 Authorization 头 | `GET /web/basic/regions` | 401，message="未提供认证Token" |
| 2 | 认证格式错误 | `Authorization: Token xxx` | 401，message="认证格式错误" |
| 3 | 空 Bearer | `Authorization: Bearer ` | 401，message="认证格式错误" |
| 4 | 伪造签名 | 篡改 JWT 第三段 | 401，message="无效的Token" |
| 5 | 过期 token | `exp` 已过 | 401 |
| 6 | 合法 token | 正常登录获取 | 200 |

> **注意**：公开端点仅 3 个——`POST /web/auth/login`、`POST /app/auth/login`、`GET /health`。
> API Key 端点 3 个——`POST /web/risks/report`、`POST /web/alarms/report`、
> `POST /web/devices/:id/heartbeat`，走 `ApiKeyAuth` 中间件而非 JWT。

### 3.2 API Key 认证

| # | 用例 | 期望 |
|:---:|:---|:---|
| 1 | 无 `X-API-Key` 头 | 401 |
| 2 | 前缀正确但哈希不匹配 | 401 |
| 3 | 已删除的 Key（`deleted_at` 非空） | 401 |
| 4 | 合法 Key | 200，且 `ac_api_key.last_used_dt` 被更新 |
| 5 | 合法 Key 调用 JWT 端点（如 `GET /web/system/users`） | 401（API Key 不授予后台权限） |

### 3.3 参数绑定与校验

| # | 场景 | 请求 | 期望 |
|:---:|:---|:---|:---|
| 1 | 必填缺失 | `POST /web/basic/regions` body `{}` | 400，message 指明 `name` 必填 |
| 2 | 类型错误 | `sequence: "abc"` | 400 |
| 3 | 枚举越界 | `data_permission: "unknown"` | 400（仅允许 `all`/`cross_dept`/`dept`/`personal`） |
| 4 | 非法 ID | `GET /web/basic/regions/abc` | 400 |
| 5 | 不存在的 ID | `GET /web/basic/regions/999999` | 404 或 `code` 非 200 |
| 6 | 唯一约束冲突 | 重复 `code` / `device_code` / `card_no` / `user_name` | 非 200，message 含冲突提示 |
| 7 | 关联不存在 | `POST /web/devices` 传无效 `region_id` | 400 或明确错误信息 |

### 3.4 分页边界

统一参数：`page`（默认 1）、`page_size`（默认 20）。

| # | 请求 | 期望 |
|:---:|:---|:---|
| 1 | 不传分页参数 | `page=1`、`page_size=20`、`total` 为全量 |
| 2 | `page=0` | 归一为 1 或 400（不可返回全表） |
| 3 | `page=-1` | 归一为 1 或 400 |
| 4 | `page_size=0` | 归一为默认值，不返回全表 |
| 5 | `page_size=1000` | 被上限截断（建议上限 100）或 400 |
| 6 | `page` 超出总页数 | `items=[]`、`total` 不变 |
| 7 | `page_size=1` | 恰好 1 条，`total` 为全量 |
| 8 | `total` 与 `items` 长度关系 | 首页 `len(items) == min(page_size, total)` |

### 3.5 响应类型一致性

| 类型 | 端点示例 | 前端读取方式 |
|:---|:---|:---|
| `RXxxList` | `GET /web/basic/regions/options`、`GET /web/devices/modes/options` | `res.data ?? []` |
| `RPageXxx` | `GET /web/system/users`、`GET /web/risks` | `res.data?.items ?? []` |
| `RXxx` | `GET /web/devices/:id` | `res.data` |

**断言**：简单列表的 `data` 必须是**数组**（不能是 `{items,total}`）；
分页列表的 `data` 必须是**对象且含 `items`/`total`/`page`/`page_size` 四个键**。
严禁同一端点在不同条件下返回不同形状。

### 3.6 软删除

| # | 用例 | 期望 |
|:---:|:---|:---|
| 1 | `DELETE /web/basic/regions/:id` | 200；库中 `deleted_at` 非空（非物理删除） |
| 2 | 删除后再 `GET :id` | 404 或明确「不存在」 |
| 3 | 删除后 `GET` 列表 | 不含该记录，`total` 减 1 |
| 4 | 删除后再次 `DELETE` | 幂等返回 200 或明确「不存在」 |
| 5 | 删除后被引用的记录 | 依业务而定（如删除区域不影响已建设备，设备 `region.name` 退化为空） |

### 3.7 数据权限过滤

同一 `GET` 列表，分别以 4 种 `data_perm` 的账号请求：

```
all ────────► 返回 N 条（全部）
cross_dept ─► 返回 本部门 + cross_dept_ids 条
dept ───────► 返回 本部门条
personal ───► 返回 本人创建条
        ▲
        └─ 断言：personal ≤ dept ≤ cross_dept ≤ all，且 dept 集合 ⊆ cross_dept 集合 ⊆ all 集合
```

适用端点：`/web/basic/regions`、`/web/basic/risk-types`、`/web/basic/alarm-types`、
`/web/devices`、`/web/devices/modes`、`/web/devices/iot-cards`、`/web/devices/voice-configs`、
`/web/devices/history`、`/web/risks`、`/web/alarms`、`/web/inspects/tasks`、`/web/inspects/records`、
`/web/upgrades/*`、`/web/stats/*`。
**不做行级过滤**的表：`ac_menu`、`ac_role`（无 `dept_id`）。

### 3.8 路由优先级

| # | 用例 | 期望 |
|:---:|:---|:---|
| 1 | `GET /web/devices/modes` | 命中 `modeH.Page`，**不得**被 `/:id` 吞掉 |
| 2 | `GET /web/devices/iot-cards` | 同上，命中 `cardH.Page` |
| 3 | `GET /web/devices/voice-configs` | 同上，命中 `voiceH.Page` |
| 4 | `GET /web/devices/options` | 命中 `deviceH.Options` |
| 5 | `GET /web/devices/history` | 命中 `deviceH.PageHistory` |
| 6 | `GET /web/risks/pending-count` | 命中 `riskH.PendingCount` |
| 7 | `DELETE /web/system/logs/clear` | 命中 `logH.Clear`，不得被 `/logs/:id` 吞掉 |
| 8 | `PUT /web/upgrades/plans/cancel` | 命中 `BatchCancelPlans`，不得被 `/plans/:id/cancel` 吞掉 |

> **实测修正（v0.1.0）**：gin v1.12 会把同级静态子节点规范化到 `:param` 之前，**与注册先后无关**（实测先注册 `/x/:id` 再注册 `/x/modes`，请求 `/x/modes` 仍命中静态 handler）。本项目仍保持「静态路径在前」的书写约定，真实防线是 `backend/tests/api/route_test.go` 的 `TestRoutePriority_StaticWinsOverParam`（发真实请求按响应特征判定 handler，已实证非空转）。
> 这是本项目最容易出错的接线问题，必须逐条断言。

## 五、执行方式

接口测试推荐以 `httptest` 在进程内构造路由，避免依赖外部服务：

```go
func TestAPI_Regions_Auth(t *testing.T) {
    testutil.WithTx(t, func(tx *gorm.DB) {
        bootstrap.SetDB(tx)                       // 事务隔离
        r := router.SetupTestRouter()             // 复用生产路由装配

        cases := []struct{ name, auth string; want int }{
            {"无token", "", 401},
            {"格式错误", "Token abc", 401},
            {"伪造签名", "Bearer forged", 401},
        }
        for _, c := range cases {
            w := httptest.NewRecorder()
            req := httptest.NewRequest("GET", "/web/basic/regions", nil)
            if c.auth != "" { req.Header.Set("Authorization", c.auth) }
            r.ServeHTTP(w, req)
            assert.Equal(t, c.want, w.Code)
        }
    })
}
```
