# 单元测试规范

> 版本: v0.1.0
> 最后更新: 2026-09-21

---

> **定位**：验证 `internal/service/` 下每个 Service 方法在给定输入下的**字段级**写入与返回正确性。
> 是五层测试体系的最底层，也是失败定位成本最低的一层。
>
> **执行频率**：每次提交（本地 `go test ./tests/...`）。
>
> **运行时间**：全量 < 30s；单模块 < 5s。
>
> **对标**：Service 层方法覆盖率 100%（每个导出方法至少 1 个用例），
> 关键字段断言覆盖率 ≥ 90%（即绝大多数模型字段都有对应的写入断言）。

## 二、WithTx 事务隔离原理

### 2.1 调用形态

```go
func TestRegionService_Create(t *testing.T) {
    testutil.WithTx(t, func(tx *gorm.DB) {
        bootstrap.SetDB(tx)
        svc := basic.NewRegionService()

        got, err := svc.Create(context.Background(), &request.CreateRegionReq{
            Name: "厂区A",
            Code: "R-A",
        })
        require.NoError(t, err)
        // 断言...
    })
}
```

### 2.2 内部链路

```
testutil.WithTx(t, fn)
   │
   ├─ 1. 取全局 DB（bootstrap.DB()）并开启事务
   │        tx := bootstrap.DB().Begin()
   │
   ├─ 2. bootstrap.SetDB(tx)   ── 用事务句柄覆盖全局单例
   │        │
   │        └─► 业务代码中 bootstrap.DB() 返回的即为该事务
   │            （Repository / Service 全部经此取库）
   │
   ├─ 3. 执行 fn(tx)           ── 业务写入、断言
   │
   └─ 4. tx.Rollback()         ── 无条件回滚（defer）
            失败时同样回滚，不污染后续用例
```

关键点：

- **覆盖的是全局单例，不是注入参数**：Service 无参构造（`NewRegionService()`），
  内部通过 `bootstrap.DB()` 取库。因此 `SetDB(tx)` 能透明劫持整条调用链，
  无需为测试改造构造签名。
- **GORM 钩子照常生效**：`BaseModel.BeforeCreate` / `BeforeUpdate` 会在事务内执行，
  因此 `created_by` / `updated_by` / `dept_id` 的自动填充行为也在测试覆盖范围内。
- **回滚而非删除**：不依赖 `DELETE` 语句，无法被软删除（`DeletedAt`）语义干扰。

> **注意**：用例内部**不要**再调用 `tx.Commit()`，否则数据落库且无法回滚，
> 会污染后续用例并可能与种子数据冲突。

## 三、字段验证要求

### 3.1 原则

**所有单元测试必须验证绝大多数字段的写入与更新。**

典型的字段失效场景（必须被测试拦住）：

| 场景 | 症状 | 拦截方式 |
|:---|:---|:---|
| DTO 字段未映射到模型 | 请求传了值，库里是零值 | 断言该字段等于输入值 |
| GORM tag 拼写错误 | 列名不匹配，写入失败或写入错误列 | 断言 + 重新 `Get` 回读 |
| 更新时遗漏字段 | `Update` 只改了部分列 | 更新后回读并逐个断言 |
| 指针字段（`*bool` / `*int64`）未赋值 | `active` 保持 nil 而非预期值 | 断言 `*got.Active == true` |
| 默认值未生效 | `sequence` 应为 10 却为 0 | 不传该字段时断言默认值 |
| 冗余字段未回填 | `device_code` 在风险记录中为空 | 断言冗余字段非空且等于源值 |

### 3.2 写入断言模板

```go
got, err := svc.Create(ctx, req)
require.NoError(t, err)

// ① 返回体断言
assert.Equal(t, "厂区A", got.Name)
assert.Equal(t, "R-A", got.Code)

// ② 回读断言（防止「返回体对了但没落库」）
var fresh model.Region
require.NoError(t, bootstrap.DB().First(&fresh, got.ID).Error)
assert.Equal(t, "厂区A", fresh.Name)
assert.Equal(t, "R-A", fresh.Code)
assert.Equal(t, 10, fresh.Sequence)          // 默认值
assert.NotNil(t, fresh.Active)
assert.True(t, *fresh.Active)                // 默认启用
assert.Equal(t, "tester", fresh.CreatedBy)   // GORM 钩子填充
assert.False(t, fresh.CreatedDT.IsZero())
```

### 3.3 更新断言模板

```go
require.NoError(t, svc.Update(ctx, id, &request.UpdateRegionReq{
    Name:     "厂区B",
    Code:     "R-B",
    Sequence: 20,
    Remark:   "已调整",
}))

var fresh model.Region
require.NoError(t, bootstrap.DB().First(&fresh, id).Error)
assert.Equal(t, "厂区B", fresh.Name)
assert.Equal(t, "R-B", fresh.Code)
assert.Equal(t, 20, fresh.Sequence)
assert.Equal(t, "已调整", fresh.Remark)
assert.Equal(t, "tester", fresh.UpdatedBy)   // 更新人自动填充
assert.False(t, fresh.UpdatedDT.IsZero())
```

### 3.4 必验字段速查

| 模型类型 | 必验字段 |
|:---|:---|
| 基础信息（Region / RiskType / AlarmType） | `name`、`code`、`sequence`、`active`、`remark`/`description`、`level`（风险/告警类型） |
| 系统管理（User / Role / Menu / Dept / Post） | `name`、`code`、`sequence`、`active`、`dept_id`、`post_id`、`data_permission`、`cross_dept_ids` |
| 资源管理（Device / IotCard / VoiceConfig） | `name`、`device_code`/`card_no`、`region_id`、`location`、`status`、`battery`、`firmware_ver`、`model_ver` |
| 风险/告警记录 | `risk_type_id`/`alarm_type_id`、`device_id`、`device_code`、`region_id`、`status`、`read`、`detect_accurate`、`handler`、`handled_dt` |
| 巡检 | `name`、`region_id`、`inspector_id`、`plan_dt`、`status`、`task_name`（冗余）、`result` |
| 升级 | `version`、`firmware_id`/`ai_model_id`、`plan_dt`、`status`、`prev_firmware_ver`、`prev_ai_model_ver`、`upgrade_type` |
| 审计字段（全部模型） | `created_by`、`created_dt`、`updated_by`、`updated_dt` |

## 五、执行与验收

```bash
# 清空测试库（必须，避免与 seed 数据冲突）
cd backend && go run ./tests/testutil/resetdb/main.go

# 全量执行
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/... -count=1 -timeout 180s

# 覆盖率采集
cd backend && TEST_DB_HOST=192.168.1.227 TEST_DB_PORT=5432 TEST_DB_USER=boticz TEST_DB_PASSWORD='<测试库密码>' TEST_DB_NAME=ai_camera_test go test ./tests/... -coverprofile=coverage.out -count=1
cd backend && go tool cover -func=coverage.out

```

1. 全部用例 100% 通过，无 `SKIP`
2. `internal/service/` 方法覆盖率 100%
3. 关键模型字段断言覆盖率 ≥ 90%
4. 单次全量运行 < 30s
5. 重复运行结果稳定（无随机失败）
