## 3. 核心代码示例

### 3.1 基础Model

所有业务模型嵌入 `BaseModel`，由 GORM 钩子自动填充审计字段与部门归属。

```go
// internal/model/base.go
package model

import (
	"context"
	"reflect"
	"time"

	"gorm.io/gorm"
)

// BaseModel 被所有业务模型嵌入，提供主键、软删除与审计字段。
type BaseModel struct {
	ID        int64          `gorm:"primarykey" json:"id"`
	DeletedAt gorm.DeletedAt `gorm:"index;comment:软删除时间" json:"deleted_at,omitempty"`

	CreatedBy string    `gorm:"column:created_by;size:50;comment:创建人" json:"created_by,omitempty"`
	CreatedDT time.Time `gorm:"column:created_dt;default:CURRENT_TIMESTAMP;comment:创建时间" json:"created_dt"`
	UpdatedBy string    `gorm:"column:updated_by;size:50;comment:更新人" json:"updated_by,omitempty"`
	UpdatedDT time.Time `gorm:"column:updated_dt;default:CURRENT_TIMESTAMP;autoUpdateTime;comment:更新时间" json:"updated_dt"`
}

// BeforeCreate 自动填充创建人、更新人与部门（若模型含 dept_id 列且为空）。
func (b *BaseModel) BeforeCreate(tx *gorm.DB) error {
	if tx.Statement == nil || tx.Statement.Context == nil {
		return nil
	}
	ctx := tx.Statement.Context

	if b.CreatedBy == "" {
		b.CreatedBy = UsernameFromCtx(ctx)
	}
	if b.UpdatedBy == "" {
		b.UpdatedBy = UsernameFromCtx(ctx)
	}

	// 反射回填 dept_id：仅当目标结构体存在该字段且当前为 nil 时。
	// 部门归属是数据权限的基础，缺失会导致 dept 级过滤失效。
	fillDeptID(tx, DeptIDFromCtx(ctx))
	return nil
}

// BeforeUpdate 自动填充更新人。
func (b *BaseModel) BeforeUpdate(tx *gorm.DB) error {
	if tx.Statement == nil || tx.Statement.Context == nil {
		return nil
	}
	b.UpdatedBy = UsernameFromCtx(tx.Statement.Context)
	return nil
}
```

> **注意**：`fillDeptID` 通过反射为含 `DeptID` 字段的模型回填部门，同时兼容 `*int64` 与 `int64`
> 两种声明方式。这样新增业务表只要带上 `dept_id` 列就自动接入数据权限，无需改动基类。

### 3.2 设备Model

设备是资源管理的核心实体，运行时指标为心跳上报的最新快照，冗余字段用于列表展示。

```go
// internal/model/device.go（节选）
package model

import "time"

// 设备运行状态常量。
const (
	DeviceStatusOnline  = "online"
	DeviceStatusOffline = "offline"
)

// Device AI 摄像头设备。表 ac_device。
//
// 运行时指标（电量/电压/存储/在线时间）由设备心跳上报，写入本表作为最新快照，
// 同时写入 DeviceHistory 作为时序历史。
type Device struct {
	BaseModel
	Active     *bool  `gorm:"column:active;default:true" json:"active"`
	Name       string `gorm:"column:name;size:255;not null;comment:设备名称" json:"name"`
	DeviceCode string `gorm:"column:device_code;size:100;not null;uniqueIndex:idx_ac_device_code;comment:设备编号" json:"device_code"`
	RegionID   *int64 `gorm:"column:region_id;index;comment:所属区域" json:"region_id"`
	Location   string `gorm:"column:location;size:255;comment:设备位置" json:"location"`
	Latitude   string `gorm:"column:latitude;size:32;comment:纬度(GIS)" json:"latitude"`
	Longitude  string `gorm:"column:longitude;size:32;comment:经度(GIS)" json:"longitude"`

	// 版本与模式
	FirmwareID   *int64 `gorm:"column:firmware_id;comment:当前固件ID" json:"firmware_id"`
	FirmwareVer  string `gorm:"column:firmware_ver;size:50;comment:当前固件版本(冗余便于列表展示)" json:"firmware_ver"`
	ModelID      *int64 `gorm:"column:model_id;comment:当前AI模型ID" json:"model_id"`
	ModelVer     string `gorm:"column:model_ver;size:50;comment:当前模型版本" json:"model_ver"`
	SystemVer    string `gorm:"column:system_ver;size:50;comment:系统版本" json:"system_ver"`
	WorkMode     string `gorm:"column:work_mode;size:50;comment:设备工作模式" json:"work_mode"`
	DeviceMode   string `gorm:"column:device_mode;size:50;comment:设备模式(充电/全开/省电)" json:"device_mode"`
	InfoInterval int    `gorm:"column:info_interval;default:60;comment:信息上传间隔(秒)" json:"info_interval"`

	// 运行时状态（设备心跳/平台探测更新）
	Status      string     `gorm:"column:status;size:20;default:offline;comment:运行状态 online/offline" json:"status"`
	Battery     int        `gorm:"column:battery;comment:电量百分比" json:"battery"`
	Voltage     string     `gorm:"column:voltage;size:32;comment:电压" json:"voltage"`
	StorageFree int64      `gorm:"column:storage_free;comment:剩余存储容量(MB)" json:"storage_free"`
	LastBeatDT  *time.Time `gorm:"column:last_beat_dt;comment:最近心跳时间" json:"last_beat_dt"`

	DeptID *int64 `gorm:"column:dept_id;index;comment:所属部门(数据权限)" json:"dept_id"`

	// 关联对象（列表展示名称用）
	Region   *Region   `gorm:"foreignKey:RegionID;references:ID" json:"region,omitempty"`
	IotCard  *IotCard  `gorm:"foreignKey:IotCardID;references:ID" json:"iot_card,omitempty"`
	Firmware *Firmware `gorm:"foreignKey:FirmwareID;references:ID" json:"firmware,omitempty"`
	AIModel  *AIModel  `gorm:"foreignKey:ModelID;references:ID" json:"ai_model,omitempty"`
}

func (Device) TableName() string { return "ac_device" }
```

> **注意**：`TableName()` 由模型显式声明，GORM 的 `NamingStrategy` 设 `SingularTable: false`，
> 表名不接受复数化推导，保证与 DDL 脚本中的表名逐字一致。

### 3.3 API处理器

Handler 只做「绑定参数 → 调用 Service → 包装响应」，业务逻辑一律下沉到 Service。
构造函数无参，Service 在构造函数内装配（见《00-接口契约.md》第 4 节装配契约）。

```go
// internal/api/handler/web/device_handler.go
package web

import (
	"strconv"

	"github.com/boticz/ai-camera-backend/internal/dto/request"
	"github.com/boticz/ai-camera-backend/internal/dto/response"
	device "github.com/boticz/ai-camera-backend/internal/service/device"
	"github.com/boticz/ai-camera-backend/pkg/utils"
	"github.com/gin-gonic/gin"
)

// DeviceHandler 设备管理处理器。
type DeviceHandler struct {
	svc *device.DeviceService
}

// NewDeviceHandler 构造设备处理器。
func NewDeviceHandler() *DeviceHandler {
	return &DeviceHandler{svc: device.NewDeviceService()}
}

// Page 分页查询设备列表
// @Summary 分页查询设备
// @Tags Device
// @Accept json
// @Produce json
// @Param req query request.PageDeviceReq false "查询参数"
// @Success 200 {object} response.RPageDevice
// @Router /web/devices [get]
func (h *DeviceHandler) Page(c *gin.Context) {
	var req request.PageDeviceReq
	if err := c.ShouldBindQuery(&req); err != nil {
		utils.BadRequest(c, err.Error())
		return
	}

	// 数据权限：由 Auth 中间件写入 gin.Context 的 data_perm / dept_id 推导
	ds := utils.NewDataScope(c)

	resp, err := h.svc.Page(c.Request.Context(), &req, ds)
	if err != nil {
		utils.ServerError(c, err.Error())
		return
	}
	utils.Success(c, resp)
}

// Get 查询设备详情
// @Summary 查询设备详情
// @Tags Device
// @Produce json
// @Param id path int true "设备ID"
// @Success 200 {object} response.RDevice
// @Router /web/devices/{id} [get]
func (h *DeviceHandler) Get(c *gin.Context) {
	id, err := strconv.ParseInt(c.Param("id"), 10, 64)
	if err != nil {
		utils.BadRequest(c, "非法的设备ID")
		return
	}

	device, err := h.svc.Get(c.Request.Context(), id)
	if err != nil {
		utils.NotFound(c, "设备不存在")
		return
	}
	utils.Success(c, device)
}

// Create 新增设备
// @Summary 新增设备
// @Tags Device
// @Accept json
// @Produce json
// @Param body body request.CreateDeviceReq true "设备信息"
// @Success 201 {object} response.RDevice
// @Router /web/devices [post]
func (h *DeviceHandler) Create(c *gin.Context) {
	var req request.CreateDeviceReq
	if err := c.ShouldBindJSON(&req); err != nil {
		utils.BadRequest(c, err.Error())
		return
	}

	m, err := h.svc.Create(c.Request.Context(), &req)
	if err != nil {
		utils.ServerError(c, err.Error())
		return
	}
	utils.Created(c, m)
}
```

```go
package device

import (
```

### 3.4 路由注册

路由装配遵循《00-接口契约.md》第 4 节的 Handler 清单，三类分组各用不同中间件。

```go
// internal/api/router/web.go（节选）
package router

import (
	"github.com/boticz/ai-camera-backend/internal/api/handler/web"
	"github.com/boticz/ai-camera-backend/internal/api/middleware"
	"github.com/boticz/ai-camera-backend/internal/bootstrap"
	"github.com/gin-gonic/gin"
)

// SetupRouter 装配全部路由。
func SetupRouter() *gin.Engine {
	r := gin.New()
	r.Use(gin.Recovery())

	authMW := middleware.NewAuthMiddleware()
	middleware.SetDefaultJWTService(bootstrap.JWTService())

	// ── 公开接口：无需鉴权 ──
	authH := web.NewAuthHandler()
	r.POST("/web/auth/login", authH.Login)
	r.GET("/health", func(c *gin.Context) { c.String(200, "ok") })

	// ── API Key 接口：设备回调，不走 Casbin ──
	apiKey := r.Group("/web", middleware.ApiKeyAuth())
	{
		riskH := web.NewRiskHandler()
		alarmH := web.NewAlarmHandler()
		deviceH := web.NewDeviceHandler()
		apiKey.POST("/risks/report", riskH.Report)
		apiKey.POST("/alarms/report", alarmH.Report)
		apiKey.POST("/devices/:id/heartbeat", deviceH.Heartbeat)
	}

	// ── 认证接口：JWT + Casbin + 操作日志 ──
	web := r.Group("/web")
	web.Use(authMW.Handler())                 // 1. JWT 认证
	web.Use(casbinHandler())                  // 2. Casbin 接口鉴权
	web.Use(middleware.OperationLog())        // 3. 增删改审计落库
	{
		// 个人中心
		profileH := web.NewProfileHandler()   // 占位：实际为 handler 包内构造
		web.GET("/profile", profileH.GetProfile)

		// 系统管理
		system := web.Group("/system")
		{
			userH := web.NewUserHandler()
			system.GET("/users", userH.Page)
			system.POST("/users", userH.Create)
		}

		// 资源管理：静态子路径统一写在 /:id 之前（gin v1.12 已自动规范化同级顺序，此为书写约定）
		devices := web.Group("/devices")
		{
			devices.GET("", deviceH.Page)
			devices.GET("/options", deviceH.Options)
			devices.GET("/history", deviceH.PageHistory)
			devices.GET("/modes", modeH.Page)          // 静态路径
			devices.GET("/iot-cards", cardH.Page)      // 静态路径
			devices.GET("/:id", deviceH.Get)           // 通配路径放最后
			devices.PUT("/:id/mode", deviceH.SwitchMode)
		}
	}

	return r
}

// casbinHandler 把 Casbin 服务包装为 gin 中间件。
// 主体取登录名（user_name），与 g / g2 / g3 的主体取值保持一致。
func casbinHandler() gin.HandlerFunc {
	cs := bootstrap.CasbinService()
	if cs == nil {
		// 初始化失败时退化为放行，由 bootstrap 打印的显著告警兜底
		return func(c *gin.Context) { c.Next() }
	}
	return middleware.CasbinMiddleware(cs.Enforce)
}
```

> **注意**：`/web/devices/modes`、`/web/devices/iot-cards` 与 `/web/devices/:id` 同级，
> 路由注册时**必须**把静态子路径写在 `/:id` 之前，否则 `modes` 会被当作设备 ID 匹配。
> 同理适用于 `/web/system/logs/clear` 与 `/web/system/logs/:id`。

## 4. 权限控制（Casbin）

### 4.1 权限模型设计

权限链路为「接口 → 菜单 → 角色 → 用户 / 部门 / 岗位」：

```
接口(API) → 菜单(Menu) → 角色(Role) → 用户 / 部门 / 岗位
```

```text
┌───────────────────────────────────────────────────────────────┐
│数据结构层                                                     │
│                                                               │
│  ac_menu                        ac_menu_api                   │
│  ┌────────────────────┐         ┌──────────────────────────┐  │
│  │ id: 811            │   1:n   │ id: 1201                 │  │
│  │ name: 设备管理     │────────▶│ menu_id: 811             │  │
│  │ type: menu         │         │ method: GET              │  │
│  │ permission_code:   │         │ path: /web/devices       │  │
│  │   device:view      │         │ ...                      │  │
│  └─────────┬──────────┘         └──────────────────────────┘  │
│            │ n:m（ac_role_menu_rel）                          │
│            ▼                                                  │
│  ┌────────────────────┐                                       │
│  │ ac_role.code       │  sub = super_admin（p 策略主体）      │
│  └─────────┬──────────┘                                       │
│            │ g / g2 / g3 继承                                 │
│            ▼                                                  │
│  ac_user.user_name ──▶ ac_dept.code ──▶ ac_post.code          │
│  （r.sub）             （g2 主体）        （g3 主体）         │
│                                                               │
│  最终 p 策略：(role.code, api.path, api.method)               │
│  例：p, super_admin, /web/devices/:id, PUT                    │
└───────────────────────────────────────────────────────────────┘
```

设计要点：

| 要点 | 说明 |
|:-----|:-----|
| 策略来源唯一 | `p` 策略只能由「角色 → 菜单 → 菜单接口」三级推导，不允许手工写入 |
| 主体取值 | `p.sub` / `g.v1` 统一使用 `role.code`；`r.sub` 使用 `user.user_name` |
| 路径形式 | `p.obj` 使用 `keyMatch2` 兼容形式，如 `/web/system/users/:id` |
| 方法校验 | matcher 中同时校验 `r.act == p.act`，避免 GET 权限被用于 DELETE |
| 三级继承 | `g` 用户直连、`g2` 部门继承、`g3` 岗位继承，任一命中即放行 |

### 4.2 菜单-接口绑定

一个菜单绑定其下全部后端接口；按钮型菜单只绑定它对应的那一个接口，从而实现接口级最小授权。

```go
// internal/model/system.go（节选）
package model

// MenuAPI 菜单绑定的后端接口，是 Casbin p 策略的唯一来源。表 ac_menu_api。
type MenuAPI struct {
	BaseModel
	MenuID      int64  `gorm:"column:menu_id;not null;index;comment:菜单ID" json:"menu_id"`
	Method      string `gorm:"column:method;size:10;not null;comment:HTTP方法" json:"method"`
	Path        string `gorm:"column:path;size:255;not null;comment:接口路径" json:"path"`
	Description string `gorm:"column:description;size:500;comment:说明" json:"description"`
}

func (MenuAPI) TableName() string { return "ac_menu_api" }
```

典型绑定（对应 `sql/init/01-初始数据.sql` 的实际数据）：

```
菜单: "设备管理" (id=811, type=menu, permission_code=device:view)
  ├─ GET    /web/devices              查询列表
  ├─ GET    /web/devices/options      下拉选项
  └─ GET    /web/devices/:id          查询详情

菜单: "新增设备" (id=8111, type=button, permission_code=device:create, parent=811)
  └─ POST   /web/devices

菜单: "编辑设备" (id=8112, type=button, permission_code=device:update, parent=811)
  └─ PUT    /web/devices/:id

菜单: "删除设备" (id=8113, type=button, permission_code=device:delete, parent=811)
  └─ DELETE /web/devices/:id

菜单: "切换设备模式" (id=8114, type=button, parent=811)
  └─ PUT    /web/devices/:id/mode
```

> **注意**：同一接口可绑定到多个菜单（如「实时监控」与「设备管理」都要读设备列表）。
> Casbin 的 `p` 策略按 `(角色, 路径, 方法)` 唯一，重复绑定不会放大权限。

### 4.3 角色-菜单关联

角色通过菜单获得权限，角色本身不直接持有接口：

```go
// internal/model/system.go（节选）
// Role 角色。表 ac_role。Code 是 Casbin 的 sub 值，必须唯一且稳定。
type Role struct {
	BaseModel
	Active         *bool  `gorm:"column:active;default:true" json:"active"`
	Sequence       int    `gorm:"column:sequence;default:10;comment:显示顺序" json:"sequence"`
	Name           string `gorm:"column:name;size:255;not null;comment:角色名称" json:"name"`
	Code           string `gorm:"column:code;size:50;not null;uniqueIndex:idx_ac_role_code;comment:权限字符(Casbin sub)" json:"code"`
	Description    string `gorm:"column:description;type:text;comment:描述" json:"description"`
	DataPermission string `gorm:"column:data_permission;size:20;not null;default:all;comment:数据权限 all/cross_dept/dept/personal" json:"data_permission"`

```

角色授权变更后**必须**重建策略，否则新权限要等到下一次定时重载才生效：

```go
// internal/service/system/role_service.go（节选）
// syncCasbinForRole 按「角色 → 菜单 → 菜单接口」重建该角色的 p 策略。
func (s *RoleService) syncCasbinForRole(ctx context.Context, roleID int64) error {
	cs := bootstrap.CasbinService()
	if cs == nil {
		return nil // Casbin 未初始化，路由层已退化为放行
	}

	var role model.Role
	if err := bootstrap.DB().WithContext(ctx).First(&role, roleID).Error; err != nil {
		return err
	}

	// 1. 清空该角色的全部 p 策略后整量重建，避免增量比对遗漏
	if _, err := cs.RemoveFilteredPolicyByRole(role.Code); err != nil {
		return err
	}

	// 2. 角色 → 菜单 → 菜单接口 三级推导
	var apis []model.MenuAPI
	err := bootstrap.DB().WithContext(ctx).
		Table("ac_menu_api AS a").
		Joins("JOIN ac_role_menu_rel AS rm ON rm.menu_id = a.menu_id").
		Where("rm.role_id = ? AND a.deleted_at IS NULL", roleID).
		Select("a.method, a.path").
		Find(&apis).Error
	if err != nil {
		return err
	}
	for _, api := range apis {
		if _, err := cs.AddPolicy(role.Code, api.Path, api.Method); err != nil {
			return err
		}
	}

	// 3. 从存储重新加载，保证多实例部署下策略立即一致
	return cs.ReloadPolicy()
}
```

### 4.4 用户/部门/岗位 → 角色（Casbin g 关系）

用户通过三条途径获得角色，任一命中即放行：

```text
┌──────────────────────────────────────────────────────────────────────────┐
│请求主体 r.sub = user_name（登录名）                                      │
│                                                                          │
│  admin                                                                   │
│    │                                                                     │
│    ├── g  ──▶ super_admin        用户直接分配的角色（ac_user_role_rel）  │
│    │                                                                     │
│    ├── g2 ──▶ 部门角色           所属部门继承（ac_dept_role_rel）        │
│    │          部门 code = ROOT                                           │
│    │                                                                     │
│    └── g3 ──▶ 岗位角色           所属岗位继承（ac_post_role_rel）        │
│               岗位 code = system_admin                                   │
│                                                                          │
│matcher：任一继承链命中 且 路径 keyMatch2 成立 且 方法相等 → 放行         │
└──────────────────────────────────────────────────────────────────────────┘
```

```go
// internal/model/system.go（节选）：三种继承主体的编码字段
// Dept.Code  —— Casbin g2 主体；Post.Code —— Casbin g3 主体
// User.Username（user_name 列）—— Casbin g 主体，也是 r.sub

// internal/service/system/role_service.go（节选）
// AssignDepts 保存角色-部门关联，并同步 g2 策略。
func (s *RoleService) AssignDepts(ctx context.Context, roleID int64, deptIDs []int64) error {
	cs := bootstrap.CasbinService()
	var role model.Role
	if err := bootstrap.DB().WithContext(ctx).First(&role, roleID).Error; err != nil {
		return err
	}

	if cs != nil {
		if _, err := cs.RemoveFilteredDeptGroupingPolicyByRole(role.Code); err != nil {
			return err
		}
	}

	// 覆盖式保存关联表
	if err := bootstrap.DB().WithContext(ctx).
		Where("role_id = ?", roleID).
		Delete(&model.DeptRoleRel{}).Error; err != nil {
		return err
	}
	for _, deptID := range deptIDs {
		if err := bootstrap.DB().WithContext(ctx).
			Create(&model.DeptRoleRel{DeptID: deptID, RoleID: roleID}).Error; err != nil {
			return err
		}
		// g2 策略主体用部门编码而非 ID，与 matcher 的 g2(r.sub, p.sub) 对齐
		var dept model.Dept
		if err := bootstrap.DB().WithContext(ctx).First(&dept, deptID).Error; err != nil {
			return err
		}
		if cs != nil && dept.Code != "" {
			if _, err := cs.AddDeptGroupingPolicy(dept.Code, role.Code); err != nil {
				return err
			}
		}
	}

	if cs != nil {
		return cs.ReloadPolicy()
	}
	return nil
}
```

> **注意**：`g2` / `g3` 的主体是**部门编码**与**岗位编码**，而 `r.sub` 是**用户登录名**。
> 两者要能连通，必须在登录时把用户所属部门的编码、所属岗位的编码也写成 `g2` / `g3` 关系，
> 详见 4.8 节的完整链路。

### 4.5 Casbin 集成代码

```go
// pkg/perm/casbin.go
package perm

import (
	"log"
	"time"

	"github.com/casbin/casbin/v2"
	gormadapter "github.com/casbin/gorm-adapter/v3"
	"gorm.io/gorm"
)

// CasbinService 封装 Casbin enforcer，提供 RBAC 校验与策略维护能力。
//
// 策略来源：角色(role.code) → 菜单(ac_role_menu_rel) → 菜单接口(ac_menu_api)，
// 即 p 策略为 (roleCode, apiPath, method)。角色继承关系有三条链：
//   g  : 用户登录名  → 角色编码（直接分配）
//   g2 : 部门编码    → 角色编码（部门继承）
//   g3 : 岗位编码    → 角色编码（岗位继承）
type CasbinService struct {
	enforcer *casbin.Enforcer
}

// NewCasbinService 基于 model 配置文件与 GORM 适配器创建 enforcer。
// 策略持久化在 casbin_rule 表，由适配器自动建表。
func NewCasbinService(db *gorm.DB, modelPath string) (*CasbinService, error) {
	adapter, err := gormadapter.NewAdapterByDB(db)
	if err != nil {
		return nil, err
	}

	enforcer, err := casbin.NewEnforcer(modelPath, adapter)
	if err != nil {
		return nil, err
	}

	if err := enforcer.LoadPolicy(); err != nil {
		return nil, err
	}

	return &CasbinService{enforcer: enforcer}, nil
}

// Enforce 校验 (用户登录名, 请求路径, 请求方法) 是否放行。
func (s *CasbinService) Enforce(username, path, method string) (bool, error) {
	return s.enforcer.Enforce(username, path, method)
}

// ReloadPolicy 从存储重新加载全部策略（角色授权变更后调用）。
func (s *CasbinService) ReloadPolicy() error {
	return s.enforcer.LoadPolicy()
}

// StartAutoReload 启动定时重载，保证多实例部署时策略最终一致。
func (s *CasbinService) StartAutoReload(interval time.Duration) {
	if interval <= 0 {
		interval = 5 * time.Minute
	}
	go func() {
		ticker := time.NewTicker(interval)
		defer ticker.Stop()
		for range ticker.C {
			if err := s.enforcer.LoadPolicy(); err != nil {
				log.Printf("Casbin 策略自动重载失败: %v", err)
			}
		}
	}()
}
```

`casbin_rule` 表的列名为 `ptype, v0..v5`（由 gorm-adapter v3 实测创建），
本项目实际使用的列见下表：

| ptype | v0 | v1 | v2 | 示例 |
|:-----:|:---|:---|:---|:-----|
| `p` | 角色编码 | 接口路径 | HTTP 方法 | `p, super_admin, /web/devices/:id, PUT` |
| `g` | 用户登录名 | 角色编码 | - | `g, admin, super_admin` |
| `g2` | 部门编码 | 角色编码 | - | `g2, ROOT, super_admin` |
| `g3` | 岗位编码 | 角色编码 | - | `g3, system_admin, super_admin` |

### 4.6 Casbin 模型配置文件

```conf
// config/rbac_model.conf（逐字复制，勿改）
[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[role_definition]
g = _, _              // 用户→角色（直接分配）
g2 = _, _             // 部门→角色（部门继承）
g3 = _, _             // 岗位→角色（岗位继承）

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
# 校验链：用户直接角色 OR 用户所属部门的角色 OR 用户所属岗位的角色
# 同时校验请求路径与请求方法（keyMatch2 支持 :id 形式的路由参数）
m = keyMatch2(r.obj, p.obj) && r.act == p.act && (g(r.sub, p.sub) || g2(r.sub, p.sub) || g3(r.sub, p.sub))
```

**相对 boticz-mes 的改进**：boticz-mes 的 matcher 只判断角色继承，不校验请求方法与路径通配：

```conf
# boticz-mes（对照）
m = g(r.sub, p.sub) || g2(r.sub, p.sub) || g3(r.sub, p.sub)
```

本项目在 matcher 中增加了 `keyMatch2(r.obj, p.obj) && r.act == p.act`，带来两点收益：

| 改进点 | 说明 |
|:-------|:-----|
| `keyMatch2(r.obj, p.obj)` | 支持 `/web/devices/:id` 形式的参数化路径，路由参数不再需要逐条枚举，同时天然免疫前缀越权（`/web/devices-x` 不会命中 `/web/devices`） |
| `r.act == p.act` | 请求方法参与校验，只授了 `GET` 的角色无法用 `DELETE` 调同一路径 |

> **注意**：`keyMatch2` 会把 `:id` 匹配为「不跨 `/` 的任意段」。因此
> `/web/system/logs/:id` 不会匹配 `/web/system/logs/clear`，两者需分别绑定。

### 4.7 路由注册中使用Casbin中间件

```go
// internal/api/middleware/auth.go（节选）
// CasbinMiddleware 基于 Casbin 策略执行接口级鉴权。
//
// 主体使用登录名（user_name），与角色继承链 g/g2/g3 的主体取值保持一致。
func CasbinMiddleware(enforce func(sub, obj, act string) (bool, error)) gin.HandlerFunc {
	return func(c *gin.Context) {
		username := c.GetString("user_name")
		if username == "" {
			utils.Unauthorized(c, "未提供认证Token")
			c.Abort()
			return
		}

		// 用真实请求路径而非路由模板：p 策略中的 :id 由 keyMatch2 匹配
		ok, err := enforce(username, c.Request.URL.Path, c.Request.Method)
		if err != nil {
			utils.ServerError(c, "权限校验失败")
			c.Abort()
			return
		}
		if !ok {
			utils.Forbidden(c, "权限不足")
			c.Abort()
			return
		}

		c.Next()
	}
}
```

```go
// internal/api/router/web.go（节选）
web := r.Group("/web")
web.Use(authMW.Handler())          // 1. JWT 认证
web.Use(casbinHandler())           // 2. Casbin 接口鉴权
```

### 4.8 权限控制的完整链路

```
1. 系统管理员配置菜单与接口绑定
   └── ac_menu (name, code, path, type=menu/button, permission_code)
       └── ac_menu_api (menu_id, method, path)
           └── 每个后端接口绑定到一个菜单项，构成 p 策略的唯一来源

2. 系统管理员创建角色并授权
   └── ac_role (name, code, data_permission)
       └── ac_role_menu_rel (role_id, menu_id)
           └── 角色拥有菜单 → 自动获得该菜单下全部接口权限
               └── syncCasbinForRole() 重建 p 策略 → ReloadPolicy()

3. 系统管理员把角色分配给用户 / 部门 / 岗位
   ├── ac_user_role_rel (user_id, role_id)  → Casbin g  : 用户登录名 → 角色编码
   ├── ac_dept_role_rel (dept_id, role_id)  → Casbin g2 : 部门编码   → 角色编码
   └── ac_post_role_rel (post_id, role_id)  → Casbin g3 : 岗位编码   → 角色编码

4. 用户登录
   └── POST /web/auth/login
       ├── bcrypt 校验密码 → 签发 JWT（HS256，claims 携带 data_perm / dept_id）
       └── 同时写入 g / g2 / g3：用户登录名 → 其直接角色 + 所属部门角色 + 所属岗位角色

5. 用户请求接口
   └── Auth 中间件解析 Bearer Token
       ├── claims 写入 gin.Context：user_id / user_name / dept_id / data_perm
       └── claims 写入 Go Context：驱动 GORM 钩子填充审计字段与 dept_id
           └── Casbin 中间件：Enforce(user_name, path, method)
               ├── g  : 用户直接角色是否覆盖该 (路径, 方法)
               ├── g2 : 用户所属部门的角色是否覆盖
               └── g3 : 用户所属岗位的角色是否覆盖
                   └── 通过 → Handler → Service → Repository
                       └── DataScope.ApplyToQuery() 施加行级过滤后返回数据
```

四级权限叠加，逐级收窄：

| 级别 | 机制 | 位置 | 拦截效果 |
|:----:|:-----|:-----|:---------|
| 1 | JWT 认证 | `pkg/auth/jwt.go` | 无 Token / Token 失效 → 401 |
| 2 | Auth 中间件 | `internal/api/middleware/auth.go` | 解析 claims 写入 gin.Context 与 Go Context |
| 3 | Casbin RBAC | `pkg/perm/casbin.go` + `config/rbac_model.conf` | 角色无权访问该接口 → 403 |
| 4 | 数据权限 DataScope | `pkg/utils/data_scope.go` | 行级过滤，只返回权限范围内的记录 |

数据权限（第 4 级）的四种取值与过滤规则：

| `data_permission` | 过滤规则 | 适用角色 |
|:-----------------:|:---------|:---------|
| `all` | 不加过滤，返回全部数据 | 超级管理员 |
| `cross_dept` | `dept_id IN (本部门 + cross_dept_ids)`，无部门时退化为按创建人 | 跨区域管理者 |
| `dept` | `dept_id = 本部门`，无部门时退化为 `created_by = 当前用户` | 部门负责人 |
| `personal` | `dept_id = 本部门 AND created_by = 当前用户` | 普通操作员 |

```go
// pkg/utils/data_scope.go（节选）
// ApplyToQuery 依据数据权限为查询附加过滤条件。
// deptCol 必须是带表别名的限定列名，例如 "d.dept_id"；
// 对应的 created_by 列由前缀推导（"d.dept_id" -> "d.created_by"）。
func (ds *DataScope) ApplyToQuery(q *gorm.DB, deptCol string) *gorm.DB {
	createdByCol := "created_by"
	if idx := strings.LastIndex(deptCol, "."); idx >= 0 {
		createdByCol = deptCol[:idx+1] + "created_by"
	}

	switch ds.DataPerm {
	case "all":
		return q
	case "cross_dept":
		ids := ParseIDs(ds.CrossDeptIDs)
		if ds.DeptID != nil {
			ids = append(ids, *ds.DeptID)
		}
		if len(ids) == 0 {
			return q.Where(createdByCol+" = ?", ds.UserName)
		}
		return q.Where(deptCol+" IN ?", dedup(ids))
	case "dept":
		if ds.DeptID == nil {
			return q.Where(createdByCol+" = ?", ds.UserName)
		}
		return q.Where(deptCol+" = ?", *ds.DeptID)
	default: // personal
		if ds.DeptID == nil {
			return q.Where(createdByCol+" = ?", ds.UserName)
		}
		return q.Where(deptCol+" = ? AND "+createdByCol+" = ?", *ds.DeptID, ds.UserName)
	}
}
```

> **注意**：`dept_id` 为空的表（如 `ac_menu`、`ac_role`）不做行级过滤，
> 因此 Repository 列表方法只对带 `dept_id` 的表传入 `ApplyToQuery`。
