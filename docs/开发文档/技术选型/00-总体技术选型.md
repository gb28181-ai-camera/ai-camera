# 总体技术选型

> 版本: v0.2.0
> 最后更新: 2026-10-21
> 范围: AI Camera 智能监控平台全栈技术栈、环境规划与关键依赖

## 1. 技术架构总览

v0.2.0 在原有单体后端之外增加了一个 **GB/T 28181 信令入口** 与一个 **ZLMediaKit 媒体节点**。
架构口径是「**一个 Go module、两个进程入口 + 一个外部媒体服务**」，而不是微服务化：
两个 Go 入口共用同一份 `internal/model|repository|service|bootstrap`、同一个数据库。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│前端层                                                                      │
│  React 19 + Vite + Ant Design 5 + Zustand + Axios + TypeScript             │
│  mpegts.js（HTTP-FLV 兜底）｜ Electron 桌面端 ｜ Flutter 移动端 ｜ 官网    │
├────────────────────────────────────────────────────────────────────────────┤
│接入 / 网关层                                                               │
│  Traefik Ingress（反向代理 + 自动 HTTPS）｜ Vite Dev Proxy                 │
│  SIP 接入：UDP/TCP 5060（设备直连 sipsvc）                                 │
├────────────────────────────────────────────────────────────────────────────┤
│后端层（Go 1.26 + Gin 1.12 + GORM 1.25 + Casbin 2.135 + JWT v5）            │
│  ┌──────────────────────────────┐   ┌──────────────────────────────────┐  │
│  │ cmd/server                   │   │ cmd/sipsvc（副本固定 1）          │  │
│  │ /web/* /app/* /media/hook/*  │   │ SIP REGISTER / MESSAGE / INVITE  │  │
│  │ 业务编排 + ZLM REST          │   │ Digest / 目录 / 会话             │  │
│  └──────────────┬───────────────┘   └──────────────┬───────────────────┘  │
│                 │        control.SipController 接口 │                      │
│                 └───────────────┬───────────────────┘                      │
│                     （embedded=true 时同进程）                             │
├────────────────────────────────────────────────────────────────────────────┤
│媒体层                                                                      │
│  ZLMediaKit（单端口收流 10000/udp+tcp，WebRTC/FLV/HLS 转协议）             │
│  RTP/PS 由 ZLM 处理，Go 侧不解复用（架构不变量）                            │
├────────────────────────────────────────────────────────────────────────────┤
│服务层                                                                      │
│  定时调度 robfig/cron（升级计划下发 / 离线巡检 / 心跳超时判定）            │
│  第三方服务：个推推送 ｜ 腾讯云短信 ｜ Pipecat 语音 Agent（可选）          │
│  媒体存储：风险图片 / 风险录像 / 语音播报音频 / 国标云端录像               │
├────────────────────────────────────────────────────────────────────────────┤
│数据层                                                                      │
│  PostgreSQL 16（主库）｜ Redis 7（配置预留，国标链路未作强依赖）            │
├────────────────────────────────────────────────────────────────────────────┤
│部署层                                                                      │
│  Docker Compose（postgres / redis / backend / frontend / zlm / sipsvc）    │
│  Kubernetes + GitLab CI ｜ Prometheus + Grafana 监控                       │
└────────────────────────────────────────────────────────────────────────────┘
```

> **部署提示**：`cmd/server` 与 `cmd/sipsvc` 分进程时，API 进程没有注入 SIP 控制器，
> HTTP 触发的播放 / 云台 / 回放命令会不可用；单进程 `gb28181.embedded=true` 是当前可用形态。
> 详见 [02-后端技术选型.md](02-后端技术选型.md) §7.6。

## 3. 环境规划

| 环境 | K8s命名空间 | 后端副本 | 资源限制 | 部署方式 |
|:----:|:----------:|:-------:|:--------:|:---------|
| dev | ai-camera-dev | 1 | 256Mi/500m | Git push 自动部署 |
| test | ai-camera-test | 2 | 512Mi/1C | Git push 自动部署 |
| staging | ai-camera-staging | 2 | 512Mi/1C | 手动触发 |
| prod | ai-camera-prod | 3~5(HPA) | 1Gi/2C | 手动审批部署 |

各环境数据库与配置对应关系：

| 环境 | 数据库 | 配置文件 | 服务端口 |
|:----:|:------|:---------|:--------:|
| dev | `ai_camera_dev` | `config/config.yaml` | 8080 |
| test | `ai_camera_test` | `config/config-test.yaml` | 8081 |
| prod | `ai_camera_prod` | `config/config-prod.yaml` | 8080 |

> **注意**：本地后端服务与测试服务端口错开（8080 / 8081），冒烟测试前必须先停止开发服务，避免端口冲突。

## 4. 数据库选型理由

| 特性 | PostgreSQL | MySQL | 说明 |
|:-----|:----------:|:-----:|:-----|
| JSONB | ✅ | 5.7+ | 存储柔性配置与第三方凭据 |
| CTE 递归查询 | ✅ | 8.0+ | 菜单树 / 部门树一次查询展开 |
| 窗口函数 | ✅ | 8.0+ | 风险与告警的同比、时段统计 |
| 部分索引 | ✅ | ❌ | 仅索引未处理告警（`status='pending'`） |
| 时序数据能力 | ✅ TimescaleDB | ❌ | 设备运行历史曲线可平滑升级 |
| 扩展生态 | Citus / PostGIS | 有限 | GIS 查看可扩展 PostGIS 地理检索 |
| GORM 适配成熟度 | ✅ 一等公民 | ✅ | 与本项目 GORM 1.25 + pgx v5 组合稳定 |
| 与现有环境一致 | ✅ | - | 与 boticz-mes 保持同一套数据库与运维经验 |

> **注意**：风险记录 `ac_risk_record` 与告警记录 `ac_alarm_record` 是写入量最大的两张表，`occurred_dt` / `status` 均已建索引；若单表超过千万行，建议按 `occurred_dt` 做月度分区。

## 5. 关键依赖

| 依赖 | 版本要求 | 说明 |
|:-----|:-------:|:-----|
| Go | >= 1.26 | 泛型、`for range` 整数、`pgx` v5 兼容 |
| Node.js | >= 20 LTS | 前端与 Electron 构建 |
| Flutter | >= 3.44 | 移动端构建（需 Dart 3.9+） |
| PostgreSQL | >= 16 | 主库，需 `pgcrypto`（bcrypt 由应用层实现，非必需） |
| Docker | >= 24 | 镜像构建与本地联调 |
| kubectl | >= 1.28 | K8s 环境运维 |
| Redis | >= 7 | 预留：验证码、令牌黑名单、实时推送 |
