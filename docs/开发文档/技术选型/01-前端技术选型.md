## 4. API请求封装

所有 API 调用统一走生成的 Controller 静态方法（如 `DeviceController.pageDevices()`），
Controller 内部使用 `src/admin/api/request.ts` 这一个 Axios 实例。

```typescript
// src/admin/api/request.ts
import axios from 'axios'
import { message } from 'antd'

const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE || '', // 开发环境由 Vite 代理 /web、/app 到 :8080
  timeout: 30000,
  headers: { 'Content-Type': 'application/json' },
})

// ── 请求拦截器：注入 Bearer Token ──
// 从 localStorage 读取而非 store，保证 React 挂载前发起的请求也能带上凭证。
request.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// ── 响应拦截器：拆包 + 统一错误提示 ──
request.interceptors.response.use(
  // 后端统一返回 { code, message, data }，此处拆掉外层信封，
  // 使调用方拿到 BaseResponse 形态的对象。
  (res) => res.data,
  (err) => {
    if (err.response?.status === 401) {
      localStorage.removeItem('token')
      // 保留 vite base 前缀（如 /admin/），避免跳转到不存在的 /login
      window.location.href = `${import.meta.env.BASE_URL || '/'}login`
    } else {
      message.error(err.response?.data?.message || '请求失败')
    }
    return Promise.reject(err)
  }
)

export default request
```

> **注意**：`401` 采用 `window.location.href` 硬跳转而非前端路由跳转，原因是拦截器运行在 React 组件树之外，拿不到 Router 上下文；硬跳转会丢弃内存态，恰好满足"鉴权失效必须重置应用状态"的要求。
> 跳转地址拼接了 `import.meta.env.BASE_URL`（管理后台为 `/admin/`），否则会跳到站点根下的 `/login` 而落到官网页面。

## 5. 三形态构建

同一套源码产出三种形态：管理后台（Web）、官网介绍页（Web）、桌面端（Electron）。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│src/ 源码层                                                               │
│  admin（管理后台） ｜ website（官网介绍页） ｜ shared（共享工具）        │
│   │                        │                          │                  │
│   │ index.html             │ website.html             │ 复用             │
│   ▼                        ▼                          ▼                  │
│ ┌───────────────────┐ ┌────────────────────────┐ ┌─────────────────────┐ │
│ │  vite.config.ts   │ │ vite.website.config.ts │ │vite.renderer.config.ts││
│ │  base: /admin/    │ │  base: /               │ │ base: ./（file://） │ │
│ │  产物: dist/      │ │  产物: dist-website/   │ │ 产物: .vite/renderer│ │
│ │  BrowserRouter    │ │  （官网无路由）        │ │  HashRouter         │ │
│ └───────────────────┘ └────────────────────────┘ └─────────────────────┘ │
│    ── Web 构建（双配置）──                      ── Electron 构建 ──      │
└──────────────────────────────────────────────────────────────────────────┘
```

| 维度 | Web（admin） | Web（website） | Electron（renderer） |
|:-----|:-------------|:---------------|:---------------------|
| 构建配置 | `vite.config.ts` | `vite.website.config.ts` | `vite.renderer.config.ts` |
| HTML 入口 | `index.html` | `website.html` | `index.html` |
| base | `/admin/` | `/` | `./`（`file://` 协议，由 forge 插件注入） |
| 产物目录 | `dist/` | `dist-website/` | `.vite/renderer/main_window/` |
| 开发端口 | 5173 | 5174 | 5199 |
| 路由模式 | `BrowserRouter basename="/admin"` | — | `HashRouter` |
| 判定常量 | `__IS_ELECTRON__ === false` | `__IS_ELECTRON__ === false` | `__IS_ELECTRON__ === true` |

Electron 侧另有 `vite.main.config.ts`（主进程）与 `vite.preload.config.ts`（预加载脚本），
二者均把 `electron` 模块标记为 `external`（由运行时提供），产物输出到 `.vite/build/`。

**路由模式切换**：桌面端页面以 `file://` 协议加载，`BrowserRouter` 的 history API 不可用，
因此通过编译期常量 `__IS_ELECTRON__` 在构建时静态选择路由实现。
路由表本身集中在 `src/admin/App.tsx`：

```typescript
// src/admin/App.tsx（片段）
declare const __IS_ELECTRON__: boolean

/** 桌面端（Electron 渲染进程）标识，由各 vite 配置的 define 注入 */
const IS_ELECTRON = typeof __IS_ELECTRON__ !== 'undefined' && __IS_ELECTRON__

export default function App() {
  return (
    <ConfigProvider locale={zhCN} componentSize="small" theme={{ token: { fontSize: 12 } }}>
      <AntdApp>
        {IS_ELECTRON ? (
          <HashRouter>
            <Suspense fallback={<PageLoading />}>
              <AppRoutes />
            </Suspense>
          </HashRouter>
        ) : (
          <BrowserRouter basename="/admin">
            <Suspense fallback={<PageLoading />}>
              <AppRoutes />
            </Suspense>
          </BrowserRouter>
        )}
      </AntdApp>
    </ConfigProvider>
  )
}
```

```typescript
// vite.renderer.config.ts（片段）
export default defineConfig({
  plugins: [react(), removeCrossorigin()], // 去除 crossorigin，否则 file:// 下 ES 模块加载失败
  define: {
    __IS_ELECTRON__: 'true',
  },
  // 不显式设置 base —— forge 的 vite 插件会注入相对 base（'./'）以适配 file:// 加载
})
```

## 6. 桌面端打包

打包工具为 **electron-forge**（配置见 `forge.config.ts`），不使用 electron-builder 直接编排流程。

```text
electron-forge make
      │
      ├── VitePlugin ──▶ 主进程 .vite/build/main.js ／ 预加载 .vite/build/preload.js
      │                  渲染进程 .vite/renderer/main_window/
      │
      └── makers
            ├── @felixrieseberg/electron-forge-maker-nsis   → Windows NSIS 安装包
            ├── @electron-forge/maker-dmg                   → macOS DMG（ULFO）
            ├── @electron-forge/maker-deb / maker-rpm       → Linux DEB / RPM
            └── @electron-forge/maker-zip                   → macOS 便携 ZIP
```

- NSIS 的 maker 仅负责把 `getAppBuilderConfig` 透传给 electron-builder，
  真正的安装器参数（`oneClick` / `allowToChangeInstallationDirectory` 等）写在 `package.json` 的 `build.nsis`。
- 打包命令：`npm run make:win` / `make:mac` / `make:linux`；仅打包不产出安装器时用 `npm run package:desktop`。
- 主进程为**无边框窗口**（`frame: false` + `titleBarStyle: 'hidden'`），标题栏由渲染层 `MainLayout` 自绘；
  外部链接一律交由系统浏览器打开（`setWindowOpenHandler` + `shell.openExternal`）。

> **注意**：管理后台与官网共享 `src/shared`（工具函数），但**不共享**状态与路由；
> 两个入口各自独立挂载、独立构建，避免官网打包体积被中后台依赖（Ant Design、ECharts）拖累。
