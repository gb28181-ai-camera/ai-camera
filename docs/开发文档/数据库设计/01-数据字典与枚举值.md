# 数据字典与枚举值

> 版本: v0.1.0
> 最后更新: 2026-09-21
> 范围: 全部状态码、类型码与枚举值，取值以 `backend/internal/model/*.go` 的常量定义为准

## 1. 枚举状态码汇总

### 1.1 设备状态

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_device.status` | `online` | 在线：最近一次心跳在超时阈值内 |
| | `offline` | 离线：心跳超时（阈值见 `ac_system_config.device_heartbeat_timeout`） |
| `ac_device_history.status` | `online` | 采样时刻设备在线 |
| | `offline` | 采样时刻设备离线 |

> **注意**：`ac_device.status` 默认值为 `offline`，设备首次注册后需收到心跳才会转为 `online`。

### 1.2 风险处理状态

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_risk_record.status` | `pending` | 未处理（默认值） |
| | `handled` | 已处理；人工确认「检测准确=否」的误报也直接置为该状态 |

状态流转（对应操作手册「AI风险」章节）：

```
设备识别风险
   └──▶ status=pending, read=false
          ├── 人工确认「检测准确=否」（误报）
          │      └──▶ status=handled, read=true, detect_accurate=no
          └── 人工确认「检测准确=是」
                 └──▶ read=true, detect_accurate=yes, status 仍为 pending
                        └── 点击「处理」填写处理结果与图片
                               └──▶ status=handled, handler/handled_dt 落库
```

### 1.3 检测准确性

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_risk_record.detect_accurate` | `yes` | 检测准确，风险成立，需进入处理流程 |
| | `no` | 误报，直接置 `status=handled` 并标记已读 |
| | （空串） | 待人工确认的初始值 |

`ac_risk_record.accurate_by` / `accurate_dt` 记录确认人与确认时间。

### 1.4 告警处理状态

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_alarm_record.status` | `pending` | 未处理（默认值） |
| | `handled` | 已处理 |
| `ac_alarm_record.read` | `true` | 消息通知已读 |
| | `false` | 未读（默认值） |

告警来源为设备自身状态，按 `ac_alarm_type.code` 区分：

| `ac_alarm_type.code` | 说明 | 默认等级 |
|:--------------------:|:-----|:--------:|
| `offline` | 离线告警：心跳超时 | `high` |
| `battery` | 电量告警：电量低于阈值 | `medium` |
| `traffic` | 流量告警：卡内剩余流量低于阈值 | `medium` |

### 1.5 巡检任务状态

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_inspect_task.status` | `pending` | 待发布（草稿） |
| | `published` | 已发布（待巡检，默认值） |
| | `finished` | 已完成：巡检人提交后任务移除并生成巡检记录 |
| | `canceled` | 已取消 |
| `ac_inspect_record.status` | `finished` | 巡检记录固定为已完成（默认值） |

任务状态流转：

```
pending ──发布──▶ published ──移动端提交──▶ finished（生成 ac_inspect_record）
   │                  │
   └──── 取消 ────────┴──▶ canceled
```

### 1.6 升级计划状态

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_device_upgrade_plan.status` | `pending` | 待升级（定时任务已排期，默认值） |
| | `running` | 升级中 |
| | `done` | 已升级 |
| | `failed` | 升级失败 |
| | `canceled` | 已取消 |
| `ac_device_upgrade_record.status` | `done` | 升级成功（默认值） |
| | `failed` | 升级失败，失败原因写 `error_msg` |
| `ac_device_upgrade_record.upgrade_type` | `now` | 现在升级：立即下发，不产生计划 |
| | `plan` | 定时升级：先生成 `ac_device_upgrade_plan` |

> **注意**：只有选择「定时升级」才会写入 `ac_device_upgrade_plan`；「现在升级」直接写 `ac_device_upgrade_record`。

### 1.7 物联网卡状态

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_iot_card.status` | `normal` | 正常（默认值） |
| | `arrears` | 欠费 |
| | `expired` | 已到期 |
| | `disabled` | 已停用 |

流量三字段口径：`traffic_total`（总额）→ `traffic_used`（已用）→ `traffic_left`（剩余），
单位均为 MB，统计时间记录在 `stat_dt`。

### 1.8 风险/告警等级

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_risk_type.level` | `high` | 高风险 |
| | `medium` | 中风险（默认值） |
| | `low` | 低风险 |
| `ac_alarm_type.level` | `high` | 高等级告警 |
| | `medium` | 中等级告警（默认值） |
| | `low` | 低等级告警 |
| `ac_risk_record.risk_level` | `high` / `medium` / `low` | 冗余自 `ac_risk_type.level`，供列表直接展示与分级统计 |
| `ac_alarm_record.alarm_level` | `high` / `medium` / `low` | 冗余自 `ac_alarm_type.level` |

> **注意**：等级为冗余字段，风险类型 / 告警类型调整等级后，**历史记录不会被追溯修改**，
> 以保证已发生的风险与告警以其发生时点的等级参与统计。

### 1.9 数据权限级别

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_role.data_permission` | `all` | 全部数据，不加行级过滤（默认值，超级管理员） |
| | `cross_dept` | 本部门 + `cross_dept_ids` 指定部门 |
| | `dept` | 仅本部门 |
| | `personal` | 仅本人创建的数据 |

`cross_dept_ids` 仅在 `data_permission = cross_dept` 时有意义，存逗号分隔的部门 ID 列表。

过滤规则由 `pkg/utils/data_scope.go` 的 `ApplyToQuery` 实现：

| 取值 | 生成的 SQL 条件 |
|:----:|:----------------|
| `all` | 无 |
| `cross_dept` | `dept_id IN (本部门, cross_dept_ids...)`；列表为空时退化为 `created_by = 当前用户` |
| `dept` | `dept_id = 本部门`；无部门时退化为 `created_by = 当前用户` |
| `personal` | `dept_id = 本部门 AND created_by = 当前用户` |

### 1.10 菜单类型与平台

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_menu.type` | `directory` | 目录：仅用于分组，无组件，不出现在权限校验中 |
| | `menu` | 菜单：对应一个页面，绑定该页面的查询类接口 |
| | `button` | 按钮：页面内的操作点，绑定新增/编辑/删除类接口 |
| `ac_menu.platform` | `pc` | 管理后台（默认值） |
| | `mobile` | 移动端 App |
| `ac_menu.hidden` | `true` | 侧边栏隐藏，仅作权限载体（如「通用能力 → 文件上传」） |
| | `false` | 正常显示（默认值） |

`ac_menu.permission_code` 命名约定：

|:-----|:-----|:-----|

| 新增 | `<域>:create` | `device:create`、`firmware:create` |
| 编辑 | `<域>:update` | `device:update` |
| 删除 | `<域>:delete` | `device:delete` |
| 导出 | `<域>:export` | `log:export` |
| 特殊动作 | `<域>:<动作>` | `risk:handle`、`user:reset-password`、`upgrade-device:cancel` |

### 1.11 通知类型与频率

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_alarm_setting.notify_type` | `app` | APP 推送（个推，默认值） |
| | `sms` | 短信（腾讯云短信） |
| | `inner` | 站内通知（写 `ac_notification`） |
| `ac_risk_notify_setting.notify_type` | `app` / `sms` / `inner` | 同上，维度换成风险类型 |
| `ac_alarm_setting.notify_freq` | `0` | 实时推送（默认值） |
| | `60` | 每小时汇总推送一次 |
| | `1440` | 每天汇总推送一次 |
| `ac_risk_notify_setting.notify_freq` | `0` / `60` / `1440` | 同上 |
| `ac_notification.category` | `alarm` | 来源为设备告警 |
| | `risk` | 来源为 AI 风险 |
| | `inspect` | 来源为巡检任务 |

`notify_user_ids` 为逗号分隔的用户 ID 列表，表示除配置者本人外额外通知的人员。

`ac_thirdparty_config.category` 取值：

| 取值 | 说明 | 配置键 |
|:----:|:-----|:-------|
| `getui` | 个推账号绑定 | `getui_app_id` / `getui_app_key` / `getui_app_secret` / `getui_master_secret` |
| `sms` | 腾讯云短信配置 | `sms_secret_id` / `sms_secret_key` / `sms_sdk_app_id` / `sms_sign_name` |

> **注意**：`ac_thirdparty_config.secret = true` 的配置项（如各类密钥）在接口返回时按脱敏处理，
> 前端只展示不可回填的掩码值。

### 1.12 消息推送

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|
| `ac_webhook_config.platform` | `feishu` | 飞书自定义机器人；报文为 `text` 类型 |
| | `dingtalk` | 钉钉自定义机器人；`secret` 非空时按 HMAC-SHA256 加签（`timestamp + "\n" + secret`） |
| | `wecom` | 企业微信机器人；markdown 类型走 `markdown.content` |
| | `custom` | 自定义 WebHook；推送通用 JSON，便于第三方系统解析 |
| `ac_webhook_config.msg_type` | `text` | 纯文本（字段以「键：值」逐行展开） |
| | `markdown` | markdown（钉钉 / 企业微信生效，含标题、引用字段与详情链接） |
| `ac_webhook_config.event_types` | `risk` | 订阅 AI 风险上报事件 |
| | `alarm` | 订阅设备告警上报事件 |
| | `inspect` | 订阅巡检通知事件 |
| | `device` | 订阅设备上下线事件 |
| | （空串） | 订阅**全部**事件 |
| `ac_webhook_config.last_status` | `success` | 最近一次推送成功 |
| | `failed` | 最近一次推送失败，失败原因写入 `last_error` |

`event_types` 为**逗号分隔**的多值列（如 `risk,alarm`），取值与 `ac_notification.category`
保持同一套语义，便于统一分发。仓储层不使用 `LIKE` 匹配（`risk` 会误命中 `risky`），
而是取回后在内存中精确比对。

> **注意**：`ac_webhook_config.msg_type` 的默认值为 `text`，但服务层 `defaultMsgType()` 会把
> 非 `text` 的取值一律归一为 `markdown`，因此前端下拉只需提供这两个选项。
> `secret` 为空串时归一为 `NULL`；编辑时传入脱敏串（含 `****`）则保持原值不覆盖。

### 1.13 国标视频（GB/T 28181）

| 字段 | 枚举值 | 说明 |
|:-----|:------:|:-----|

| | `activated` | 首次 REGISTER 鉴权通过 |
| | `rejected` | 鉴权失败（Digest 错误等） |
| `ac_device.sip_transport` | `UDP` / `TCP` | SIP 信令传输 |
| `ac_device.stream_mode` | `UDP` | 默认；设备向 ZLM 发 RTP over UDP |
| | `TCP-PASSIVE` | 平台监听，设备主动连；受 ZLM 单端口模式约束 |
| | `TCP-ACTIVE` | 平台主动连设备；**与单端口收流互斥，本期不支持** |
| `ac_device.charset` | `GB2312` | 默认；MANSCDP XML 的声明与内容编码 |
| | `UTF-8` | 部分新设备 |
| `ac_device.gb_version` | `2016` | 默认；GB/T 28181-2016 设备 |
| | `2022` | GB/T 28181-2022 设备；支持 PTZ 精准位置、巡航轨迹、看守位、存储卡状态等新命令 |
| `ac_device.status` / `ac_gb_channel.status` | `online` / `offline` | 设备运行状态（沿用 v0.1.0 取值） |
| `ac_gb_channel.status` | `ON` / `OFF` | 设备侧上报的通道状态（GB28181 原值） |
| `ac_gb_channel` 目录事件 `Event` | `ADD` / `UPDATE` / `ON` | 视为在线（新增/属性更新/上线） |
| | `OFF` / `VLOST` / `DEFECT` | 视为离线（离线/视频丢失/故障） |
| | `DEL` | 视为离线并删除目录项 |
| `ac_gb_subscribe.type` | `catalog` | 目录变更订阅 |
| | `alarm` | 报警订阅 |
| | `mobile_position` | 移动位置订阅 |
| | `ptz_position` | ★ GB/T 28181-2022 PTZ 精准位置变化订阅 |
| `ac_gb_subscribe.status` | `active` / `expired` / `failed` | 订阅状态 |
| `ac_voice_session.type` | `broadcast` | 语音广播 |
| | `talk` | 对讲 |
| | `agent` | 语音 Agent 会话 |
| `ac_voice_session.status` | `active` / `stopped` / `failed` | ★ 是 `stopped` 不是 `ended` |
| `ac_voice_provider.category` | `stt` / `llm` / `tts` / `vad` | provider 字典分类 |
| `ac_gb_alarm.alarm_priority` | `1` | 一级（特急） |
| | `2` | 二级（紧急） |
| | `3` | 三级（一般） |
| | `4` | 四级（其他） |
| `ac_gb_alarm.handled` | `true` / `false` | 是否已处理；处理人复用 `updated_by` |
| `ac_gb_sip_log.direction` | `in` / `out` | 报文方向 |
| `ac_gb_sip_log.result` | `success` / `failed` / `rejected` | ★ 401 Digest 挑战记为 `success`（它是握手第一步，不是拒绝），`rejected` 只给白名单/Digest 失败/方法不支持 |
| `ac_gb_media_server.type` | `zlm` | 节点类型 |
| `ac_gb_media_server.rtp_enable` | `false` | 本项目**单端口模式**标记；为 `true` 表示多端口，与 sipsvc 的实现不符 |

> **单端口模式**：设备统一向 ZLM 的 `rtp_proxy_port`（默认 10000）发包，ZLM 按 RTP 头里的
> SSRC 自动建流；流名是 SSRC 的**大写十六进制**（如 `0BEBC201`）。
> `{deviceId}_{channelId}` 是 WVP 的内部别名，ZLM 不认识。
