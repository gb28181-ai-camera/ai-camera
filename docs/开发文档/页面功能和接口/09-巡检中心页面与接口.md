# 巡检中心 - 页面功能与接口

> 版本: v0.1.0
> 最后更新: 2026-09-21

## 1. 页面列表

| 序号 | 页面名称 | 路由 | 类型 | 说明 |
|:----:|---------|------|:----:|------|
| 1 | 巡检任务管理 | `/inspect/task` | 列表页 | 创建巡检任务并指派巡检人 |
| 2 | 巡检记录 | `/inspect/record` | 列表页 | 巡检人处理完成后产生的记录 |

> **注意**：巡检任务的**完成动作只在移动端**（`PUT /app/inspect-tasks/:id/finish`）发生。
> 管理后台负责创建、编辑、删除任务与查看记录，不提供「完成」按钮。

## 2. 巡检任务管理

### 2.1 页面功能

- **列表字段**：任务名称、所属区域、巡检位置、巡检人、巡检内容、巡检时间（`plan_dt`）、
  状态、消息通知、备注、创建时间。
- **搜索条件**：所属区域（`region_id`）、任务名称关键字（`keyword`）、巡检人（`inspector_id`）、
  巡检时间范围（`start_dt` ~ `end_dt`）、状态（`status`）。
- **新增巡检任务**：点击「新增」，填写任务名称、所属区域、巡检位置、**选择巡检人员**、巡检内容、
  巡检时间与备注。巡检任务发布后，由该巡检人员使用账号登录（管理平台或移动端）进行巡检任务处理。
- **查看**：点击「查看」查看巡检任务的详细信息，且该消息通知**由未读转为已读**（`read = true`）。
- **编辑**：点击「编辑」，可对巡检任务内容进行修改。
- **删除**：点击「删除」并确认删除后，可对该条数据进行删除；点「取消」则取消删除。
- **状态流转**：
  - `pending` — 待发布；
  - `published` — 已发布（待巡检），任务创建后默认状态；
  - `finished` — 已完成，巡检人在移动端提交后，该巡检任务从任务列表中移除并生成一条巡检记录；
  - `canceled` — 已取消。
- **通知人**：任务指派后在巡检人账号中生成一条 `category = inspect` 的系统通知。
- **数据权限**：列表按 `dept_id` 施加行级过滤，巡检人只能在移动端看到指派给自己的任务。

> **注意**：`InspectorID` 为巡检人用户 ID，下拉数据来自 `GET /web/system/users/options`。

### 2.2 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/web/inspects/tasks` | 巡检任务分页列表 |
| GET | `/web/inspects/tasks/:id` | 巡检任务详情 |
| POST | `/web/inspects/tasks` | 新增巡检任务 |
| PUT | `/web/inspects/tasks/:id` | 编辑巡检任务 |
| PUT | `/web/inspects/tasks/:id/read` | 标记巡检任务消息通知已读（「查看」触发） |
| DELETE | `/web/inspects/tasks/:id` | 删除巡检任务 |
| GET | `/web/basic/regions/options` | 所属区域下拉选项 |
| GET | `/web/system/users/options` | 巡检人下拉选项 |

### 2.3 接口数据格式

**GET /web/inspects/tasks**

请求参数：

```json
{
  "page": 1,
  "page_size": 20,
  "keyword": "北门",
  "region_id": 1,
  "inspector_id": 2,
  "status": "published",
  "start_dt": "2026-09-01 00:00:00",
  "end_dt": "2026-09-30 23:59:59"
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|:----:|---|
| `page` / `page_size` | int | 否 | 分页参数，默认 1 / 20 |
| `keyword` | string | 否 | 匹配任务名称 |
| `region_id` | int64 | 否 | 所属区域 |
| `inspector_id` | int64 | 否 | 巡检人用户 ID |
| `status` | string | 否 | `pending` / `published` / `finished` / `canceled` |
| `start_dt` / `end_dt` | string | 否 | 巡检时间（`plan_dt`）范围 |

响应数据：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "items": [
      {
        "id": 301,
        "active": true,
        "name": "北门区域周巡检",
        "region_id": 1,
        "location": "北门入口及周边立杆",
        "inspector_id": 2,
        "content": "检查设备外观、供电、镜头遮挡与线缆固定情况",
        "plan_dt": "2026-09-22T09:00:00+08:00",
        "status": "published",
        "read": false,
        "remark": "",
        "region": { "id": 1, "name": "北门区域", "code": "REG001" },
        "created_by": "admin",
        "created_dt": "2026-09-20T15:00:00+08:00"
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20
  }
}
```

> **注意**：`region.name` 为关联名称字段，列表必须展示区域名称而非仅 `region_id`。
> `inspector_id` 对应的用户名由前端结合用户下拉选项（`code` 为登录名）渲染，或由响应中的冗余字段辅助展示。

**GET /web/inspects/tasks/:id**

请求参数：路径参数 `id`（任务 ID）。

响应数据（`RInspectTask`）：单条巡检任务对象，结构同列表条目。

**POST /web/inspects/tasks**

请求参数：

```json
{
  "name": "北门区域周巡检",
  "region_id": 1,
  "location": "北门入口及周边立杆",
  "inspector_id": 2,
  "content": "检查设备外观、供电、镜头遮挡与线缆固定情况",
  "plan_dt": "2026-09-22 09:00:00",
  "status": "published",
  "remark": "",
  "active": true
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|:----:|---|
| `name` | string | 是 | 任务名称 |
| `region_id` | int64 | 是 | 所属区域 |
| `inspector_id` | int64 | 是 | 巡检人用户 ID |
| `content` | string | 是 | 巡检内容 |
| `plan_dt` | string | 是 | 巡检时间 |
| `location` | string | 否 | 巡检位置 |
| `status` | string | 否 | 缺省 `published` |
| `remark` | string | 否 | 备注 |

响应数据：返回新建的巡检任务对象。

**PUT /web/inspects/tasks/:id**

请求参数：同新增（可只提交需修改的字段）。

响应数据：

```json
{ "code": 200, "message": "success", "data": null }
```

**PUT /web/inspects/tasks/:id/read**

标记该巡检任务的消息通知为已读（页面「查看」动作触发，对应 §2「查看」条目）。重复调用幂等（已读时不再写库）；任务不存在返回 404「巡检任务不存在」。

请求参数：路径参数 `id`。

响应数据（`RBool`）：

```json
{ "code": 200, "message": "success", "data": true }
```

**DELETE /web/inspects/tasks/:id**

请求参数：路径参数 `id`。

响应数据：

```json
{ "code": 200, "message": "success", "data": null }
```

> **注意**：任务删除为软删除；已生成巡检记录的任务被删除后，记录仍可独立查看
> （记录内保留了任务快照字段 `task_name` / `region_id` / `location` / `inspector` / `content`）。

## 3. 巡检记录

### 3.1 页面功能

- **列表字段**：任务名称、所属区域、巡检位置、巡检人、巡检内容、巡检时间、处理结果图、处理时间、处理结果、状态。
- **搜索条件**：所属区域（`region_id`）、任务名称关键字（`keyword`）、巡检人（`inspector_id`）、
  处理时间范围（`start_dt` ~ `end_dt`）。
- **数据产生时机**：被指派的巡检人员处理完巡检任务后，巡检记录模块中才会产生已处理的巡检记录。
  管理后台**不会**直接新增记录，记录只能由移动端 `PUT /app/inspect-tasks/:id/finish` 触发产生。
- **查看**：点击「查看」，可查看巡检记录的详情信息或处理图片（`result` 与 `result_image`）。
- **快照保留**：记录保留任务快照字段（任务名称、区域、位置、巡检人、内容），
  因此任务被编辑或删除后记录仍可独立查看。
- **处理结果图**：`result_image` 由移动端拍照或选择图片后上传（`POST /web/upload`）得到。
- **状态**：记录生成后 `status = finished`。
- **只读**：记录为**只读**数据，管理后台不提供编辑与删除端点。

> **注意**：记录中的 `inspector` 是提交时的巡检人姓名快照，`inspector_id` 为对应用户 ID。

### 3.2 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/web/inspects/records` | 巡检记录分页列表 |
| GET | `/web/inspects/records/:id` | 巡检记录详情 |
| GET | `/web/basic/regions/options` | 所属区域下拉选项 |
| GET | `/web/system/users/options` | 巡检人下拉选项 |

### 3.3 接口数据格式

**GET /web/inspects/records**

请求参数：

  "page_size": 20,

  "inspector_id": 2,
  "start_dt": "2026-09-01 00:00:00",
  "end_dt": "2026-09-30 23:59:59"

响应数据：

```json

  "message": "success",
  "data": {
    "items": [
      {
        "id": 501,
        "task_id": 301,
        "task_name": "北门区域周巡检",
        "region_id": 1,
        "location": "北门入口及周边立杆",
        "inspector_id": 2,
        "inspector": "张三",
        "content": "检查设备外观、供电、镜头遮挡与线缆固定情况",
        "plan_dt": "2026-09-22T09:00:00+08:00",
        "result": "设备外观完好，供电正常，镜头有少量灰尘已清洁",
        "result_image": "/uploads/inspect/20260922/a.jpg",
        "handled_dt": "2026-09-22T09:25:00+08:00",
        "status": "finished",
        "region": { "id": 1, "name": "北门区域", "code": "REG001" },
        "created_dt": "2026-09-22T09:25:00+08:00"
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20
  }

```

| 字段 | 类型 | 说明 |
|---|---|---|
| `task_id` | int64 | 来源巡检任务 ID |
| `task_name` | string | 任务名称（快照，任务改名后不变） |
| `region_id` / `region.name` | int64 / string | 所属区域 ID 与**区域名称** |
| `inspector_id` / `inspector` | int64 / string | 巡检人 ID 与**巡检人姓名快照** |
| `plan_dt` | time | 计划巡检时间（取自任务） |

| `handled_dt` | time | 处理（提交）时间 |

**GET /web/inspects/records/:id**

请求参数：路径参数 `id`（记录 ID）。

响应数据（`RInspectRecord`）：单条巡检记录对象，结构同列表条目。

> **注意**：巡检记录详情弹窗同时展示「处理结果图」与「任务快照信息」，
> 图片地址直接取 `result_image`，无需额外接口。

## 4. 任务状态流转

```
管理员新增任务
      │
      ▼
  published（已发布，待巡检）
      │  巡检人账号收到 category=inspect 系统通知
      │
      ├── 巡检人在移动端提交处理结果 + 处理结果图
      │        PUT /app/inspect-tasks/:id/finish
      │        → 任务 status = finished（从任务列表移除）
      │        → 生成一条 InspectRecord（status = finished）
      │
      └── 管理员取消 → canceled
```

| 状态 | 取值 | 说明 |
|---|---|---|
| 待发布 | `pending` | 已创建未发布 |
| 已发布 | `published` | 待巡检，任务默认状态 |
| 已完成 | `finished` | 已转巡检记录 |
| 已取消 | `canceled` | 已取消 |
