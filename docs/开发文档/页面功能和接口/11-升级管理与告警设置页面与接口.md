## 2. 设备升级管理

设备升级管理页由三个 Tab 组成：**升级设备**、**升级计划**、**升级记录**。

### 2.1 页面功能

**Tab 1：升级设备**

- **远程升级**：对设备的**固件**与**AI 模型**进行远程升级，支持「现在升级」与「定时升级」两种方式，
  并支持勾选多条设备进行**批量升级**。
- **搜索条件**：所属区域（`region_id`）、设备名称（`keyword`）、设备编号（`device_code`）、
  固件（`firmware_id`）、设备模式（`device_mode`）。
- **现在升级**：提交后立即下发升级指令，升级成功后会在「升级记录」中增加一条升级记录。
- **定时升级**：提交后在「升级计划」中生成一条定时升级任务，可点击「取消升级」取消该任务。
- **批量升级**：勾选一条或多条设备后点击「批量升级」，对所选设备统一下发同一固件/模型。
- **升级内容**：可选择仅升级固件、仅升级模型，或两者同时升级；两者都不选则提交失败。

**Tab 2：升级计划**

- **产生时机**：对设备进行定时升级时，升级计划中才会产生相应设备的升级任务。
- **列表字段**：设备名称、设备编号、所属区域、设备位置、升级固件、升级模型、升级时间、状态、备注。
- **搜索条件**：固件名称（`firmware_id` / `keyword`）、设备名称/编号、所属区域、状态、升级时间范围。
- **取消升级**：点击「取消升级」取消该条定时升级任务，状态置为 `canceled`。
- **批量取消升级**：选择一条或多条数据可进行批量取消升级操作。
- **状态取值**：`pending` 待升级 / `running` 升级中 / `done` 已升级 / `failed` 升级失败 / `canceled` 已取消。

**Tab 3：升级记录**

- **产生时机**：对设备进行升级后，升级记录中就会产生相应的设备升级记录。
- **列表字段**：设备名称、设备编号、所属区域、设备位置、流量卡、上一固件、上一模型、升级固件、
  升级模型、升级时间、升级方式、结果、操作人。
- **上一版本**：对同一设备升级**两次**后，上一固件（`prev_firmware_ver`）和上一模型（`prev_ai_model_ver`）
  中才会显示上一次升级的固件/模型；首次升级时为空。
- **搜索条件**：设备名称（`keyword`）、设备编号（`device_code`）、操作时间范围（`start_dt` ~ `end_dt`）、
  所属区域。

> **注意**：升级计划与升级记录均为**只读历史数据**，仅升级计划支持「取消」操作。

### 2.3 接口数据格式

**POST /web/upgrades/devices**

请求参数：

```json
{
  "device_ids": [5, 6, 7],
  "upgrade_type": "plan",
  "firmware_id": 2,
  "model_id": 3,
  "plan_dt": "2026-09-23 02:00:00",
  "remark": "夜间低峰期升级"
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|:----:|---|
| `device_ids` | int64[] | 是 | 设备 ID 列表，一条即为单设备升级，多条为批量升级 |
| `upgrade_type` | string | 是 | `now` 现在升级 / `plan` 定时升级 |
| `firmware_id` | int64 | 否 | 升级固件 ID，与 `model_id` 至少填一个 |
| `model_id` | int64 | 否 | 升级模型 ID，与 `firmware_id` 至少填一个 |
| `plan_dt` | string | 条件 | `upgrade_type = plan` 时必填，升级时间 |
| `remark` | string | 否 | 备注 |

响应数据（`RUpgradeDevices`）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "upgrade_type": "plan",
    "device_count": 3,
    "record_ids": [],
    "plan_ids": [101, 102, 103]
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `device_count` | int | 命中的设备数 |
| `record_ids` | int64[] | `now` 方式产生的升级记录 ID 列表 |
| `plan_ids` | int64[] | `plan` 方式产生的升级计划 ID 列表 |

> **注意**：`upgrade_type = now` 时 `plan_ids` 为空且不写入 `plan_dt`；
> `upgrade_type = plan` 时 `record_ids` 为空，升级真正执行后才写入升级记录。

## 3. 固件管理

### 3.1 页面功能

- **列表字段**：固件名称、固件类型、适用模型、固件文件、版本号、文件大小、MD5、上一版本描述、描述、发布时间、创建时间。
- **搜索条件**：固件名称关键字（`keyword`）、固件类型（`firmware_type_id`）。
- **新增固件**：点击「新增」录入固件信息，其中**固件类型**中数据与固件类型管理中的数据相关联。
- **上传固件文件**：调用 `POST /web/upload` 上传固件包，回填 `file_url`、`file_size`、`md5`。
- **下载固件**：点击「下载固件」，下载固件文件（`file_url`）。
- **编辑固件**：点击「编辑」，可修改固件信息。
- **删除固件**：删除前二次确认。已被升级计划/记录引用的固件不建议删除。
- **下拉数据源**：固件选项（`GET /web/upgrades/firmwares/options`）供「升级设备」「模型管理」使用。

### 3.2 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/web/upgrades/firmwares` | 固件分页列表 |
| GET | `/web/upgrades/firmwares/options` | 固件下拉选项 |
| GET | `/web/upgrades/firmwares/:id` | 固件详情 |
| POST | `/web/upgrades/firmwares` | 新增固件 |
| PUT | `/web/upgrades/firmwares/:id` | 编辑固件 |
| DELETE | `/web/upgrades/firmwares/:id` | 删除固件 |
| GET | `/web/upgrades/firmware-types/options` | 固件类型下拉选项 |

## 4. 模型管理

### 4.1 页面功能

- **列表字段**：模型名称、适用固件、模型文件、版本号、文件大小、MD5、描述、发布时间、创建时间。
- **搜索条件**：模型名称关键字（`keyword`）、适用固件（`firmware_id`）。
- **新增模型**：点击「新增」录入模型信息。**选择适用固件中数据与固件管理中的数据相关联**，
  即模型必须绑定一个已存在的固件版本。
- **上传模型文件**：调用 `POST /web/upload` 上传模型文件，回填 `file_url`、`file_size`、`md5`。
- **下载模型**：点击「下载模型」，下载模型文件。
- **编辑模型**：点击「编辑」，可修改模型信息（含更换适用固件）。
- **删除模型**：删除前二次确认。

> **注意**：模型与固件是**多对一**关系——一个模型只绑定一个固件版本，一个固件下可以有多个模型。
> 升级设备时若只选了模型未选固件，平台会按模型的适用固件校验设备当前固件是否兼容。

### 4.2 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|

| GET | `/web/upgrades/models/options` | 模型下拉选项 |
| GET | `/web/upgrades/models/:id` | 模型详情 |
| POST | `/web/upgrades/models` | 新增模型 |
| PUT | `/web/upgrades/models/:id` | 编辑模型 |
| DELETE | `/web/upgrades/models/:id` | 删除模型 |
| GET | `/web/upgrades/firmwares/options` | 适用固件下拉选项 |

- **搜索条件**：固件类型关键字（`keyword`）、状态（`active`）。

- **下拉数据源**：`GET /web/upgrades/firmware-types/options` 供「固件管理」新增表单使用。

## 6. 设备告警设置

### 6.1 页面功能

- **配置范围**：可配置告警类型（离线告警、电量告警、流量告警）的**通知人员**、**通知类型**及**报警频率**。

## 10. 消息推送配置

### 10.1 页面功能

- **通道列表**：分页展示全部 WebHook 通道，列出行序号、配置名称、平台、消息格式、
  订阅事件、WebHook 地址、启用状态、最近发送结果与备注。
- **新增 / 编辑通道**：弹窗表单填写配置名称、平台、WebHook 地址、签名密钥、
  消息格式、订阅事件、排序、启用状态与备注；四个平台共用同一张表单，
  仅「签名密钥」的提示文案随平台变化（钉钉为加签密钥，飞书 / 企业微信可留空）。
- **平台下拉**：平台选项由 `GET /webhooks/platforms` 动态返回（飞书 / 钉钉 / 企业微信 / 自定义 WebHook），
  前端不硬编码。
- **启用 / 停用**：列表内直接切换，停用后 `Dispatch` 不再向其下发消息。
- **测试推送**：对**已保存**的通道调用 `POST /webhooks/:id/test` 实时下发一条测试消息；
  失败原因在响应 `data.message` 中回显，便于直接定位（地址错误 / 加签失败 / 平台错误码）。
- **即时测试**：新增弹窗中可先对**未保存**的表单内容调用 `POST /webhooks/test` 验证连通性，通过后再保存。
- **通道健康度可见**：列表直接展示 `last_send_dt` / `last_status` / `last_error` 三个快照字段，
  无需进入详情即可发现推送失败。
- **删除**：软删除（写 `deleted_at`），删除前需二次确认。

> **注意**：WebHook 配置是**平台级**配置（不按部门隔离），由系统管理员统一维护；
> 因此仓储层不施加数据权限过滤，任何登录用户看到的都是同一份通道列表。
> 这与「设备告警设置 / 风险通知设置」按 `user_id` 隔离的语义不同。

> `event_types` 是**逗号分隔字符串**（如 `"risk,alarm"`）。服务层 `joinEvents()` 负责转换，
> 并顺带剔除非法取值；传入空数组即写入空串，语义为「订阅全部」。

**PUT /web/settings/webhooks/:id**

请求参数（`request.UpdateWebhookReq`）：字段与新增一致。

响应数据：

```json
{ "code": 200, "message": "success", "data": true }
```

> **注意**：`secret` 传空或传脱敏串（含 `****`）时**保持原值不覆盖**，
> 避免把掩码写进数据库。`active` 为 `nil` 时同样保持原值。

**DELETE /web/settings/webhooks/:id**

请求参数：路径参数 `id`。

响应数据：

```json
{ "code": 200, "message": "success", "data": true }
```

**PUT /web/settings/webhooks/:id/enable**、**PUT /web/settings/webhooks/:id/disable**

请求参数：路径参数 `id`。均为无请求体。

响应数据：

```json
{ "code": 200, "message": "success", "data": true }
```

**POST /web/settings/webhooks/:id/test**

请求参数：路径参数 `id`；请求体可省略，省略时使用默认测试文案。

```json
{
  "title": "自定义测试标题",
  "content": "自定义测试正文"
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|:----:|---|
| `title` | string | 否 | 测试消息标题；为空时取「WebHook 连通性测试」 |
| `content` | string | 否 | 测试消息正文；为空时取默认文案 |

响应数据（`RWebhookTest`）：

```json
{
  "code": 200,
  "message": "success",
  "data": { "success": true, "message": "测试消息已发送，请到对应群聊确认" }
}
```

推送失败时 `code` 仍为 200，但 `data.success = false`，失败原因在 `data.message` 中：

```json
{
  "code": 200,
  "message": "success",
  "data": { "success": false, "message": "钉钉返回错误 errcode=310000 errmsg=sign not match" }
}
```

> **注意**：即使推送失败，本接口也会把结果写入通道的 `last_status` / `last_error`，
> 因此测试后刷新列表即可看到该通道的健康度变化。

**POST /web/settings/webhooks/test**

请求参数（`request.TestWebhookInlineReq`）：与新增配置一致，另可附带 `title` / `content`。

```json
{
  "name": "临时验证",
  "platform": "custom",
  "url": "https://example.com/hook",
  "msg_type": "text",
  "event_types": ["alarm"],
  "title": "连通性验证",
  "content": "这是一条即时测试消息"
}
```

响应数据（`RWebhookTest`）：同 `POST /webhooks/:id/test`。
本接口**不落库、不更新任何通道状态**，仅用于保存前验证地址与密钥是否正确。

**自定义平台（`platform = custom`）的推送报文**

自定义平台推送通用 JSON，便于第三方系统直接解析：

```json
{
  "event": "alarm",
  "event_label": "设备告警",
  "title": "离线告警",
  "content": "设备 东门摄像头 于 2026-09-21 10:30:12 触发告警",
  "fields": {
    "告警类型": "离线告警",
    "告警等级": "high",
    "设备名称": "东门摄像头",
    "设备编号": "CAM_001",
    "设备位置": "厂区东门",
    "发生时间": "2026-09-21 10:30:12",
    "处理状态": "未处理"
  },
  "occurred_dt": "2026-09-21 10:30:12"
}
```

`event_label` 取值由事件类型决定：`risk` → `AI风险`、`alarm` → `设备告警`、
`inspect` → `巡检通知`、`device` → `设备状态`。

### 10.4 平台报文差异

| 平台 | 报文格式 | 加签 | 备注 |
|:-----|:---------|:-----|:-----|
| `feishu` | `{"msg_type":"text","content":{"text":"..."}}` | 不需要 | 校验响应 `code` / `StatusCode` 是否为 0 |
| `dingtalk` | `text` 或 `{"msgtype":"markdown","markdown":{"title","text"}}` | `secret` 非空时启用 | HMAC-SHA256（`timestamp + "\n" + secret`），base64 后 URL 编码拼到 `timestamp` / `sign` 查询参数；校验 `errcode` |
| `wecom` | `text` 或 `{"msgtype":"markdown","markdown":{"content":"..."}}` | 不需要 | 校验 `errcode` |
| `custom` | 通用 JSON（见上） | 可选 | 不解析业务错误码，仅看 HTTP 状态码 |

> **注意**：钉钉加签会使最终 URL 显著变长，因此 `url` 列长度设为 1000。
> 飞书 / 企业微信在 HTTP 200 下仍可能返回业务错误码，实现中会额外解析响应体。

## 11. 升级与告警状态取值对照

| 维度 | 取值 | 说明 |
|---|---|---|
| 升级计划状态 | `pending` | 待升级 |
| 升级计划状态 | `running` | 升级中 |
| 升级计划状态 | `done` | 已升级 |
| 升级计划状态 | `failed` | 升级失败 |
| 升级计划状态 | `canceled` | 已取消 |
| 升级方式 | `now` / `plan` | 现在升级 / 定时升级 |
| 通知类型 | `app` / `sms` / `inner` | APP 推送 / 短信 / 站内通知 |
| 报警频率 | `0` / `60` / `1440` | 实时 / 每小时 / 每天（分钟） |
| 推送平台 | `feishu` / `dingtalk` / `wecom` / `custom` | 飞书 / 钉钉 / 企业微信 / 自定义 WebHook |
| 推送消息格式 | `text` / `markdown` | 纯文本 / markdown（钉钉、企业微信生效） |
| 推送订阅事件 | `risk` / `alarm` / `inspect` / `device` | 空值表示订阅全部事件 |
| 推送最近结果 | `success` / `failed` | 最近一次推送成功 / 失败 |
