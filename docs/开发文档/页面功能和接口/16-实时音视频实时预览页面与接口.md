# 实时音视频 - 实时预览（MQTT 房间信令）

> 版本：v0.6.0
> 最后更新：2026-10-25
> 页面：`/av/preview`（实时音视频 → 实时预览）

## 1. 目标与拓扑

在管理后台直接查看「WebRTC 服务组」设备的实时画面。信令走 MQTT，
媒体由设备与浏览器点对点传输（NAT 受限时经 TURN），后端不转发音视频。

```
浏览器 ──WebSocket──▶ Go /web/av/ws
                         │
                         ├─ publish  iot/<group>/device/<device_code>/signal
                         ▼
                     MQTT broker
                         ▲
设备 ──subscribe─────────┘
设备 ──publish iot/<group>/signal/backend──▶ Go（room_id 非空）

媒体：浏览器 ◀════ DTLS/SRTP（P2P 或 TURN） ════ 设备
```

- 后端只做**信令中继与身份校验**，不解析 SDP、不碰 RTP/PS。
- 浏览器不直连 MQTT，避免把产品级 MQTT 凭据暴露给前端。
- 设备使用「产品 × MQTT 服务」凭据（与 IOT/OTA 下发的一致）。

## 2. 话题约定

| 方向 | 话题 | 说明 |
|:--|:--|:--|
| 设备订阅 | `iot/<group_code>/device/<device_code>/signal` | 接收 joinRoom / answer / iceCandidate / leaveRoom |
| 设备发布 | `iot/<group>/signal/backend` | 发送 joinRoom / offer / iceCandidate / leaveRoom（`room_id` 必填） |
| 后端发布 | `iot/<group>/device/<device_code>/signal` | 平台账号 `__platform__`，ACL 已放行 |
| 浏览器 | `ws(s)://<host>/web/av/ws?ticket=...` | 一次性 ticket，60 秒 |

`room_id` 固定等于 `device_code`。一条消息是否属于房间信令，以
`room_id` 是否为空判断；旧 App → ZLM WHEP 的 offer 没有 `room_id`，
因此两条链路可以共用同一个后端话题。

## 3. 消息结构

统一 JSON，用 `type` 区分：

```json
{
  "type": "joinRoom | offer | answer | iceCandidate | leaveRoom | ready | error | invite | agree | reject | hangup",
  "room_id": "CAM_001",
  "device_code": "CAM_001",
  "client_id": "viewer-1a2b3c4d",
  "to": "device-CAM_001",
  "role": "viewer | device",
  "sdp": "v=0...",
  "sdp_type": "offer | answer",
  "candidate": {
    "candidate": "candidate:...",
    "sdpMid": "0",
    "sdpMLineIndex": 0,
    "usernameFragment": "..."
  },
  "call_id": "device-call-173459",
  "media_type": "video | audio",
  "reason": "user_closed",
  "code": "invalid_message",
  "message": "错误说明",
  "device_online": true
}
```

服务端会覆盖 `room_id / device_code / client_id / role`，不信任浏览器
自填的身份字段。

## 4. 握手顺序

```
1. 查看方打开页面 → POST /web/av/devices/:id/viewer-ticket
      ← ticket + ws_url + client_id + room_id + ice_servers
2. 浏览器连 /web/av/ws
      ← {"type":"ready","client_id":"viewer-...","device_online":true}
3. 浏览器 → joinRoom
4. 设备收到 → 回 joinRoom（带 to=viewer）
5. 浏览器收到设备的 joinRoom → 再发一次 joinRoom
6. 设备收到第二次 joinRoom → 创建 PeerConnection、发 offer
7. 浏览器 setRemoteDescription → createAnswer → 发 answer
8. 双方 trickle iceCandidate；设备中途可再次发 offer（ICE restart）
9. 关闭页面/点断开 → leaveRoom；设备关闭对应 PeerConnection
```

设备是**固定 offer 方**，浏览器只 answer。查看方收到设备重新 offer 时，
页面在非 stable 状态先 `rollback` 再接受，从而支持 ICE restart / 重新协商。

## 4.1 设备 ↔ App 通话控制（v0.6.0 适老化相机）

在媒体协商前增加一层呼叫控制：

```
App ──invite(call_id)──▶ 设备
设备 ──agree / reject──▶ App
agree 后：App joinRoom → 设备 offer → App answer → 媒体建立
任一方挂断：hangup → 对端关闭 PeerConnection
```

- 设备呼叫 App：设备发布 `invite`，`to="app"` / `to="user:<id>"` / 具体 client_id。
  Hub 只投给 `role=app` 的连接；**没有在线 App 时调用离线推送**。
- App 呼叫设备：`POST /app/av/devices/:id/call-ticket` 拿 role=app 的 ticket，
  连 `/app/av/ws`，发 `invite`；设备回 `agree` 后按上面的媒体流程。
- Web 预览连接（role=viewer）也能发 invite/agree/reject，用于联调；
  真实的来电只投给 App，不打扰 Web 预览。
- App 必须已认领/绑定设备：`ac_iot_device_account.platform_user_id = 当前用户`。

### 4.2 离线推送

- App 启动后调用 `POST /app/push-tokens` 上报个推 CID；
  退出登录调用 `DELETE /app/push-tokens/:cid`。
- 设备 invite 时房间内无 App 连接 → 后端查设备绑定用户 → 个推单推
  （`ac_thirdparty_config(Category='getui')`）。
- 推送 payload：`{type:"av_invite", room_id, device_code, call_id, media_type}`；
  App 点击通知打开 `/iot/call?deviceId=...`。
- 未配置个推或用户未上报 CID 时只记录日志，不阻塞设备呼叫。

## 5. 后端接口

| 方法 | 路径 | 鉴权 | 说明 |
|:--|:--|:--|:--|
| GET | `/web/av/devices` | JWT + Casbin `av:preview:view` | 仅返回产品绑定启用 WebRTC 服务组的设备 |
| POST | `/web/av/devices/:id/viewer-ticket` | JWT + Casbin `av:preview:connect` | 校验行级数据权限、设备/产品/服务组/MQTT 服务；签发 ticket 与 TURN 凭据 |
| GET | `/web/av/ws?ticket=...` | 一次性 ticket | 房间信令 WebSocket（role=viewer） |
| POST | `/app/av/devices/:id/call-ticket` | App JWT + 设备绑定 | role=app 的 60s ticket |
| GET | `/app/av/ws?ticket=...` | 一次性 ticket | App 通话/查看 WebSocket |
| POST | `/app/push-tokens` | App JWT | 注册个推 CID |
| DELETE | `/app/push-tokens/:cid` | App JWT | 注销个推 CID |

`viewer-ticket` 响应：

```json
{
  "ticket": "...",
  "expires_in": 60,
  "ws_url": "ws://127.0.0.1:8080/web/av/ws",
  "room_id": "CAM_001",
  "device_id": 1,
  "device_code": "CAM_001",
  "device_name": "东门摄像头",
  "client_id": "viewer-1a2b3c4d",
  "group_code": "webrtc",
  "device_online": true,
  "ice_servers": [
    {
      "urls": ["stun:...", "turn:...?transport=udp"],
      "username": "1792922772:web-1",
      "credential": "...",
      "realm": "ai-camera",
      "ttl": 3600,
      "expires_at": 1792922772
    }
  ]
}
```

TURN 凭据使用 TURN REST API（`web-<user_id>` subject），与 App 的
`/app/rtc/ice-servers` 同源。

## 6. 权限与安全

- 页面菜单权限：`av:preview:view`；
- 连接按钮：`av:preview:connect`；
- 设备详情查询使用 `DataScope`（`ac_device.dept_id`），知道 ID 也不能越权；
- 设备必须启用、产品启用、产品绑定启用的 `webrtc` 服务组、组内 MQTT 服务启用；
- MQTT 平台账号 ACL 只允许：
  - subscribe `iot/+/signal/backend`
  - publish `iot/+/app/+/signal`（旧 WHEP）
  - publish `iot/+/device/+/signal`（房间信令）
- ticket 一次性、60 秒有效；WebSocket 不在 URL 里携带 JWT。

## 7. 设备模拟器（联调用）

`backend/tools/webrtcsim` 用 Pion 生成真实 H.264 画面，验证整条链路：

```bash
cd backend
MQTT_DEVICE_USERNAME=svc_xxx MQTT_DEVICE_PASSWORD='***' \
go run ./tools/webrtcsim \
  --broker tcp://127.0.0.1:1883 \
  --group-code webrtc --device-code CAM_001 \
  --stream-file tools/gbsim/testdata/sample.h264 --fps 25 \
  --report-interval 10s \
  --invite-after 20s --invite-to app
```

- `--report-interval`：上报电量/位置，每 6 个周期补一条跌倒告警；
- `--invite-after`：启动后向 App 发起呼叫，用于验证 invite/agree 与离线推送。

凭据来自 `ac_iot_product_service`（产品 × MQTT 服务），不是平台账号。

## 8. 前端页面

- 设备下拉（自动选中第一台）、连接/断开、重新协商；
- 视频区域 + 分辨率/帧率/码率/ICE/Connection 指标；
- 房间、查看方 ID、设备在线状态；
- 信令日志（收发方向、错误高亮），便于现场排障；
- 断线、`leaveRoom`、设备重发 offer 均有状态提示。

## 9. 已验证

- Node WS 客户端：ready → joinRoom → 设备 joinRoom → 二次 joinRoom → offer → candidate，
  offer SDP 5022 bytes；
- Playwright（Edge）：页面真实视频首帧 `videoWidth > 0`，
  `ice=connected / connection=connected`；
- 模拟器日志显示 `connection=connected`，离开后收到 `leaveRoom` 并释放 PeerConnection。
- 通话控制：Node WS 以 role=viewer / role=app 发 `invite`，设备模拟器回 `agree`；
  设备发 `invite` 时 App WS 收到，未连接 App 时后端日志出现
  「离线来电推送失败 ... 个推未配置」（回调已触发，等待配置个推）。

## 10. 已知限制

- 浏览器需支持 H.264；Playwright 自带 Chromium 通常不含专有编解码器，
  视频帧用例建议 `E2E_BROWSER_CHANNEL=msedge`。
- 设备端真实固件需按本文档实现话题与消息；`webrtcsim` 仅用于联调。
- 跨公网必须正确配置 `TURN_EXTERNAL_IP` 与 `TURN_URLS`；
  本机回环验证可只用 host candidate。
- 当前每个设备最多 8 路同时查看（`DefaultMaxViewersPerRoom`）。
