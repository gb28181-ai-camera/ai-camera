## 2. 用户管理

### 2.1 页面功能

- **搜索条件**：部门（`dept_id`）、用户名/姓名关键字（`keyword`）、状态（`active`）。搜索条件可组合，点击「查询」刷新列表，点击「重置」清空。
- **列表字段**：用户编号、用户名、姓名、部门、岗位、手机号、邮箱、状态、创建时间。
- **新增用户**：带红色 `*` 的均为必填项。部门数据来自部门管理（`GET /web/system/depts/options`）、岗位数据来自岗位管理（`GET /web/system/posts/options`）、拥有角色数据来自角色管理（`GET /web/system/roles/options`）。
- **编辑用户**：修改后点「确定」提示保存成功即生效；点「取消」不保存。登录名唯一，重复提交返回 400。
- **删除用户**：支持选择一条或多条进行批量删除，点「删除」后需二次确认；确认后删除（软删除 `deleted_at`），取消则不删除。
- **禁用/启用账号**：账号默认为启用状态。禁用后该账号无法登录管理平台（登录接口返回 403）。
- **重置密码**：输入新密码后完成重置，用户下次登录需使用新密码。
- **分页**：默认每页 20 条，支持切换页码与每页条数。
- **数据权限**：列表按当前用户的 `data_perm` 施加行级过滤。

> **注意**：禁用账号与重置密码是独立端点（`PUT /users/:id/disable`、`PUT /users/:id/reset-password`），
> 不要用编辑接口提交 `active` 字段来替代启停操作。

## 3. 菜单管理

### 3.1 页面功能

- **树形展示**：按 `parent_id` 展开三级结构——目录（`directory`）/ 菜单（`menu`）/ 按钮（`button`）。列表展示菜单名称、路由唯一键（`path`）、组件（`component`）、排序（`sequence`）、类型、链接、权限标识（`permission_code`）、状态。
- **搜索条件**：菜单名称（`keyword`）、状态（`active`）。
- **新增菜单**：带红色 `*` 的均为必填项（名称、类型、排序）。按钮型菜单必须填写 `permission_code`，该值即前端按钮显隐的权限标识。
- **编辑菜单**：修改后点「确定」提示保存成功即生效；点「取消」不保存。
- **删除菜单**：点「删除」后二次确认，确认即删除；取消则不删除。存在子菜单时不允许删除。
- **菜单 API 绑定**：为菜单绑定后端接口（HTTP 方法 + 路径），这是 Casbin `p` 策略的**唯一来源**。角色授权时按「角色 → 菜单 → 菜单 API」三级推导出可访问的接口集合。
- **平台区分**：`platform` 取值 `pc` / `mobile`，决定该菜单出现在管理后台还是移动端。

> **注意**：新增或修改 API 绑定后，需重新为角色授权（或触发角色策略同步）才会写入 `casbin_rule`。

### 3.2 接口列表

| POST | `/web/system/menus` | 新增菜单 |
| PUT | `/web/system/menus/:id` | 编辑菜单 |
| DELETE | `/web/system/menus/:id` | 删除菜单 |
| GET | `/web/system/menus/:id/apis` | 菜单已绑定的接口列表 |
| POST | `/web/system/menus/:id/apis` | 新增菜单接口绑定 |
| DELETE | `/web/system/menus/apis/:apiId` | 删除菜单接口绑定 |

## 4. 角色管理

### 4.1 页面功能

- **搜索条件**：角色名称/权限字符关键字（`keyword`）、状态（`active`）。
- **列表字段**：角色编号、角色名称、权限字符（`code`）、显示顺序、状态、创建时间。权限字符是 Casbin 的 `sub` 值，唯一且稳定。
- **新增角色**：带红色 `*` 的均为必填项。「拥有权限」勾选的菜单决定该角色用户登录后能看到的菜单与按钮；未勾选的一律不可见且接口不可访问。
- **编辑角色**：修改后点「确定」提示保存成功即生效；点「取消」不保存。
- **数据权限设置**：点击「数据权限」为该角色配置可见数据范围——`all` / `cross_dept` / `dept` / `personal`；选择 `cross_dept` 时需指定跨部门 ID 列表。
- **授权维度**：菜单、部门、岗位、用户四个维度分别提供独立的查询与保存接口，保存为整体覆盖式提交。
- **删除角色**：点「删除」后二次确认，确认即删除；取消则不删除。
- **策略同步**：角色授权变更后，后端重建该角色的 `p` / `g` / `g2` / `g3` 策略并 `ReloadPolicy()`。

> **注意**：`g` 为「用户 → 角色」，`g2` 为「部门 → 角色」，`g3` 为「岗位 → 角色」，
> 三种继承关系并存，用户的实际权限是三者并集。

### 4.2 接口列表

| GET | `/web/system/roles/:id` | 角色详情 |
| POST | `/web/system/roles` | 新增角色 |
| PUT | `/web/system/roles/:id` | 编辑角色 |
| DELETE | `/web/system/roles/:id` | 删除角色 |
| GET | `/web/system/roles/:id/menus` | 查询角色已授权菜单 ID |
| PUT | `/web/system/roles/:id/menus` | 保存角色菜单授权 |
| GET | `/web/system/roles/:id/depts` | 查询角色已授权部门 ID |
| PUT | `/web/system/roles/:id/depts` | 保存角色部门授权 |
| GET | `/web/system/roles/:id/posts` | 查询角色已授权岗位 ID |
| PUT | `/web/system/roles/:id/posts` | 保存角色岗位授权 |
| GET | `/web/system/roles/:id/users` | 查询角色下的用户 ID |

## 5. 部门管理

### 5.1 页面功能

- **树形展示**：按 `parent_id` 组树，列表展示部门名称、排序、状态、创建时间。
- **搜索条件**：部门名称（`keyword`）、状态（`active`）。
- **新增部门**：带红色 `*` 的均为必填项；可选上级部门（`parent_id`）与负责人（`leader_id`）。部门编码 `code` 是 Casbin 的 `g2` 主体。

## 6. 岗位管理

### 6.1 页面功能

- **搜索条件**：岗位编码 / 岗位名称关键字（`keyword`）、状态（`active`）。
- **列表字段**：岗位编号、岗位编码、岗位名称、岗位排序、状态、创建时间。岗位编码 `code` 是 Casbin 的 `g3` 主体。
- **新增岗位**：带红色 `*` 的均为必填项。
- **编辑岗位**：修改后点「确定」提示保存成功即生效；点「取消」不保存。
- **删除岗位**：支持选择一条或多条进行批量删除，点「删除」后二次确认。
- **与用户管理联动**：岗位数据是「用户管理 → 岗位」下拉的数据源。

### 6.2 接口列表

## 7. 操作日志

### 7.1 页面功能

- **搜索条件**：系统模块（`module`）、操作人员（`operator`）、操作类型（`action`）、操作时间范围（`start_dt` ~ `end_dt`）。
- **列表字段**：日志编号、系统模块、操作类型、请求方式、操作人员、主机（`ip`）、操作地点、状态、操作时间、耗时。
- **查看详情**：点击「详细」查看日志完整信息，包含请求参数（`params`）与错误信息（`error_msg`）。
- **删除日志**：支持选择一条或多条进行批量删除，点「删除」后二次确认。
- **清空日志**：点「清空」并确认后，全部日志记录被清除，不可恢复。
- **导出日志**：点「导出」将当前筛选条件下的日志导出为 `.xlsx` 文件。

> **注意**：导出接口按当前查询条件返回**全量**（不受分页限制），由前端生成 xlsx。
> 清除操作影响全部日志，与当前筛选条件无关。

### 7.2 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/web/system/logs` | 操作日志分页列表 |
| GET | `/web/system/logs/:id` | 操作日志详情 |
| DELETE | `/web/system/logs/:id` | 删除单条日志 |
| DELETE | `/web/system/logs/clear` | 清空全部日志 |
| GET | `/web/system/logs/export` | 按条件导出日志 |

## 8. 系统通知

### 8.1 页面功能

- **消息汇聚**：统一展示设备告警（`category = alarm`）、风险通知（`risk`）、巡检通知（`inspect`）三类消息。
- **搜索条件**：消息类型（`category`）、是否已读（`read`）、关键字（`keyword`）。
- **未读红点**：侧边栏通知图标上有未读红点，数量来自 `GET /web/system/notifications/unread-count`；全部已读后红点隐藏。
- **查看消息**：点击消息标记该条为已读（`PUT /notifications/:id/read`），并跳转到对应业务模块（风险监控 / 设备告警 / 巡检任务）。
- **全部已读**：点「全部已读」将当前用户所有消息置为已读。
- **删除消息**：删除单条消息。
- **通知频率**：设备告警、风险通知的推送频率在「设备告警设置」「风险通知设置」中配置；巡检消息在指派的巡检人员账号中显示。

> **注意**：通知按 `user_id` 隔离，用户只能看到与操作自己的消息。

### 8.2 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/web/system/notifications` | 通知分页列表 |
| GET | `/web/system/notifications/unread-count` | 未读消息数 |
| PUT | `/web/system/notifications/:id/read` | 标记单条已读 |
| PUT | `/web/system/notifications/read-all` | 全部标记已读 |
| DELETE | `/web/system/notifications/:id` | 删除通知 |

## 9. 系统参数

### 9.1 页面功能

- **列表展示**：参数名称、参数键（`key`）、参数值、分组、数据类型、排序、状态、说明。支持按关键字（`keyword`）过滤。
