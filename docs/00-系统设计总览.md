# AI Camera 智能监控平台设计总览

> 版本: v0.1.0
> 最后更新: 2026-09-21

## 1. 系统概述

本系统为**AI 智能监控平台（AI Camera Platform）**，以 AI 摄像头为前端采集终端，通过边缘侧 AI 推理识别风险事件，将风险图片/录像与设备运行状态回传至云端平台，实现**实时视频监控、AI 风险识别与闭环处置、设备告警、巡检协同、统计分析（含可视化大屏）、设备与固件/模型远程升级、物联网卡管理**的一体化管控。

系统由三个前端共用一套 Go 后端：

- **管理后台**（React 19 + Ant Design 5）：面向平台管理员与区域负责人，完成全部配置与处置工作
- **官网介绍页**（React 19 + 纯 CSS）：对外品牌展示，与后台同属一个 npm 工程的双入口
- **移动端 App**（Flutter）：面向巡检人与现场人员，完成风险处置与巡检任务处理

## 2. 设计原则

| 原则 | 说明 |
|------|------|
| **模块化** | 功能按业务域拆分，模块间通过外键关联 |
| **状态机驱动** | 风险、告警、巡检任务、升级计划都有明确的`status`状态流转 |
| **可追溯** | 所有数据表保留`created_by`、`created_dt`、`updated_by`、`updated_dt`审计字段 |
| **软删除** | 使用`deleted_at`标记删除，不物理删除 |
| **区域维** | 区域是设备、风险、告警、巡检的公共归属维度，全部列表支持按区域筛选 |
| **快照冗余** | 风险与巡检记录保留设备/区域/任务名称快照，避免源数据变更影响历史记录 |
| **四级鉴权** | JWT 身份 → Auth 中间件 → Casbin 接口级 RBAC → 数据权限行级过滤 |

> **注意**：本项目在 Casbin 匹配器中显式加入 `keyMatch2(r.obj, p.obj) && r.act == p.act`，
> 相比仅做角色成员校验的方案，实现了真正的**接口 + 方法级**鉴权（详见第 7 节）。

## 6. 鉴权体系

### 6.1 四级权限叠加

| 层级 | 机制 | 实现位置 | 作用 |
|:----:|------|---------|------|
| 1 | JWT (HS256) | `pkg/auth/jwt.go` | 身份标识 + 携带数据权限三要素 |
| 2 | Auth 中间件 | `internal/api/middleware/auth.go` | 校验 Bearer Token，写入 gin.Context 与 Go Context |
| 3 | Casbin RBAC | `pkg/perm/casbin.go` + `config/rbac_model.conf` | 接口 + 方法级鉴权，三种角色继承链 |
| 4 | 数据权限 | `pkg/utils/data_scope.go` | 行级过滤（全部/跨部门/本部门/仅本人） |

### 6.2 Casbin 三链角色继承

```
        ┌─────────────┐
用户 ───▶│  g  (直接)  │───┐
        └─────────────┘   │
        ┌─────────────┐   │      ┌──────────┐        ┌──────────────────┐
部门 ───▶│  g2 (部门)  │───┼─────▶│ p: 角色  │───────▶│ obj: 接口路径     │
        └─────────────┘   │      │  → 接口  │        │ act: HTTP 方法    │
        ┌─────────────┐   │      └──────────┘        └──────────────────┘
岗位 ───▶│  g3 (岗位)  │───┘
        └─────────────┘
```

匹配器：

```ini
m = keyMatch2(r.obj, p.obj) && r.act == p.act && (g(r.sub, p.sub) || g2(r.sub, p.sub) || g3(r.sub, p.sub))
```

> **注意**：`keyMatch2` 支持 `/web/system/users/:id` 形式的路由参数匹配；
> `r.act == p.act` 保证方法级隔离。二者缺一都会退化为「只校验角色成员」的弱鉴权。

### 6.3 数据权限四级

| 级别 | 编码 | SQL 过滤条件 | 说明 |
|------|------|-------------|------|
| 全部 | `all` | 无附加条件 | 超级管理员 / 平台运营 |
| 跨部门 | `cross_dept` | `dept_id IN (本部门 + 跨部门列表)` | 区域总负责人 |
| 本部门 | `dept` | `dept_id = 当前部门` | 部门管理员 |
| 仅本人 | `personal` | `dept_id = 当前部门 AND created_by = 当前用户` | 普通员工 |

有效级别由用户的三路角色（直接/岗位/部门）按优先级 `personal < dept < cross_dept < all` 取最高者。
