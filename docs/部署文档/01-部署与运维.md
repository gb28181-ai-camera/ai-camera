## 1. 部署架构

AI Camera 平台采用「单后端服务 + 三前端入口」的部署形态：后端 `ai-camera-backend` 一个
Deployment 承载 `/web/*`（管理后台 + 官网）与 `/app/*`（移动端）两套路由；前端拆分为
管理后台静态站、官网静态站两个 Nginx 容器；移动端 App 与桌面端 Desktop 不进集群，走
文件分发（应用市场 / 安装包下载）。

### 1.1 端口与访问面

| 组件 | 集群内端口 | 对外入口 | 说明 |
|:---|:----:|:---|:---|
| `ai-camera-backend` | 8080 | `https://api.ai-camera.com` | 生产环境端口；开发 8080 / 测试 8081 |
| `ai-camera-admin` | 8080 | `https://admin.ai-camera.com` | 管理后台静态站（Vite `dist/`，base `/admin/`） |
| `ai-camera-website` | 8080 | `https://www.ai-camera.com` | 官网介绍页静态站（Vite `dist-website/`，base `/`） |
| PostgreSQL | 5432 | 集群内 | 业务库 |
| Redis | 6379 | 集群内 | 预留：验证码、令牌黑名单、WebSocket 会话 |

> **注意**：`ai-camera-admin` 与 `ai-camera-website` 是同一份前端工程的两个构建产物，
> 通过 `npm run build:admin` 与 `npm run build:website` 分别产出，**不可混用** —— 管理后台
> 资源路径以 `/admin/` 为根，官网以 `/` 为根，混用会导致静态资源 404。

## 3. Docker镜像构建

后端与两个前端各有独立 Dockerfile。后端 Dockerfile 位于 `backend/Dockerfile`
（`--prod` 时用 `backend/Dockerfile.prod`），两个前端 Dockerfile 位于 `frontend/` 下。

### 3.1 后端Dockerfile

```dockerfile
# backend/Dockerfile
# 多阶段构建：builder 编译静态二进制 → runtime 仅保留二进制与配置模板
FROM golang:1.26-alpine AS builder

WORKDIR /build

# 先复制依赖描述文件，利用层缓存加速重复构建
COPY go.mod go.sum ./
RUN go env -w GOPROXY=https://goproxy.cn,direct && go mod download

# 复制源码并编译（CGO_ENABLED=0 保证静态链接，可在 alpine 直接运行）
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags "-s -w" \
      -o /build/server ./cmd/server/main.go

# ── 运行阶段 ──
FROM alpine:3.20

RUN apk add --no-cache ca-certificates tzdata curl && \
    cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    echo "Asia/Shanghai" > /etc/timezone

WORKDIR /app

# 二进制、Casbin 模型、Swagger 文档（Swagger 关闭时可不复制）
COPY --from=builder /build/server            /app/server
COPY --from=builder /build/config/rbac_model.conf /app/config/rbac_model.conf
COPY --from=builder /build/docs/web          /app/docs/web

# 上传目录与日志目录（生产建议挂载 PVC）
RUN mkdir -p /app/uploads /app/logs

EXPOSE 8080

# 健康检查：/health 为内联端点，不经过鉴权
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD curl -fsS http://127.0.0.1:8080/health || exit 1

CMD ["/app/server"]
```

```dockerfile
# backend/Dockerfile.prod
# 生产镜像：与 Dockerfile 一致，差异为镜像更精简 + 关闭 Swagger 由 ConfigMap 控制
FROM golang:1.26-alpine AS builder

WORKDIR /build
COPY go.mod go.sum ./
RUN go env -w GOPROXY=https://goproxy.cn,direct && go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags "-s -w" \
      -o /build/server ./cmd/server/main.go

FROM alpine:3.20
RUN apk add --no-cache ca-certificates tzdata curl
WORKDIR /app
COPY --from=builder /build/server                 /app/server
COPY --from=builder /build/config/rbac_model.conf /app/config/rbac_model.conf
RUN mkdir -p /app/uploads /app/logs
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD curl -fsS http://127.0.0.1:8080/health || exit 1
CMD ["/app/server"]
```

构建与推送：

```bash
# 开发镜像（推送 dev-registry.boticz.com:5000）
cd backend && bash scripts/build.sh

# 生产镜像（推送 registry.boticz.cn:5000）
cd backend && bash scripts/build.sh --prod
```

### 3.2 前端管理后台 Dockerfile

前端镜像采用**单镜像双站点**：一个 nginx 容器同时托管管理后台（`/admin/`）与官网（`/`）。
这与 K8s 清单中的两个独立 Deployment 并不冲突 —— 生产环境用同一镜像起两个 Deployment，
分别以 `Traefik` 路由到不同 Host；也可以只部署一个容器走路径区分。

```dockerfile
# frontend/Dockerfile
# ============================================================================
# AI Camera 前端镜像
# 一个 npm 工程、两个 Web 构建目标：
#   - 管理后台   index.html    → dist/          （base /admin/）
#   - 官网介绍页 website.html  → dist-website/  （base /）
# 镜像内由 nginx 同时托管两者：/admin/ → 管理后台，/ → 官网。
# ============================================================================

FROM node:22-alpine AS builder

WORKDIR /app

# 国内镜像加速
RUN sed -i 's/dl-cdn.alpinelinux.org/mirrors.aliyun.com/g' /etc/apk/repositories
RUN npm config set registry https://registry.npmmirror.com
ENV ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/

# 依赖层单独缓存
COPY package.json ./
RUN npm install

COPY . .

# build:admin 含 tsc --noEmit；build:website 仅 vite build
RUN npm run build

# ============================================================
# 生产镜像：nginx:alpine 托管静态文件
# ============================================================
FROM nginx:alpine

RUN sed -i 's/dl-cdn.alpinelinux.org/mirrors.aliyun.com/g' /etc/apk/repositories

# 官网产物放到站点根，管理后台产物放到 /admin 子目录
COPY --from=builder /app/dist-website /usr/share/nginx/html
COPY --from=builder /app/dist /usr/share/nginx/html/admin

COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 8080

CMD ["nginx", "-g", "daemon off;"]
```

```nginx
# frontend/nginx.conf
server {
    listen 8080;
    server_name localhost;

    root /usr/share/nginx/html;
    index index.html;

    # Gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml image/svg+xml;
    gzip_min_length 256;

    # 管理后台（base /admin/，产物位于 /usr/share/nginx/html/admin）
    # 注意：alias 路径片段会被替换为 location 前缀，故末尾均需带 `/`
    location /admin/ {
        alias /usr/share/nginx/html/admin/;
        # SPA 路由回退；回退 URI 重新匹配本 location，alias 解析为 .../admin/index.html
        try_files $uri $uri/ /admin/index.html;
    }

    # 管理后台带 hash 的静态资源强缓存
    location /admin/assets/ {
        alias /usr/share/nginx/html/admin/assets/;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 官网介绍页（base /，产物位于站点根）
    location / {
        try_files $uri $uri/ /index.html;
    }

    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 后端接口反向代理（如由本容器统一入口时启用，按需调整 upstream）
    # location /web/ { proxy_pass http://backend:8080; proxy_set_header Host $host; }
    # location /app/ { proxy_pass http://backend:8080; proxy_set_header Host $host; }
}
```

> **注意**：`alias` 指令的路径片段会被替换为 `location` 前缀，因此 `location /admin/` 与
> `alias` 的**末尾都必须带 `/`**。`try_files` 的兜底 URI 写 `/admin/index.html`（绝对路径）
> 而非 `index.html`，否则会解析到站点根目录的官网 `index.html`。

构建与运行：

```bash
# 单镜像双站点
cd frontend && docker build -t ai-camera-frontend .
cd frontend && docker run -p 8080:8080 ai-camera-frontend

# 验证：/ 返回官网，/admin/ 返回管理后台
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/admin/
```

### 3.3 前端官网 Dockerfile

官网也可独立打成**只含官网**的镜像（体积更小，适合官网单独部署到 CDN 边缘或独立域名）：

```dockerfile
# frontend/Dockerfile.website
# 仅构建官网入口 website.html（base /），产物 dist-website/
FROM node:22-alpine AS builder

WORKDIR /app
RUN sed -i 's/dl-cdn.alpinelinux.org/mirrors.aliyun.com/g' /etc/apk/repositories
RUN npm config set registry https://registry.npmmirror.com

COPY package.json ./
RUN npm install
COPY . .
RUN npm run build:website

FROM nginx:alpine
RUN sed -i 's/dl-cdn.alpinelinux.org/mirrors.aliyun.com/g' /etc/apk/repositories

COPY --from=builder /app/dist-website /usr/share/nginx/html
COPY nginx.website.conf /etc/nginx/conf.d/default.conf

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

```bash
cd frontend && docker build -f Dockerfile.website -t ai-camera-website .
cd frontend && docker run -p 8081:80 ai-camera-website
```

> **注意**：官网容器**不代理后端** —— 官网为纯静态展示页，不调用任何 API。
> 官网内的「登录」入口为跳转到管理后台域的绝对链接（`/admin/`）。

### 3.4 前端Desktop (Electron) 构建

桌面端与管理后台共用同一份 `frontend/` 工程，通过 Electron Forge + Vite 插件打包，
配置见 `frontend/forge.config.ts` 与 `frontend/vite.renderer.config.ts`。

```bash
# 桌面端开发模式（Electron 主进程 + 渲染进程热更新）
cd frontend && npm run dev:desktop

# 仅打包不生成安装包（产物在 out/，用于本地验证）
cd frontend && npm run package:desktop

# 生成 NSIS 安装包（Windows）
cd frontend && npm run make:win

# 生成 DMG（macOS）/ DEB+RPM（Linux）
cd frontend && npm run make:mac
cd frontend && npm run make:linux
```

```bash
# frontend/scripts/build-desktop.sh（三平台打包 + 一致性校验的推荐入口）
# 关键约束：
#   1. package.json 的 version 必须与发布版本一致，否则安装后反复提示「发现新版本」
#   2. 打包前先执行 npm run typecheck，避免类型错误进产物
#   3. 产物路径 out/make/**/*.exe|.dmg|.deb，交付到对象存储后由下载页读取发布清单
```

> **注意**：`package.json` 中 `build.nsis.packElevateHelper` 必须保持 `false`，
> 否则 NSIS 打包会因缺少 `elevate.exe` 而失败。

## 4. Kubernetes部署清单

### 4.1 后端Deployment

```yaml
# k8s-apply-gitops/ai-camera-prod/deployments/ai-camera-backend.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ai-camera-backend
  namespace: ai-camera-prod
  labels:
    app: ai-camera-backend
spec:
  replicas: 2
  selector:
    matchLabels:
      app: ai-camera-backend
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0          # 先起新 Pod 再停旧 Pod，保证零中断
  template:
    metadata:
      labels:
        app: ai-camera-backend
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/port: "8080"
        prometheus.io/path: "/metrics"
    spec:
      initContainers:
        # 等待数据库就绪：AutoMigrate 在启动时执行，库不可用会导致启动失败
        - name: wait-for-db
          image: postgres:16-alpine
          command:
            - sh
            - -c
            - |
              until pg_isready -h postgresql-service.postgresql.svc.cluster.local -p 5432; do
                echo "等待 PostgreSQL 就绪..."; sleep 2
              done
      containers:
        - name: backend
          image: registry.boticz.cn:5000/boticz/ai-camera-api:latest
          imagePullPolicy: Always
          ports:
            - name: http
              containerPort: 8080
          env:
            # 切换配置文件的唯一开关：dev=config/config.yaml  test=config/config-test.yaml
            - name: CONFIG_PATH
              value: /app/config/config.yaml
            - name: TZ
              value: Asia/Shanghai
          volumeMounts:
            - name: config
              mountPath: /app/config
              readOnly: true
            - name: uploads
              mountPath: /app/uploads          # 风险图片 / 录像 / 音频 / 固件 / 模型
            - name: logs
              mountPath: /app/logs
          resources:
            requests:
              cpu: 200m
              memory: 256Mi
            limits:
              cpu: "1"
              memory: 1Gi
          readinessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 10
            periodSeconds: 10
            failureThreshold: 3
          livenessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 30
            periodSeconds: 20
            failureThreshold: 3
      volumes:
        - name: config
          configMap:
            name: ai-camera-cm           # 完整 config.yaml（含数据库口令）
        - name: uploads
          persistentVolumeClaim:
            claimName: ai-camera-uploads-pvc   # ReadWriteMany
        - name: logs
          emptyDir: {}
---
# k8s-apply-gitops/ai-camera-prod/services/ai-camera-backend-svc.yaml
apiVersion: v1
kind: Service
metadata:
  name: ai-camera-backend
  namespace: ai-camera-prod
spec:
  selector:
    app: ai-camera-backend
  ports:
    - name: http
      port: 8080
      targetPort: 8080
  type: ClusterIP
```

### 4.2 自动扩缩（HPA）

```yaml
# k8s-apply-gitops/ai-camera-prod/hpa/ai-camera-backend-hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: ai-camera-backend-hpa
  namespace: ai-camera-prod
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: ai-camera-backend
  minReplicas: 2
  maxReplicas: 8
  metrics:
    # 1. CPU：通用负载信号
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    # 2. 内存：风险图片上传与统计聚合会拉高内存占用
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 80
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 60
      policies:
        - type: Percent
          value: 100
          periodSeconds: 60       # 每分钟最多翻倍
        - type: Pods
          value: 2
          periodSeconds: 60
      selectPolicy: Max
    scaleDown:
      stabilizationWindowSeconds: 300   # 冷却 5 分钟，避免设备上报潮汐导致抖动
      policies:
        - type: Pods
          value: 1
          periodSeconds: 120
```

> **注意**：设备心跳按 `info_interval`（默认 60 秒，`ac_device.info_interval`）周期到达，
> 500 台设备约 8 QPS 的稳态流量。真正的扩容触发点不是心跳，而是**风险上报后的列表刷新**
> 与**首页看板/可视化大屏的聚合查询** —— 因此 HPA 的 CPU 阈值不宜过高。

## 7. 备份策略

| 对象 | 方式 | 频率 | 保留 | 存放位置 |
|:---|:---|:---|:---|:---|
| PostgreSQL 全量 | `pg_dump -Fc` | 每日 02:00 | 30 天 | 对象存储 `backup/pg/daily/` |
| PostgreSQL 归档 | WAL 归档（`archive_mode=on`） | 持续 | 7 天 | 对象存储 `backup/pg/wal/` |
| K8s 资源清单 | `kubectl get all -o yaml` | 每次发布前 | 90 天 | GitOps 仓库 |
| `uploads/` 目录 | `rsync` 增量同步 | 每日 03:00 | 30 天 | 对象存储 `backup/uploads/` |
| ConfigMap / Secret | 加密后入 GitOps | 变更即提交 | 永久 | GitOps 仓库 |
| 固件 / AI 模型文件 | 上传时同步一份原始件 | 上传即同步 | 永久 | 对象存储 `release/firmware/` |

```bash
# 数据库备份（生产库，容器内执行）
kubectl -n ai-camera-prod exec -it statefulset/postgresql -- \
  pg_dump -U boticz -d ai_camera_prod -Fc -f /tmp/ai_camera_prod_$(date +%F).dump

kubectl -n ai-camera-prod cp \
  postgresql-0:/tmp/ai_camera_prod_$(date +%F).dump \
  /backup/pg/daily/ai_camera_prod_$(date +%F).dump

# uploads 目录增量备份（PVC 已挂载到 NFS 时可直接 rsync）
rsync -av --delete /mnt/ai-camera-uploads/ /backup/uploads/$(date +%F)/

# 恢复演练（在独立库中还原，禁止直接覆盖生产库）
createdb -h 192.168.1.227 -U boticz ai_camera_restore_drill
pg_restore -h 192.168.1.227 -U boticz -d ai_camera_restore_drill -c /backup/pg/daily/ai_camera_prod_2026-09-20.dump
```

> **注意**：`uploads/` 目录当前落在 PVC 上，备份粒度是文件级；迁移到对象存储后（见
> [02-监控与容灾.md](02-监控与容灾.md) 第 5.5 节），备份策略应改为**跨桶复制 + 版本控制**，
> 不再依赖 rsync 快照。

```bash
kubectl -n ai-camera-prod describe pod -l app=ai-camera-backend                   # 排查 Pod 异常
kubectl -n ai-camera-prod exec -it deploy/ai-camera-backend -- sh                 # 进入容器
kubectl -n ai-camera-prod exec -it deploy/ai-camera-backend -- wget -qO- localhost:8080/health  # 容器内健康检查
kubectl -n ai-camera-prod rollout restart deploy/ai-camera-backend                # 滚动重启
kubectl -n ai-camera-prod rollout status  deploy/ai-camera-backend --timeout=300s # 等待发布完成
kubectl -n ai-camera-prod rollout undo    deploy/ai-camera-backend                # 回滚到上一版本
kubectl -n ai-camera-prod set image deploy/ai-camera-backend backend=registry.boticz.cn:5000/boticz/ai-camera-api:v0.1.0  # 指定镜像版本
kubectl -n ai-camera-prod get configmap ai-camera-cm -o yaml                      # 查看运行配置
kubectl -n ai-camera-prod exec -it deploy/ai-camera-backend -- ls -lh /app/uploads # 查看上传目录占用

# ── 数据库运维 ──
psql -h 192.168.1.227 -U boticz -d ai_camera_dev -c "\dt"                         # 列出开发库全部表
psql -h 192.168.1.227 -U boticz -d ai_camera_dev -c "SELECT count(*) FROM ac_device;"  # 统计设备数
psql -h 192.168.1.227 -U boticz -d ai_camera_dev -c "SELECT count(*) FROM ac_risk_record WHERE status='pending';"  # 统计未处理风险
kubectl -n ai-camera-prod exec -it statefulset/postgresql -- pg_isready -U boticz  # 检查数据库就绪
```

> **注意**：执行 `psql` 等数据库命令时必须显式指定 `-d` 目标库。开发库 `ai_camera_dev`
> 与测试库 `ai_camera_test` 结构相同但数据独立，**禁止**在未确认库名的情况下执行写操作。
